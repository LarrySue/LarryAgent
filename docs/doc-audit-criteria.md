# 文档审计判据正本（悬空项盘点 · 假完成审计）

> **地位**：判据与方法论的**单一正本**。**条目不在本文件** —— 找到的悬空项进 `TODO.md`〈🧹 悬空项盘点（常驻活区）〉；本文件只管「怎么盘、怎么判」。
> **归属**：A 半（悬空盘点）由 WB 出候选、Qoder 复核 docs 面；B 半（假完成审计）由 ZCode 独立判。分工见 §五。
> **来源**：WB 2026-10-31 起草于 `exchange/log-workbuddy.md`〈🧹 待办 · 悬空项盘点〉；2026-11-02 老大定「判据正本不搬进 TODO」，由 Qoder 迁入本区（判据原文，语义未改）。

## 〇、盘点分两半（⛔ 只做 A 半等于没盘）

| 半 | 问的是 | 判据 | 谁判 |
|---|---|---|---|
| **A · 悬空** | 该做的，**做了吗** | 三空（见一） | WB 出候选；Qoder 复核 |
| **B · 假完成** | 说做了的，**真做到位了吗** | 七形态（见七） | **ZCode 独立判** —— WB ⛔ 不单独判 |

两张表**合起来才是全貌**：A 半找「漏的」，B 半找「假的」。只做 A 半会得出「该做的都有人做」——而这正是假完成最容易藏进去的地方。

## 一、A 半：什么算悬空（三空即悬空）

一条**已经说死**的要求／承诺／结论，同时满足：

- **Q1 没做** —— 实现侧或文档侧没有落地（无代码、无对应段落）；
- **Q2 没挂** —— **三处正本**均无条目承接（范围见下）；
- **Q3 没人在飞** —— `exchange/log-*.md` 状态区无派发、无在飞任务。

⇒ 三条全空 ＝ 悬空。**危害不是「没人做」，是「它看起来已经有人管了」**：文档写在那里，读的人默认它在流程里。

### Q2 的三处正本（⚠️ 只查 `TODO.md` 会整片误报）

| 正本 | 位置 | 性质 |
|---|---|---|
| `TODO.md` | 全文 | 任务／进度 |
| `HUMAN_NOTE.md` | `:57` 缓删区〈初步裁定为过时计划〉 | **活的欠账**，不是「过时计划」—— `product-positioning.md:109` 明说系自 `TODO.md` **暂时**挪出（DSH 迁移后处理、或至少挪回） |
| `HUMAN.md` | `:22`〈一些普通待办〉 | 老大自己的提醒位（AI 只读） |

⇒ 只查 `TODO.md` ⇒ 上面两片的条目**全部**会被判成「Q2 没挂」⇒ 三空成立 ⇒ **一次性误报 30+ 条**，盘点信噪比归零。

## 二、⛔ 不算悬空（先排除，否则一报一大片）

| 排除项 | 判据 |
|---|---|
| 明标「⏳ 待裁／待老大定」 | 已挂，只是等裁 —— 属「已知未决」，非悬空 |
| LA 整体未开建的部分 | LA 未上线，权限体系等运行时实现未到期；但**须确认 `TODO.md` 里有对应阶段**，无阶段才算悬空 |
| 原则／取向类表述 | 不承诺具体交付（如「靠氛围不靠限制」）⇒ 非待办 |
| 正本已指路 archive 的历史结论 | 已承接，正本指路即为有主 |
| 「上游 DSH 未实现」的事实陈述 | **上游没做完 ≠ 我方欠账**（Known Limitations／proposed／SAFETY 未审计等） |
| `exchange/log-*` 的回报格式 | log 文件按设计就是**自由格式**（近似空文件起步），无固定栏位要求 ⇒ 「某栏位未统一」⛔ 不算悬空 |

## 三、扫三类源（按此顺序，先窄后宽）

1. **`docs/`（正本）** —— 抓「承诺，待 … 兑现」「待补」「须」「应」「后续」「下一版」「未实现」「⏳」这类模式，逐条追到「具体哪一句承诺」。⚠️ 先扫 `docs/la-space/` ＋ `docs/product-positioning.md`（产品口径最密），其余 docs 次轮。
2. **`archive/`（已定但未升格进正本）** —— 🔎 已有实例：`archive/memory-ownership/memory-ownership-voices.md:241-249` Z2 告知三场景（在线／故障修复中／最坏转继承者），原仅承接送达判据 ＋ `notified` 哨兵，三场景未升；**2026-11-02 老大裁并已升格**（`docs/la-space/requirements.md` §3.1〈告知三场景〉）。保留此例作为「已定未升格」的检出样本。
3. **`exchange/log-*.md`（口头已定、既没进 docs 也没进 TODO）** —— 形态：「我记着，下次改」。

## 四、每条必须答三问（⛔ 不许留空，答「无」也要附检索式）

| 栏 | 内容 |
|---|---|
| 悬空项 | 一句话，⛔ 不写「文档某处」这种没法找的描述 |
| 出处 | `文件:行` |
| Q1 做了吗 | 证据（`文件:行` 或 commit）；**⛔ 不采信「应该做了」** |
| Q2 三处正本挂了吗 | `grep -n` 命中行号，或「无（附检索式）」 |
| Q3 在飞吗 | `log-*` 状态区／派发稿；无则写无 |
| 建议归属 | **WB 改 ／ Qoder 改（docs 归她）／ 派执行方 ／ 需老大裁** |

产出＝**五栏表**（能直接派活的形态），⛔ 不是散文。若扫完 **0 条**，也要写检索式与遍历范围（纪律③：说「没有」必须附检索式）。

**A 半复核判句**（给 Qoder）：**这句是「我们要做到」，还是「我们讨论过要」？**

**与日常当次复验的分工**：

| | 当次复验 | B 半审计 |
|---|---|---|

## 六、复验清单常设项（每条都踩过一次）

1. **闭环宣称须注「验收时点实物指针」＝文件 ＋ mtime／哈希**。凡写「已完成／复验成立」，必须同时写清：**验的是哪个文件、它的 mtime／sha 是多少、什么时候取的**。⛔ 不写「已核过」这种不可回溯的话。理由：历史条目没人回头查是全部发现的放大器——不是犯了多少错，是**错完之后没有任何东西能让人回头看见它**。
2. **⛔ 判「某配置没改」只认实物 mtime／哈希，不认 git 痕迹**。实测：`.dsh-home/` 整个在 `.gitignore` 里 ⇒ 该目录下任何文件**永远不可能**出现在 `git show --stat` 里 ⇒ 「git 零命中」是**恒真结果**、没有判别力。
3. **🔴 判「部署件正确」时，证据带 sha ＋ 时点，且复验时必须以当前部署件重取**。实测：P0② 在飞期间部署件被持续重建 —— 一份部署件证据的有效期只有一个构建周期。
4. **判据缺臂会产出「真完成」，而它看起来和「假完成」一模一样**。实例：判据「真库不变」在写入路径未做时**照样绿**（断言把写入拦下，真库自然不动）⇒ 凡判「某个改动已落地」，**必须有只对它成立的正证**，只用「没出事」作证必假。

## 七、B 半 · 假完成审计（七形态判据）

> **审计对象**：`TODO.md` ／ `log-*` 里**已标「✅ 已完成／已闭环／已落地」**的条目。
> **核心一问**：**它符合文档的要求，还是只符合「没被追问」？**

### 七形态（逐条可判，⛔ 不用感觉）

| # | 形态 | 长什么样 |
|---|---|---|
| ① | **判据反噬** | 为了让判据变绿去改**被测对象**，而不是改判据 |
| ② | **形式在，路不走** | 代码里有这个分支／开关，但主链路从不调用它 |
| ③ | **覆盖边界缺** | 结论对，但没写适用范围，单读即被理解成全称 |
| ④ | **改一处，平行处未改** | 同一规矩散在多处，改了其中一处就报完成 |
| ⑤ | **部分报全量** | 做了 A 段报「已完成」，B 段不提 |
| ⑥ | **自述当证据** | 拿执行方的说明当完成证据，没回源 |
| ⑦ | **过期证据** | 数字**在写下时为真**，交付时已被后续动作推翻；报告内部一致、精度漂亮，只能靠**外部时间戳链／哈希**发现 |

### 判法

每条给三档之一：**符合 ／ 不符（标形态编号）／ 无法判（写明缺哪份证据）**。⚠️「无法判」也必须写缺什么，⛔ 不许滑进「大概没问题」——那是把没查成说成了没问题。

**⑦ 与 ⑤ 的区别（处置不同，别合并）**：⑤「部分报全量」要**补做**（是活）；⑦「过期证据」只要**重取一次**（是动作）。前者补完还得验，后者重取即结案。
**⑦ 的查法**：⛔ 不能只读报告 —— 必看**外部指针**（产物 mtime ／记下的 sha 与实物当前 sha ／报告引用的 run 编号），核对「这个数字是哪一次跑的」。

### 抽样规则（不可能全查，先定死）

| 档 | 范围 |
|---|---|
| **必查（不抽样）** | 涉 Tier0 的全部；**曾被回退／订正过的**（有病史，复发率高） |
| **抽样** | 近 30 天宣布闭环的；老大点名 |
| **不查** | 已**如实自我限缩**的（如明写「回传侧未做」）—— 人家说了没做完，不算假完成 |

### 三条边界

1. **ZCode 可以反驳判据本身**。若某个形态在这批条目上不成立，直接说「这条判据不适用」，⛔ 别硬套。判据是 WB 出的，她不在场才判得干净。
2. **ZCode 只读，⛔ 不代改**。判定归她，改动归归属方（WB／Qoder／执行方）。
3. **WB ⛔ 不预先给结论、⛔ 不圈定「肯定没问题的那几条」** —— 圈了就等于替她缩了靶子。

## 八、方法论六条（WB 2026-11-02 提出 · ⛔ 非约束）

> 手感经验，不替代 §一～§七 的判据；冲突时以判据为准。

1. **文档自带的可复算判据 > 自造关键词**（实例：`docs/product-positioning.md:109` 的脱钩检出式抓到了关键词没扫到的东西）。
2. **标题是筐，不是定性**（实例：`HUMAN_NOTE.md`〈初步裁定为过时计划〉区里 30+ 条是活欠账）。
3. **行号与条目号皆脆弱引用**（实例：「`TODO` 待核段第 5 条」已漂成第 1 条）。
4. **「文档承认没做」与「没人知道」要分开报**（前者可能是主动搁置，后者才是真漏）。
5. **排除项比命中更重要**（实例：一批 50 处命中只有 3 条真问题）。
6. **写判据先跑基线**（写「改后 X=0」前先测它现在是不是 0，否则造出天生为红的假判据）。
