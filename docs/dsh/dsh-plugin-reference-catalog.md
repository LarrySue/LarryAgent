# DSH 插件参考清单（值得参考插件策展）

> **定位**：DSH 生态（及值得借鉴的外部生态）中**值得参考的插件**的长期策展清单——每件沉淀「**值得参考的点**」。⛔ **只借鉴不直装**（原则 = `docs/dsh/dsh-migration.md` §3.0），本清单不回答"装不装"、只回答"参考什么"。**"浩如烟海"是常态** ⇒ 只收**筛选后的观察对象**，宁缺毋滥。
> **维护人**：**Qoder**（老大 2026-10-12 设立并归口）。
> **更新模式**：**老大触发制**——不设定期任务、不设执行间隔；每轮更新在 §⑥ 版本记录留痕。
> **区域属性**：本文件是 `docs/`（定案区）内的**例外活文档**——由 Qoder 持续维护；其余 AI 不直接改动（发现问题向 Qoder 或老大提出）。长期策展、不随任何阶段专题归档。

## ① 收录判据 ＋ 标注体系

**收录判据**（满足其一即可候选，最终由策展判断）：
1. 有**可借鉴的设计模式／机制／实现技巧**，且能与能力树（`docs/product-positioning.md` 2.x）某子项建立映射；
2. 代表某种**产品形态**的先行实践（即便我方暂无对应子项）；
3. 老大点名关注的对象。

**淘汰判据**：与产品定位冲突 ／ 关键信息无法核实 ／ 长期无活力且参考点已被吸收 ⇒ 移入 §⑤ 淘汰区（**留一行理由，不静默消失**）。

**标注体系**（沿用 `docs/ai-governance.md` §3.1 证据分级）：🟢 已实测验证 ｜ 🟡 已读源码／规格（未实测）｜ 🔴 待研（仅传闻／一句话描述）。

**两条硬纪律**：
- **版本脱节哨兵**（`docs/dsh/dsh-migration.md` §3.0.1 事实 14）：每件必核其 peer 对基线 `dsh-v0.1.5-rc.2` 的 semver 兼容声明——社区件曾出现 `^0.1.0-rc.7` 对我方基线判 false 的实例；
- **采集锚**：每条记**采集日期**与**当时基线 tag**；换基线时旧读数不自动外推（与 3.4 基线结论同一纪律）。

## ④ 观察渠道与工作方法（后续轮次）

1. **社交平台（国内外）**：X ／ Reddit ／ 掘金／V2EX／微信公众号等的 DSH 插件讨论与实测帖——重点采**真实使用反馈**（活力与坑）；
2. **GitHub 状态**：stars 趋势／最近提交／issue 响应／是否 archived——判定**活力**；
3. **技术角度**：源码与架构（capability seam 对接方式、与官方 `docs/subsystems/` 53 篇规格的契合度）；
4. **官方生态**：上游发行说明与包组地图（`docs/dsh/dsh-015-upstream-inventory.md` 表 B）——新官方件优先看。
