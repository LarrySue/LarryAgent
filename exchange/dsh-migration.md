## 零、项目情况简介（供未介入本项目的 AI 参考）

> 本节为自足背景，目标读者是**完全未参与本项目**的外部 AI——读到这里即可对「这是什么项目、为什么讨论时间上下文」形成完整理解，无需再翻其他文件，Trae、Claude、Marvis、Workbuddy、Qoder可忽略此部分。

**LarryAgent 是什么**：个人 AI Agent，单人使用、**第一版起即面向云部署**（当前本机仅开发+测试环境，尚未达到第一版发版）。PC 版为 C/S——client 在本机不上云（选 C/S 而非 B/S 为本地文件操作能力）、server 部署云端；移动版为 B/S。核心能力三件：管对话、有长期记忆、能调工具（读写文件 / 执行命令 / 联网搜索）。技术栈 **Python FastAPI + SQLite + ChromaDB + Vue 3 + Tauri + HTML5**（PC 端 Tauri 壳，移动端 HTML5 规划中）。

**多角色机制**：对话由「角色」驱动，每个角色 = 一套 system_prompt + 可选工具组合。当前有 `default`（通用）/ `code`（编程）/ `health`（健康）/ `finance`（金融）/ `science`（科学）五个角色，角色清单由后端 `config.yaml` 统一管理、经 `GET /api/roles` 下发前端动态渲染。

**记忆系统现状**（本讨论的地基）：

- **短期记忆**：对话消息存 `messages` 表（SQLite），按会话组织。
- **长期记忆**：会话归档时，把整段对话交给 LLM 摘要成单条 summary → 写入 `memories` 表（SQLite）+ 向量化入 ChromaDB。**双写结构：SQLite 是真相源，ChromaDB 只是可重建的索引**。
- **召回**：新对话时按语义相似度从 ChromaDB 检索相关记忆，拼进上下文。

## 二、DSH 事实画像

> 来源：2026-09-06 WebSearch + 公开资料（DeepSeek 官方仓库 `deepseek-ai/deepseek-harness`、官方站 `deepseek.com/harness`、技术社区解读）。
> **注意**：star / fork 各源口径差异较大（65.6k ~ 137.1k），不作为判断依据，此处不录。

| 维度 | 事实 |
|---|---|
| **是什么** | DeepSeek 官方开源 **Agent Harness（智能体运行框架）**。官方公式 `Agent = Model + Harness` |
| **不是什么** | **不是大模型、不是推理引擎**（≠ vLLM / SGLang）。模型负责推理，Harness 负责对接环境、工具闭环、任务调度、权限管控、会话追踪 |
| **定位** | **架构通用、开箱偏编码**。内核无特权、连 Agent Loop 都可换 → 理论可做通用 Agent；但内置工具（文件读写编辑 / Shell / 代码解释器）与四模式**均围绕编码场景**设计，官方对标 Claude Code / OpenHands / Aider |
| **官方口径分歧** | 多数解读称"AI **编程** Agent Harness"；亦有解读明确「**不是单一编码助手**，而是可组装的智能体基础设施」——**并不矛盾**：架构通用 ≠ 开箱通用 |
| **口号** | Everything is a Plugin（万物皆插件） |
| **内核** | **Cordis** 插件总线（Koishi 生态插件内核） |
| **主语言** | **TypeScript**（Monorepo，`packages/` 下 40+ 包） |
| **许可证** | MIT |
| **创建 / 版本** | 2026-08-13 创建；当前 **0.1.0-rc.7**（2026-08-17） |
| **官方状态明示** | **developer preview**，README 加粗大写强调"会有破坏性变更" |
| **运行形态** | Web UI（`127.0.0.1:3080`，`npx @deepseek-ai/dsh web`）+ headless + **ACP** |
| **四模式** | `standard`（完整工具栈）/ `PTC`（程序化工具调用，省 Token）/ `minimal`（benchmark）/ `creative`（插件热加载） |

### 2.1 关键能力（按与本项目相关度排序）

1. **沙箱安全策略分级**（对应 #9）：`workspace-write` / `read-only` / `danger-full-access`；高危操作可人工确认；事件监听可加拦截策略
2. **会话持久化 + 上下文压缩**（对应 #13）：SessionEvent 追加日志，铁律"模型可见即已记录"；支持 **fork 分叉 / resume 恢复 / compaction 上下文压缩 / 回放**
3. **Trajectory 完整轨迹**（对应 #11）：思考、工具调用、返回结果**全记录**，比"工具名+状态+摘要"更完整
4. **结构化工具管道**（对应 #2）：前置策略拦截 → 沙箱守卫 → 审批 → 超时重试 → 结果规范化 → 后置处理
5. **多模型适配**（对应 #1）：内置 5 适配器（DeepSeek-V3 / R1 / OpenAI 兼容 / Anthropic / Ollama），可配置**多模型路由**
6. **子代理委托 + Skill**（对应 #3）：`spawn` / `fork` 两种子代理，支持后台任务与工作流编排
7. **真正的插件总线**：模型适配器、文件工具、Shell、Skill、会话存储、权限、主循环、UI 全部可插拔可热替换，副作用随卸载撤销

> **PTC 模式**（对应 #8，部分）：模型输出 TS 代码编排批量工具调用，减少 LLM 往返、省 Token。
> **ACP（Agent Client Protocol）**：headless 之外的自动化服务协议，是 B / D 路径集成的关键抓手。

## 三、基于 31 子项的承接对照（当前评估，2026-09-06 23:00，老大待审）

> **老大新判断框架**："业余项目造几个月不如开源、难追技术趋势"——这是经济性论证，与原"完全不适合、没有必要"框架有交集但不完全重合。**事实底稿保留**，新评估重做对照。

### 3.1 一句话结论

**思路价值 60%、代码复用价值 10–20%、换底座经济性不值得**。

### 3.2 DSH 真能替的（3 块通用机制层）

| DSH 能力 | 对应子项（新编号） | 现状 | 净增量 |
|---|---|---|---|
| **compaction 上下文压缩**（按行业 2026 路径：工具结果遮蔽 + 历史摘要 + 滑动窗口） | 2.9.2 超长会话一致性 🚧 | 现靠 `max_input_tokens` **截断旧消息**，**机制反向**（是丢，不是压） | **显著** |
| **沙箱分级 + 高危人工审批 + 事件拦截策略** | 2.7.1 行为安全硬护栏 ✅（弱）、2.7.2 边界透明 ✅ | 现仅有 IP 白名单 / 目录限制 / SSRF 拦截 / 工具轮次上限，**无审批、无分级** | **显著** |
| **Trajectory 完整轨迹（含思考 + 全事件流）** | 2.8.2 AI 行为可见 ✅ | 现 ToolCallCard 仅"工具名 + 状态 + 结果摘要" | **有增量**（更完整） |

> 这三块确实是 DSH 强项，**也是你现在造得费工 + 容易做得不够好的地方**——符合"业余项目不造通用轮子"的判断。

### 3.3 DSH 一概替不了的（产品专属层）

| 类别 | 子项（新编号） | DSH 状态 |
|---|---|---|
| **长期记忆闭环** | 2.4.1 短期记忆 ✅ / 2.4.2 长期记忆（SQLite + ChromaDB 双写 + 本地 bge-small-zh）✅ / 2.4.3 记忆可管理 🚧 / 2.4.4 保鲜与失效 📐 / 2.4.5 用户画像 📐 / 2.4.6 知识库 🗣️ | **一概不管**——DSH 的 session log 是原始事件流水，与 LarryAgent 的摘要+向量语义记忆互补不替代 |
| **角色机制** | 2.6.1 角色切换 ✅（含 system_prompt + 工具组合 + config 下发） | 不管 |
| **工具生态** | 2.5.1 多模型切换 ✅ / 2.5.2 工具挂载 ✅（shell/file_ops/web_search 三个）/ 2.5.3 扩展性 ✅ | 不管 |
| **会话管理** | 2.3.1 回收站 🚧 / 2.3.2 对话体验 🚧 | DSH 的 session fork/resume ≠ 回收站（不同语义）；DSH sandbox 是权限沙箱 ≠ 每会话文件沙盒 |
| **可见性产品表述** | 2.8.1 沉淀信息可见 🚧 / 2.8.3 资源消耗可见 🚧 | 不管 |
| **形态专属** | 2.10.1 云端部署 📐 / 2.10.2 端侧能力 📐 / 2.10.3 单人单实例 ✅ | DSH Web UI 是**本地**形态（`127.0.0.1:3080`），与 LarryAgent 上云 + 多端形态**冲突**；单人形态 DSH 也未提供 |

> **核心判断**：31 子项里 **≈15 个 ✅/🚧 + 5 个 🗣️/📐 = 约 20 个是产品专属**，开源里没有对应物。你造这部分不是"造轮子"，是"市面上没这种产品"。

### 3.4 DSH 自身风险

| 风险 | 事实 | 影响 |
|---|---|---|
| **preview 阶段** | `0.1.0-rc.7`（2026-08-17），官方 README 明示**破坏性变更**；项目仅 3 周大；当时未见 GA 时间表（**需复核最新版本**) | 把已过 P4 的 LarryAgent 押在 rc 框架上，返工风险实打实 |
| **跨语言** | DSH 是 **TypeScript** Monorepo；LarryAgent 后端是 **Python FastAPI** | 走 A/B 路径即成本大头 |
| **生态不确定** | DeepSeek 路线 / 插件市场 / 文档完整度均处于早期 | 长期可持续性未验证 |
| **会话存储外接能力** | DSH 会话存储是否可外挂自有存储（如 SQLite）——关系到能否保住现有 memory 层，原 §九 调研待办保留项 | 决定迁移后能否双轨并存 memory |
| **headless + ACP 契约稳定性** | 自动化服务协议是 B / D 路径集成抓手，原 §九 调研待办保留项 | 决定 B / D 路径能否成立 |

### 3.5 路径推荐：C 借思路（强推）

**做法**：把 DSH 的 compaction prompt 设计、审批事件钩子、Trajectory 记录结构**抄过来**集成到现有 Python 后端，不动现有架构。

| 指标 | 估值 |
|---|---|
| 成本 | **1–2 周**（学习 + 集成 + 测试） |
| 收益 | 直接让 **2.9.2 / 2.7.1 / 2.8.2** 三个 🚧 升 ✅；2.4.4 保鲜/失效可借鉴；2.5.3 MCP 接入可省一半力气 |
| 返工风险 | **零**（增量集成，不动现有架构） |
| 押 preview 风险 | **零**（只抄思路，不绑运行时） |

**操作路径**：
1. 让 Trae 做 2 周内可集成的 prototype：compaction prompt + 工具结果遮蔽（先不做 LLM 摘要）+ 高危工具审批 UI
2. Claude 单独测（不动现有 P4 测试矩阵）
3. WB 复验：是否真覆盖三块、不引新依赖

### 3.6 不推荐

| 路径 | 不推荐理由 |
|---|---|
| **A 换底座** | Python → TypeScript 重写 + 仍要重做 60% 专属代码 + 押在 preview 框架 + 形态冲突（本地 Web UI vs 上云多端）。经济性算不过来 |
| **B 嵌一层** | 跨语言通信 + 双套会话状态同步 + 记忆层须双轨并存。成本中、收益与 C 重叠大半，但复杂度高一档 |
| **D 接能力** | 适合"想要 DSH 独家能力"时再用（如 DSH 某些 model 路由或工具编排）。当前诉求是"少造通用轮子"，C 已满足，D 不必 |
