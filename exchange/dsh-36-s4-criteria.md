## 0 · 目标（一句话）

**挂 `session/` 事件流的自做插件，把会话记忆写进「我们自己的库」（SQLite 真相源 + ChromaDB 向量），并让新会话能召回** —— 回答「记忆本体在 DSH 下可脱离 session log 独立存 ／ 取」这一个问题。

⛔ 两个**易混成同一件事**的结论，显式拆开：
- **「双写通路成立」**（3.6，0 token）≠ **「召回对产品可用」**（3.6.1，LLM 端到端）—— 前者不依赖后者成立；
- **「降级不阻塞」**（J4）≠ **「补偿恢复」**（恢复后补写，**本步定义不验**，属产品规划 2.4.4）。

## 1 · 拆分与场地形态

| 块 | 内容 | 判据 | token | key |
|---|---|---|---|---|
| **3.6** | 双写闭环 ＋ 注入面 | **J0–J5** | **0** | **不需要** |
| **3.6.1** | 召回闭环（LLM 端到端） | **J6** | 少量 | 需要（env 层注入） |

- ⭐ **0 token 的构造原理**（同 3.0 三态教训）：无 key 态下 session 照常建立、`user/message` 与 `turn/end`（reason=error）事件照常产生（3.0 实证：无 key 时 exit 0 + session + 12 条事件）⇒ 事件消费与落库**不需要 LLM 调用**。⚠️ **该假设 v1 只是推断（V16）⇒ J0 第一件事就是把它变成枚举事实**（事件清单不在列 ⇒ 停手回报，0 token 形态重设计）。
- ⭐ **J5 并入 3.6 的理由**（裁定①）：注入面（`systemPrompt.context`）是整条管线**最易静默失效**的一跳（参考件哑坑②变体：provider 注册了但装配时没调到 ／ 被覆盖 ／ 被裁剪），且它 **0 token 可验** ⇒ 没有理由留到 key 块。
- ⭐ **临时 home = 无 key 态的骨架，但不充分（V15）**：`mkdtemp` 只消掉凭据四层里的第 2（存储文件）／ 4（主目录 `.env`）层；**第 1 层（启动环境）与第 3 层（调用 cwd 下的 `.env`）不受临时 home 影响** ⇒ 必须 **J0 显式自证**（显式不注入 ／ 清除 `DEEPSEEK_API_KEY` ＋ 确认 cwd 无 `.env` ＋ 记三元组），否则「0 token 承诺失效 ＋ 三态混淆」。
- **插件进临时 home 的手势（V17）**：`dsh plugin --profile sdk add <dir>`（先例 `harness/scripts/run-33b-remote-approval.mjs:204-221` ／ `:454`）；**副本须删 `.modules.yaml`**（381 `:100` ／ 33b `:159`；否则 Windows 上 1 s 即 `ERR_PNPM_UNEXPECTED_VIRTUAL_STORE`）。每个验收脚本头部加**姿势自证**一行（`dsh-migration.md:914` 规则：模拟的是哪条真实链路 —— 哪个 home ／ profile ／ 通道）。
- **key 纪律**：3.6.1 的 key 走 env 层注入（优先级最高、精确可控）；`.credentials.yaml` 的**值不进派发稿、不进日志、不进证据**。

## 2 · 判据（四问形态：作用层 ／ 计量口径 ／ 结果态可分 ／ 断言视图）

### J0 无 key 态自证 ＋ 事件清单预检（v2 新增 · V15 ／ V16 ／ V13）

- **作用层**：本块一切 0 token 判据的**前置门** —— 不成立则后面全停。
- **计量口径（三条全满足）**：
  1. 显式清除 ／ 不注入 `DEEPSEEK_API_KEY`，确认 invocation cwd 无 `.env`；记 **(DSH_HOME, profile, 凭据来源层) 三元组**（照 3.0 口径）；
  2. 断言该轮**无 `assistant/message`** 且 `turn/end` 非 completed（reason=error 态）；
  3. **落事件类型清单**，断言 `user/message` 与 `turn/end` **在列**（3.0 旧证只到「12 条事件」数目、未枚举类型 ⇒ 本步补枚举）。
- **顺带预检（0 成本，闭合 V13）**：同一次跑 dump `request/header` 与 `request/context` **两帧原文** ⇒ 定死「召回注入块出现在哪一帧」，J5 ／ J6 按它落（项目自有记录：`request/header` = 完整 system prompt ＋ 工具 schema ／ `request/context` = 注入上下文，`dsh-migration.md:649`；**注入块在哪帧未实测**，写错 = Trae 撞假红后自行换帧、无人复核）。
- **结果态可分**：清单缺 `user/message` ／ `turn/end` ⇒ **停手回报**（⛔ 不得自行换事件类型凑）。
- **断言视图**：事件清单原文 ＋ 两帧原文落证据目录。

### J1 事件确实被消费（不是只注册了监听）

- **作用层（唯一判定载体）** = **我们 SQLite 库里含 nonce 的记忆行**。
- ⛔ **不算的层**：① 插件 `inject` ／ `provide` 声明在、activate 打点有 —— **注册 ≠ handler 挂上 ≠ 事件流到 handler**（参考件哑坑①：provide 类则构造器从不跑；⭐ **且订阅挂在构造函数里（`lib/index.js:1119-1133`）⇒ 服务不实例化 = 连订阅都不生效**，比哑坑①更狠一层）；② DSH session log 里有事件 —— 自家持久化，**恒真**（双写是语义层，`dsh-pysdk-probe-trae.md:135`）；③ `--dump-config` 里插件行在 —— 只组配置树、不激活插件（L0 已定假绿源）。
- **计量口径**（v2 修补 · V1 ／ V2）：
  - 正向：一个会话 user message 含 `PING-<nonce>`（无 key 态即可）⇒ 库里可查到含同一 nonce 的行；**行内须带事件派生字段**（参考件现成形状 `sourceEventSeq`，`lib/index.js:2183`），与该会话事件流里的 `user/message` seq **交叉核对**（把断言从「文本进了库」升为「**该事件**被消费」——否则轮询 session.jsonl 等非事件通道也能满足）。
  - **开跑前断言目标库为空**（或该 nonce 不存在）⇒ 防残留满足。
  - 负向对照（v2 改写 · V1）：⛔ 不再按「行数」断言（轮末摘要形状会落不含 nonce 的行 ⇒ 误红，或诱导实现方砍掉摘要）—— 改为 **①「同装置只建会话、不发 prompt」＋ ②「发一条不含对照 nonce 的 prompt」两臂，均不得出现带该 nonce 的行**。
- **断言视图**：直读 SQLite 库文件；⛔ 不在内存对象 ／ 打点日志上单独断言。

### J2 数据落在我们自己的库（带反向哨兵）

- **作用层** = 插件配置指定的**外接 SQLite 绝对路径**（临时目录下 `larry-memory-<run>.db`，不碰任何活库）。
- ⭐ **反向哨兵**（判据有效性的检验本身）：把 path **指回临时 home 内的 DSH 默认后端**（session 落盘目录）⇒ 数据**不在**我们指定文件里 ⇒ J2 **必须变红**。
- **v2 修补（V3，红因不唯一 = 伪哨兵）**：
  - 哨兵臂**加阳性证据**：nonce **出现在哨兵位置**（或插件日志明示写入哨兵路径）⇒ 证明红因是「指错了路」而不是「插件根本没工作」；
  - 两臂**共用同一 nonce ／ 同一断言目标文件**；哨兵路径**写死为临时 home 内**某目录（⛔ 照字面「DSH 默认后端」实现有落真 home 的风险）；
  - 哨兵臂是**另一次跑**（同装置、换配置），留痕两次运行标识。
- **计量口径**：库文件里能**查到同一 nonce**（同 S0④：不是「文件存在 ／ 条数够」）。
- **断言视图**：库文件内容；⛔ 不在「DB 对象已 open」上断言。

### J3 ChromaDB 双写落库

- **作用层** = chroma collection（HTTP：`chromadb` npm client → `npx chroma run --path <临时目录>` 起的 node server；server 与库路径均临时，收尾清理）。
- **计量口径（v2 写死四件 · V5）**：① **读基线 → 跑 → 增量 ≥1** 且**按 nonce 定位到目标条**（⛔ 不写「count+1」无基线式）；② **id 来源 = SQLite 行 id**，顺带断言 **Chroma id ≡ SQLite 行 id**（双写关联）；③ server 起时**钉临时端口**并两侧显式配置（防连错 server）；④ **v2 新增（V4）取回存储向量验能力指纹**：维度 = **512**（bge-small-zh；chroma 默认 embedding 为 384 维 MiniLM 级 ⇒ 不传向量时被 server 默认函数免费满足，①②③ 全绿而我方设计一字未验）；更强做法 = 与 `embed-probe` 同文本本地向量做余弦比对（`ts-embed.mjs:34,51,61,66`，DSH-2.5 实测漂移 2.2e-7 ⇒ 阈值按数量级 **0.9999**）。
- ⚠️ 「以 nonce 原文自检索 top-1」**判别力弱**（同文本 → 同向量 → cosine≈1，近乎恒真）⇒ 只作旁证，**判别力靠④**。
- **embedding 来源** = 我方 TS 侧 bge-small-zh 资产（`harness/scripts/embed-probe/`）；⛔ 不用 server 默认 embedding。
- **结果态可分**：负向对照 = 停 server 后 add 不得静默成功（落 J4）。
- **断言视图**：chroma HTTP API 的 get/query 返回原文；⛔ 不在插件侧「我调用了 add」上断言（调用 ≠ 落库 —— 参考件哑坑②同款）。

### J4 降级行为（ChromaDB 不可达）

- **作用层** = 停 chroma server 后**继续跑一轮**（无 key 态）三条件：① 对话不阻塞 ② SQLite 真相源**仍写入** ③ **日志有降级记录**。
- **v2 修补**：
  - **双锚改向（V6）**：活臂 ③ 原写「日志有降级记录」⇒ **活臂不可能有降级，自相矛盾**。改为 —— **活臂：①不阻塞 ②真相源在 ③「不得出现降级行」**（反向日志哨兵）；**停臂：①不阻塞 ②真相源在 ③降级行在**。
  - **③ 写死（V6）**：通道（stderr 或插件日志文件）＋ **唯一匹配串**（须含本次失败特征，如 URL ／ errno）＋ 只允许出自失败路径（⛔ 启动期无条件打印一行 `chroma disabled` 不算）。
  - **① 加时间界（V7）**：无 key 态 turn 本就 error 终局 ⇒ 「走完到终局」**恒真**（插件拖几十秒也绿）。给**数量级时间界**（终局时刻 − prompt 起跑 < X s，X 取同日活臂同轮消耗同数量级；软阈值报警不写精确区间）；**或诚实收窄** —— 明写「本臂只覆盖 connection-refused 快失败，不测 hung-server」列为边界。
  - **③ 的依据摆正（V8）**：`product-positioning.md:182` 原文只有「ChromaDB 不可用时静默降级，不阻塞对话」，**无「须留日志」字样** ⇒ 改写为「**我方判据要求**（纪律出处：`dsh-migration.md:814`『静默 fail-closed 会制造假绿』）＋ 标注『产品文档未明写、属口径引申』」。红线不变，权威来源摆对。
- **产品口径**：「静默」指**不弹给用户**，⛔ 不是**无日志**；观测点在日志，日志无记录即红。
- **断言视图**：turn 终局事件 ／ 我们库 ／ 插件日志三处分别取证。
- ⛔ **本块不验**：恢复后补偿补写（「定义不验」，见 §3 ／ §6-3）。

### J5 召回注入面（v2 并入 3.6 · 0 token）

- **作用层（v2 上移 · V9）** = **装配产物**：召回注入块出现在 **J0 预检定死的帧**（`request/context` 或 `request/header`）原文里，且含目标 nonce。
- ⛔ **不算的层**：① 「provider 注册成功」—— ⚠️ 参考件自己把注册包在 try/catch 里（`lib/index.js:2230`，失败只 `console.error`）⇒ **注册 API 不抛错 ≠ 注册生效**；② `text()` 返回值单独断言 —— 相对「模型实际收到的 system prompt」**同样是中间表示**（provider 算得对 ≠ 装配时调到了它：注册在无人读的路径 ／ 被后注册覆盖 ／ order 后被裁剪 —— 哑坑②变体）；**若因故只能调 `text()`**，须改为「观测**装配过程调用过该 provider**」（调用计数 ／ 入参留痕），⛔ 不许测试自己构造 context 调它（那样「装配真的调到了它」完全没验）；③ **WB 台账②（`system-prompt` 在 `--dump-config` 在位）只证装配存在，⛔ 不证运行时激活**（`--dump-config` 是已定假绿源，`dsh-migration.md:812`）。
- **计量口径**：注入块含同一 nonce（逐字）；块为空字符串即红。
- **v2 修补（V10）**：① **B 会话自身输入不得含 nonce**、⛔ 不复用 A 的会话（防「不召回也见到」）；② 参考件 `recallSync` 无命中时**兜底最近记忆**（`lib/index.js:1327-1333`）⇒ 小库任何 query 恒含最近条目 ⇒ **明写「本步不区分 query 命中 ／ 兜底命中」**（诚实边界，与 §5 同层；语义固定为兜底的对照臂属加强项，最小闭环不派）。
- **结果态可分**：负向对照 = **空 memory 库**（DB 指向全新文件）⇒ 注入块**不含** nonce。
- **断言视图**：J0 预检定死的帧原文；⛔ 不在事件流上断言（同 J1 ②）。

### J6 LLM 端到端召回（3.6.1，需 key）

- **作用层** = **模型实际收到的上下文**（J0 预检定死的帧）＋ **模型输出**双取证 —— 老大 2026-10-17 裁「就用 LLM 端到端」。
- **计量口径**：A 会话让模型写「项目代号 = `PING-<nonce>`」（或 user message 直接陈述，确保入库）→ 全新会话 B 问「我的项目代号是什么」→ **模型回答逐字含（连续子串）该 nonce**。
- **v2 修补（V11 ／ V12 ／ V13）**：
  - **负向臂加存在性断言**：该轮须有 `assistant/message` 且 `turn/end.reason.kind === 'completed'`（⛔ 防「key 失效 ／ 网络失败 ／ 拒答 ⇒ 没回答 ⇒ 『不含 nonce』真空成立」—— 负锚假绿，同 3.0 失败态误读教训）；
  - **正向臂加前置**：跑 B 前库里已有含该 nonce 的行（J1 已过的复述），否则停手报「属 J1 ／ J2 未过，非本判据结论」；
  - **采样口径写死**：正向 n=1 判逐字包含，允许**一次留痕重试**（报次数）；负向 1 次但须**非空回答**；**nonce 随机 ≥8 hex**（防模型瞎编击穿）、两臂**同一问句**、A ／ B **不同 session**、负向臂**不得复用 A 的库文件**；
  - **承载帧** = J0 预检定死的帧（⛔ 不再悬置 `request/context` vs `request/header`）。
- **key 纪律**：env 层注入；⛔ 不承担 key 落位证成（3.0 已闭环事）。
- **断言视图**：帧原文 ＋ assistant/message 输出**双取证**；⛔ 只凭模型输出不算（证明不了是召回注入起的作用）。

## 3 · 双写一致性模型（3.6 交付的「定义」，判据只验其可观测部分）

- **模型定义**：SQLite = **真相源**（同步写、权威）；ChromaDB = **派生索引**（后写、可重建 —— 承 `product-positioning.md:178`「可由 SQLite 重建」）。
- **不可达时**：SQLite 写入**不受影响**（fail-open 只在向量侧；真相源侧 fail-closed——写不进真相源必须报错）；对话不阻塞；**日志记降级**（J4 验的正是这三条）。
- **补偿**（恢复后按 SQLite 重建 Chroma）：**本块只定义、不验** —— 产品规划已列（`:210` 向量同步补偿，属 2.4.4）；最小闭环边界，诚实写进回报。⚠️ **本项为 WB 裁（§6-3），待老大终审确认**。
- ⚠️ **双写不是事务** ⇒ 定义里必须写明「允许短暂不一致，以真相源为准收敛」，⛔ 不得声称「双写一致」（那是不可能交付的）。
