**Marvis 宏观视角 v4（2026-08-15）：DeepSeek Harness (DSH) 评估记录**

背景：8 月 13 日晚 DeepSeek 开源 Harness (DSH) v0.1 开发者预览版（MIT，Node.js/Cordis，对标 Claude Code/Codex），评估是否抛弃 LarryAgent 转投。

**结论：差距过大，不建议转投，但值得借鉴。**

三个硬伤：
1. 技术栈割裂——LarryAgent 是 Python/FastAPI/ChromaDB，DSH 是 Node.js/Cordis，转投 = 推倒重来（Python SDK 仅是调用入口，深度改造 Agent Loop/插件仍在 Node 侧）
2. 灵魂能力 DSH 不直接给——记忆系统、token 成本控制、安全边界（shell 白名单 / api key 鉴权）均需自建插件，等于丢弃自研差异化后用插件重写一遍
3. v0.1 预览版，破坏性迭代风险，作为个人项目长期基座不成熟

值得借鉴三点：
1. "一切皆插件"架构——未来让工具层更可替换
2. Session Log 全量可重建（恢复 / 回放 / 审计）——补调试盲区
3. 多 Agent 编排 + 长任务 + 计划 / 待办机制——六 AI 协作的成熟参考

路径定位：DSH 是参照系，不是替代品。个人数据主权 + 记忆 + 低成本必须自研，DSH 架构可在 P4/P5 少走弯路。

**Marvis 宏观视角 v5（2026-08-15）：关于"轻松 vs 了解"的边界——人类知情权**

起因：老大提出，随 AI 参与度提高，自己越来越轻松，但对项目越来越不了解，需评估该趋势。

核心判断："轻松"与"了解"本不该零和，现在变零和是因项目缺一条"人类视角的主线"，而非 AI 干得太多。

健康的了解度下降：代码细节、测试写法、具体实现——本就该越来越不碰，是 AI 参与的价值所在。

必须始终保有的四样（决定项目归属）：
1. 架构关键决策——为什么这么设计
2. 安全边界——哪里危险、危险在哪、取舍依据
3. 约束与红线——哪些限制生效、为什么存在
4. 当前状态——进行到哪、卡在哪、下一步

最危险信号：连约束 / 红线都由 WorkBuddy 单方定，若老大不清楚"有哪些约束、为什么"，则原则 4（明确安全边界）退化为 AI 单方约定，违背本意。交流区由 AI 全权维护同理，把老大挡在信息流之外。

结论：要保的不是"动手能力"，是"知情权"；轻松是目标，知情是底线，可兼得，前提是补一条人类视角主线。

方向（节奏与取舍由老大定）：
- 关键决策的"为什么"记在老大 30 秒能扫到的地方，而非散在 exchange 各文件
- AI 定期出"人类版简报"：变了什么、为什么变、有什么风险（非代码 diff）
- 老大保留最终知情权与裁决权，让出动手权与实现权
