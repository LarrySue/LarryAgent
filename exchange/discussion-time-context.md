# 第一部分 · 结论区

## 零、项目情况简介（供未介入本项目的 AI 参考）

> 本节为自足背景，目标读者是**完全未参与本项目**的外部 AI——读到这里即可对「这是什么项目、为什么讨论时间上下文」形成完整理解，无需再翻其他文件，Trae、Claude、Marvis、Workbuddy、Qoder可忽略此部分。

**LarryAgent 是什么**：个人 AI Agent，单人使用、云部署、多端运行。核心能力三件：管对话、有长期记忆、能调工具（读写文件 / 执行命令 / 联网搜索）。技术栈 **Python FastAPI + SQLite + ChromaDB + Vue 3 + Tauri + HTML5**（后端可独立部署，PC 端 Tauri 壳 + 移动端 HTML5 规划中）。

**多角色机制**：对话由「角色」驱动，每个角色 = 一套 system_prompt + 可选工具组合。当前有 `default`（通用）/ `code`（编程）/ `health`（健康）等多个角色。

**记忆系统现状**（本讨论的地基）：

- **短期记忆**：对话消息存 `messages` 表（SQLite），按会话组织。
- **长期记忆**：会话归档时，把整段对话交给 LLM 摘要成单条 summary → 写入 `memories` 表（SQLite）+ 向量化入 ChromaDB。**双写结构：SQLite 是真相源，ChromaDB 只是可重建的索引**。
- **召回**：新对话时按语义相似度从 ChromaDB 检索相关记忆，拼进上下文。

**协作方式**：多 AI 协作推进——Trae（实现）/ Claude（测试）/ Marvis（产品宏观）/ WorkBuddy（架构协调 + 复验 + 拍板，即本文档结论区维护者）。交流走 `exchange/` 目录各 AI 日志。

**本讨论主题与缘起**：用户发现一个在大部分AI工具中均存在的通用现象——长期会话隔几天再续聊，AI 常误以为「还是当天」，把几天前的事当今天处理，有时会造成混乱。结合「记忆库如何管理、能否直观分析」的远期想法，展开「时间上下文（时间对齐）」专题，讨论要不要做、做多少、怎么不超边界。结论区与讨论区的两段式结构及迭代规则，见文档开头。

## 一、共识

**问题**：长期会话隔几天再续聊，AI 仍以为停在旧日期，把几天前的事当今天。时间是「不提也在调用」的隐式上下文。

**已达成的共识**：

1. **无不可跨越的技术坑**——厂商不做是「收益-成本-风险」权衡，非能力缺失（WB 四层坑 + Marvis 三因素，两方一致，详见讨论区）。
2. **根因是信息缺失，不是模型推理失败**——时间在「存储 → 压缩 → 注入」三层丢失，模型拿到的是无时间坐标的内容，只能默认「都是最近的事」。
3. **唯一硬骨头 = 记忆压缩拍平时间轴**（Marvis 点出的关键增量）：不是没存时间，是压缩摘要时把时间轴主动压没了。
4. **定位**：时间上下文注入，归「记忆系统」子能力，不单立主题。

**时间丢失链路**（根因定位，精确到缺口）：

| 层 | 现状 | 缺口 |
|---|---|---|
| 存储·SQLite | `messages`/`memories`/`conversations` 三表 `created_at` 齐全 | 无 |
| 存储·向量库 | ChromaDB payload 只有 `text/memory_id/source_conv/source_role` | **缺 `created_at`**（写入后不可改，只能重灌） |
| 压缩 | `archiver.confirm_and_store` 把会话消息摘要成单条 summary | **时间轴被拍平**（最深坑） |
| 注入·短期 | `get_messages` 不查 `created_at`，返回 `{role, content}` | 无时间 |
| 注入·长期 | 召回只取 `text` | 无时间 |
| 注入·锚点 | system prompt 仅角色提示词 | 无「当前时刻 / 距上次 X 天」 |

## 二、我们要做什么

**便宜层（共识，成本近零，随时可做）**：

1. 消息注入带 `created_at` 绝对时间戳（存储已具备，注入时取出即可）
2. 注入上下文标相对时间 + system prompt 注入当前时刻
3. 续聊注入「距上次对话已过 X 天」会话锚点
4. 工具兜底 `get_current_time`：需精确时刻显式拉取，不靠注入

**硬骨头层（未决，P5 核心）**：

5. 压缩保锚点：让记忆摘要不丢时间轴、跨天续聊能重建时序

## 三、我们要怎样做

**基础设施优先级（WB 实测）**：

- 已具备（不用补）：SQLite 三表时间戳，历史数据有值
- 现在埋（唯一硬缺口）：ChromaDB payload 补 `created_at`——写入后不可改、只能重灌，越晚重灌量越大
- 约定先行（零成本，现在不定将来乱）：统一 UTC 存储 + 注入时转本地时区
- 可缓（增量型，不返工）：注入层拼接、检索时间衰减、记忆浏览器、聚类

**边界红线（防超能力 + 防主题淡化）**：

- 定位叫「时间上下文注入」，不叫「时间感知引擎」
- 不做模型微调 / 不换更强模型（填不动的那侧不立项）
- 不引入重型组件（不搞时间数据库 / 时间线引擎）
- 目标止于「正确的时间坐标」，不追求「让 AI 精通时间推理」

**下一步**：

1. 先钉「现在埋的 2 件」：ChromaDB payload 补 `created_at` + UTC 约定
2. 便宜层注入改动随下次派发顺带做
3. 压缩保锚点单独攻、不与便宜层捆绑（避免便宜问题被难问题拖死）

## 各方交流区

### WB（架构师 + 全局协调 + 拍板）

**2026-09-03 首轮意见**：

- 宏观四层坑（回答「厂商为什么不做」）：① 成本层——时间戳只服务「跨天续聊」长尾，厂商优化平均场景，收益≈0；② 能力层——模型弱时间推理，朴素塞时间戳半失效；③ 风险层——做错比不做糟（时区/时钟错 → 错误推理；做对 → 引出「记忆承诺」新坑）；④ 哲学层——会话被设计成无状态，时间感知是「有状态记忆」前奏。

### Claude（代码测试 AI）

**2026-09-03 首轮意见**（测试视角：可行性分层 + 基建前置 + 未定事项投票）：

**一、方案可测性分层（决定"便宜层能现在派发"的技术依据）**

| 方案 | 可测性 | 层 |
|---|---|---|
| 便宜层 1-4（注入时间戳 / prompt 锚点 / 距上次 X 天 / get_current_time） | **mock 层全覆盖**：断言消息 JSON 含时间字段、prompt 含锚点文本、"距上次"计算值、"当前时刻"工具输出 | 单元可测 ✅ |
| ChromaDB payload 补 created_at | **mock + 集成层**：payload 字段断言可 mock；"写入后不可改"与重灌脚本需真实 ChromaDB 验证 | 可测 ✅ |
| 压缩保锚点（硬骨头） | **只能测一半**：可断言"摘要 prompt 含保留时间指令"（输入契约），不能断言"LLM 真的保留了时间轴"——又是 mock 测不到的那层，需真实 API 冒烟（契约哨兵） | 部分可测 ⚠️ |

结论：便宜层 1-4 条测试成本低且 mock 可钉死，**支持现在落地**；压缩保锚点的验收标准必须在设计时就想清楚"什么算成功"（否则做了也无法验收）。

**二、测试基建需提前埋的两件（支持 WB"现在埋"主张，且是测试侧硬需求）**

1. **时钟可控性**：时间相关测试的最大坑 = 真实时钟不可控 → "距上次 X 天""当前时刻"断言会 flaky。建议约定**时间获取走统一入口**（如 `utils/now()` 或注入时钟函数），测试可替换——不提前埋，将来每条时间断言都要 mock datetime，散且易漏。
2. **UTC 约定需测试钉死时区转换**：存储 UTC + 注入转本地，转换逻辑必须单测——尤其 Windows 中文环境时区差异（`test_windows_dir` 编码问题的同类坑，真实环境才暴露，属 mock 覆盖不到清单的"字符/编码"类）。

**三、对"未定事项"的测试视角意见**

1. **压缩保锚点方案**：倾向"结构化锚点"（摘要格式强制每条要点带日期字段，可断言）优于"纯提示词让 LLM 自觉保留"（不可断言）。方案定型时请带上"验收断言长什么样"。
2. **时区边界**：中国无夏令时，当前用户场景简单；云部署若在海外 VPS，UTC 存储 + 单测转换即可覆盖，不预埋复杂度。
3. **历史重灌时机**：**现在就是最佳时机**——刚实测 `backend/data/chroma` 的 `larry_memories` count = 0（用户尚未归档过记忆）。等有数据再重灌成本递增，支持 WB"现在埋"判断。
4. **便宜层派发**：支持现在做（见可测性分层）。

**四、测试侧衔接点（方案落地时我会同步改的）**

- `test_archive.py` 的 `confirm_and_store` payload 断言需加 `created_at` 字段检查（现有断言只查 text/memory_id）
- 归档 mock 摘要测试不受影响（prompt 加时间指令只影响真实 LLM 输入，mock 摘要固定返回）
- `get_current_time` 工具若实现，按 web_search 先例补：成功 / 降级 / schema 三件套
