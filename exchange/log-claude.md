#### 8.2b 漏洞清单（V1…V18 · 三件套：触发场景 ／ 严重度 ／ 修补建议）

**V1 · J1 负向臂按"行数"断言，与轮末摘要落行形状冲突**｜**堵洞**
- **触发**：实现按参考件形状 ④（`turn/end` → 轮末摘要；`lib/index.js:343` ＋ `:360-368`）落行 ⇒ 若"空转一轮"里真产生了 `turn/end`，库里会新增**不含 nonce 的摘要行** ⇒ 「库不得新增行」**误红**；反之实现方为让负向臂变绿，会悄悄砍掉轮末摘要 —— 两种结果都不是判据想要的。
- **修补**：负向臂改写成 ①「同装置**只建会话、不发 prompt**」＋ ②「发一条**不含对照 nonce** 的 prompt ⇒ 不得出现**带该 nonce** 的行」；若确要断言行数，须先在草稿写明本实现的落行策略（是否落轮末摘要）＋"行数"指哪张表。

**V2 · J1 正向：无"事件派生字段 ／ 库空基线"⇒ 非事件通道与残留都能通过**｜**加强**
- **触发**：把 nonce 送进库的路不止事件流一条（轮询 `session.jsonl`、读 `sessions` 服务、会话快照）⇒ 断言只认"文本进了库"，**不认"事件被消费"**；另若目标库／该 nonce 非全新，"查到含 nonce 的行"可由**残留**满足。
- **修补**：① 开跑前断言目标库为空（或该 nonce 不存在）；② 行内须带**事件派生字段**（参考件有现成形状：`sourceEventSeq`，`lib/index.js:2183`）并与该会话事件流里的 `user/message` seq 交叉核对 ⇒ 把断言从"文本进了库"升为"**该事件**被消费"。

**V3 · J2 哨兵红因不唯一（不可分红）＋ 哨兵落点未限临时 home**｜**堵洞**
- **触发**：`path` 指错后，「我们指定文件里没有 nonce」**同时**被"插件根本没工作／写都没写"满足 ⇒ 红因不可归（R3-b 的反面：路有了，但红因不唯一）。又：草稿写"指回 DSH 默认后端（session 落盘目录）"，**未限定该后端在临时 home 内** —— 照字面实现有落到真 home 的风险（与"不碰任何活库"冲突）。
- **修补**：哨兵臂加**阳性证据**（nonce **出现在哨兵位置**，或插件日志明示写入哨兵路径）；两臂共用同一 nonce／同一断言目标文件；哨兵路径写死为**临时 home 内**某目录；写明哨兵臂是**另一次跑**（同装置、换配置）。

**V4 · J3 embedding 来源无断言 ⇒ "不用 server 默认 embedding"被免费绕过**｜**堵洞**
- **触发**：客户端 `add({documents, metadatas})` 不传向量时，**chroma server 用它自带的默认 embedding**（英文 onnx）⇒ ①②③ **全绿**（count+1 ／ get 命中 ／ 同文本自检索必然 top-1），而 J3 的核心设计要求（我方 bge-small-zh 资产）**一个字也没验到**。⚠️ ③"以 nonce 原文自检索"本身近乎恒真（同文本 → 同向量 → cosine 1.0），判别力弱，**补不上**这个缺口。
- **修补**：加第四条断言 —— 取回存储向量并验**能力指纹**：维度 = **512**（bge-small-zh；默认函数为 384 维 MiniLM 级）；更强做法 = 与 `embed-probe` 同文本本地向量做余弦比对（`ts-embed.mjs:34,51,61,66`：`Xenova/bge-small-zh-v1.5` ＋ lowercase ＋ CLS ＋ L2；DSH-2.5 实测漂移 `2.2e-7` ⇒ 阈值按数量级给 0.9999）。这条同时把"③ 判别力弱"补成"真验到 embedding 那一跳"。

**V5 · J3 计量口径：基线／增量／id 来源／端口四件未写死**｜**加强**
- **触发**：① "count +1" 无基线读取；一条事件产多行（或产摘要行）时 `+1` 误红。② "按 id get" 的 **id 从哪来**未写（插件自生成 ⇒ 测试事先不知道）。③ `chroma run` **默认端口未钉** ⇒ 同端口若另有服务在跑，插件会连错 server（假绿或"写进别处"）。
- **修补**：写死"读基线 → 跑 → 增量 ≥1，且按 nonce 定位到目标条"；id 来源写明（建议 = SQLite 行 id，并顺带断言 **Chroma id ≡ SQLite 行 id** 这条双写关联）；起 server 时钉**临时端口**并两侧显式配置。

**V6 · J4 双锚自相矛盾 ＋ 日志哨兵未写死**｜**堵洞**
- **触发**：草稿写"双锚 = server 活着时 ①②③ **全绿**"，而 ③ = "日志有降级记录" —— **活臂不可能有降级** ⇒ 该臂无法按字面执行（执行方多半自行忽略 ⇒ 双锚实际只剩一侧）。又：③ 未写死"哪条日志通道／匹配什么串／是否只允许出自失败路径" ⇒ 启动期无条件打印一行 `chroma disabled` 也能满足。
- **修补**：活臂写成「①不阻塞 ②真相源在 ③**不得出现降级行**」（反向日志哨兵）；停臂 ③ 写死：通道（stderr 或插件日志文件）＋唯一匹配串（须含本次失败特征，如 URL/errno）＋只出自失败路径。

**V7 · J4 "不阻塞"无时间界 ⇒ 自动满足**｜**堵洞**
- **触发**：无 key 态下 turn **本就以 error 终局** ⇒ 「turn 正常走完到 error 态的终局」**恒真** —— 即便插件把 turn 拖到几十秒，只要最终终局就绿（判定条件与前提态同形的典型）。
- **修补**：给**数量级时间界**（终局时刻 − prompt 起跑 < X s，X 取同日**活臂同轮消耗**的同数量级；软阈值用数量级报警、不写精确区间）；或诚实收窄 —— 明写"本臂只覆盖 **connection-refused 快失败**，**不测 hung-server**"并列为边界。

**V8 · J4 ③ 的"产品口径依据"实为引申**｜**加强**
- **触发**：`product-positioning.md:182` 原文只有"ChromaDB 不可用时**静默降级**，不阻塞对话"，**没有"须留日志"字样**；草稿把"静默 = 不弹给用户、≠ 无日志"当**依据**引用 ⇒ 实现方去对产品文档会**对不上**，红线会被读成外挂要求。
