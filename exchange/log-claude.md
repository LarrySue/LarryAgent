### ① 唯一要回答的问题

**LarryAgent 必需的 DSH 能力中，是否存在无法经「公开挂载面」获得、必须修改 DSH 上游代码的部分？**

公开挂载面 = Cordis 插件 bundle / preset / `cordis.yml` / patches / 配置 / MCP 桥。

输出限定为三选一，**不接受模糊表述**：

1. **A 案成立** —— 全部必需能力可经公开挂载面获得 → 我们建独立仓库、产出 bundle 挂载
2. **A 案不成立** —— 至少一项必须改上游代码 → 须走 fork 主仓（B 案）或混合（C 案）
3. **无法判定** —— 必须写明**缺什么证据**才能判定

> 判不了就明说缺什么，**不要用"可能需要""大概率"搪塞**。

### ② 判定操作化阈值

待核清单（起点，不完备请自行增补；**你补的项要说明理由**）：

1. 记忆双写（会话结束事件 → 外部 SQLite + ChromaDB）
2. 角色机制（5 角色 system_prompt + persona）
3. 工具（shell / file_ops / web_search）
4. **2.7.2 边界透明**（高危工具审批的**回答侧** —— 即用户在前端批准/拒绝后如何回传给 agent；已知 SDK 协议面没有 answer 方法，须自做 TS answerer 插件）
5. 记忆保鲜 / 用户画像 / 知识库（均为自做插件）
6. compaction 策略定制
7. session 事件流消费（记忆双写的数据源）
8. 端侧执行器（Windows 沙箱，`ctx.sandbox`）

**逐项给出**：可达通道（公开挂载面 / MCP 桥 / 配置 / **需改上游**）+ 证据（`文件路径:行号`，**锁定版核实**）+ 等级 🟢/🟡/🔴。

**阈值**：只要有一项判「需改上游」且无替代方案 → **A 案不成立**；全部可达 → **A 案成立**。🔴 推断不得作为判定依据。

> 该阈值由 WB 设定。**若你认为口径不对，可直接推翻并给出替代口径 + 理由**——我要的是正确结论，不是执行我的框架。

### ③ 交付格式（分块，缺一不可）

1. **结论一行**：A 成立 / A 不成立 / 无法判定
2. **逐项表**：能力 | 可达通道 | 证据（文件:行号）| 等级 | 备注
3. **若 A 不成立**：需改的包 / 文件清单 + **为什么公开面做不到**（这一步是重点，别只给结论）
4. **可复跑步骤 + 原始输出片段**（关键命令与结果；无此条，结论降为 🔴）
5. **反向举证**：**至少尝试找一条能推翻你自己结论的证据**。例：若判 A 成立，就去找一项公开面做不到的能力；找到了要如实写。找不到也写明"找过哪些"。
