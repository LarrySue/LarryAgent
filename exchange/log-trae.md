### ⚠️ 三方并行：环境隔离（可验证）

老大点名三方**并行**独立执行（Trae / Claude / Qoder）。**顺位仅表示资源冲突时的让行次序，不是优先级、更不是串行**——三方同时开跑。

**统一根目录**：探针产物一律放在**项目外**的专属根下，每人一个子目录——
Trae `probe-trae/` · Claude `probe-claude/` · Qoder `probe-qoder/`。
venv、`DSH_HOME`、报告草稿、临时文件**全部**放自己子目录内，**不要放进仓库**（会污染 git；提交前 `git status` 自查）。

**为什么必须隔离**：`dsh plugin --profile sdk add` 会把持久 patch 写进 `$DSH_HOME/profiles/sdk/cordis.patch.yml`——三人共用同一 `DSH_HOME` 会**互相覆盖 patch，产出互相污染的结果**。这种污染的症状是「偶发失败」，极易被误判成「DSH 是 alpha 框架不稳定」——**而那正是本次要判定的对象**，等于拿被污染的数据去判定框架成色。

**四条隔离自检（跑之前做，输出贴进报告「环境事实」，缺一不可）**：

1. `DSH_HOME` 指向自己子目录（贴 `echo $DSH_HOME` 原始输出）
2. venv 是自己的（贴 `python -c "import sys;print(sys.prefix)"` 输出）
3. **系统 Node 已移出 PATH**（贴 `node -v` 的输出——**必须报错**，不报错等于没验）
4. MCP 探针端口是自己的（贴端口号）

**baseline 快照（把「隔离」从声明变成证据，必做）**：

- 开跑前：在自己的 `DSH_HOME` 内 `git init && git add -A && git commit -m baseline`
- 跑完后：`git status` / `git diff`，**把这个输出贴进报告**
- 两个作用：① 证明「我改的东西都在自己目录里」；② **检出被别人污染**——出现自己没做过的变更即隔离失效，**立刻停下报告，不要带着污染继续跑**

**唯一需要错峰的情形**：任何**必须动全局 / 默认 `DSH_HOME`** 的步骤（如验证不带覆盖时的默认行为），**先确认另外两方当前没在跑**。其余全部并行，不需要等谁。

**防锚定**：先各自独立跑完落盘报告，再交叉比对——**不要先看别人的报告再跑**（那样交叉验证就退化成附议）。交叉比对由 WB 做。

**冲突收口规则**：三方结论不一致时，**以「可复现的实证」为准，不以多数票为准**。故每份报告都必须给出**可复跑步骤 + 原始输出**；给不出的一方，其结论降为 🔴 不作判定依据。冲突项由 WB 复验（本地锁定版核 + 必要时复跑）。
