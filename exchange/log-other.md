### 判定操作化（WB 细化，见下；**你的任务之一正是审查它**）

**一等 = 下列四条全满足**：

1. **能力覆盖**：JSON-RPC 方法面相对 TS 侧**无实质缺口**（判据：31 子项任一必需能力在 Py 侧拿不到即为缺口）
2. **挂载通道**：B 三通道中 **B3 MCP 桥可行**，且 B1 / B2 至少一条可行
3. **官方支持度**：官方文档 / CI smoke / 发布同 train 三项中至少两项成立。**实测与文档冲突时以实测为准**
4. **可独立运行**：**在无系统 Node.js 的环境**完整跑通

**二等 = 任一条不满足。无法判定 = 证据不足以覆盖上述四条。**

### ⚠️ 两条执行硬约束（做不到就判「无法验证」，不要含糊过去）

1. **「无需系统 Node.js」必须真验**：验证时把 Node 从 PATH 移除（或临时改目录名），跑通后还原。**机器上装着 Node 就等于没验证这条**。
2. **禁用真实 API key**：跑 demo 需要的模型凭据**一律走环境变量**；**禁止**使用 `config.yaml` 里的真实 key，**禁止**出现在任何报告 / 日志 / 命令行回显 / git 提交中。用临时测试 key 或 mock；官方示例若支持 offline / mock 模式优先用它。

### ⚠️ 三方并行：环境隔离 + 独立执行（必读）

1. **各自独立 venv**（项目外，路径自定），不共用、不互相装包。
2. **各自独立 `DSH_HOME`（必做）**：`dsh plugin --profile sdk add` 会把持久 patch 写进 `$DSH_HOME/profiles/sdk/cordis.patch.yml`——**三人共用同一 `DSH_HOME` 会互相覆盖 patch，产出互相污染的结果**。用环境变量把 `DSH_HOME` 指到自己的目录，并在报告「环境事实」里写明路径。
3. **MCP 探针用不同端口**，避免端口占用导致假失败。
4. **先独立跑完、落盘报告，再交叉比对**——**不要先看别人的报告再跑**（那样就成了锚定，交叉验证失效）。交叉比对由 WB 做。
5. 只写自己的报告文件，不改他人报告、不改 `ref/dsh-bare`（只读）；提交前 `git status` 自查。
