> **定位**：本文件是 LarryAgent **产品能力层功能边界**的权威版本（README 仅存指针，定稿后本文件回 `docs/`）。文档采用**结论区 + 讨论区**两段式，用法见下方「迭代规则」。

> **当前轮次**：第 1 轮——WB 综合各方意见后建立结论区；**待各方对结论区表态「同意 / 有异议」**。

---

## 迭代规则（怎么用这份文档）

1. **结论区（上半）** = 待定稿的共识与决策，由 **WB 综合各方意见后维护**。
2. **讨论区（下半）** = 各方在各自区块下给意见（新增 / 修改 / 否决 / 补充）。
3. 每轮循环：各方在讨论区给意见 → WB 综合 → 更新结论区。
4. **定稿标准**：结论区各方均认可，且讨论区各方意见收束为「同意」。

### 2.3 二、记忆与知识

> 本域由单行升格而来（项目主线是「越来越懂你」的记忆闭环，一行装不下）。

#### 2.1 短期记忆 ✅

会话内消息历史，超长按 `llm.max_input_tokens` 截断旧消息（见 7.2 — 该机制本身是一致性问题的根源）。

#### 2.2 长期记忆闭环 ✅

- **提取**：`memory/archiver.py::generate_summary` — 归档时 LLM 生成摘要（`POST /api/memory/archive`）
- **人审**：`POST /api/memory/archive/confirm` → `confirm_and_store`，**确认（可编辑）后才入库**
- **双写**：SQLite 为真相源 + ChromaDB 向量库（可由 SQLite 重建）；Embedding 用本地 bge-small-zh
- **召回**：新对话按语义相似度检索（`memory/engine.py::get_long_term_memory`），拼进上下文
- **降级**：ChromaDB 不可用时静默降级，不阻塞对话

#### 2.3 记忆可管理 🚧

**已做**：`GET /api/memory` 列表可查；`DELETE /api/memory/{id}` 删除；`is_active` 停用。编辑发生在 confirm 入库前。

**承诺档位澄清**：当前档位 = **可看 / 可停用 / 可删 / 入库前可编辑**，**不含**入库后编辑与重归档。远期想法「记忆浏览器 / 可视化」（本条即其需求落点）未进 TODO。

#### 2.4 记忆保鲜与代谢 📐

**计划**（`TODO.md` 记忆系统调优段，长期、按使用体感调）
- 检索参数调优（`score_threshold` / `top_k` / 分级阈值）
- 相邻 chunk 合并（避免 LLM 看到被截断片段）
- **保鲜机制**：`last_hit_at` / `priority`，被频繁检索的记忆提升保留权重
- 向量同步补偿（ChromaDB 恢复后校验 SQLite ↔ Chroma 一致性并补写）
- Embedding 模型迁移脚本（重建 collection + 全量重索引，待触发）

#### 2.5 用户画像 📐

**计划**（`TODO.md` 多场景 AI 架构段，标「长期」）：从记忆中提炼结构化用户画像，注入 system prompt；落地手段含长期记忆按 `source_role` 加权（软隔离）。

> 层级：它是**记忆的衍生物**（TODO 原文即从记忆提炼），故为记忆域子项，不与长期记忆并列。

#### 2.6 知识库 🌱

**零承接**：TODO 无条目、`exchange/` 无讨论稿、无设计。

**老大 2026-09-06 裁定：知识库是必要的，非常必要**——当前仍无方案与排期，待立项。

与 2.2 的区别：长期记忆 = 对话自动沉淀（已实现）；知识库 = 用户主动导入的外部资料（RAG 同源、产品语义不同）。

### 2.4 三、能力扩展

#### 3.1 多模型按需切换 ✅

`config.yaml` 的 `models.<name>` 任意新增，`config.py` 自动解析，**加模型零代码**。当前为手动指定，无自动路由。

#### 3.2 工具挂载 ✅

**已做**
- 框架：`tools/base.py`（BaseTool 护栏基类：超时强制 / 错误归一 ToolError / 执行日志）+ `registry.py` 注册 + `config.yaml` `enabled_tools` 开关
- 已挂：`shell` / `file_ops` / `web_search`
- `web_search`：Brave provider（可插拔），2026-09-04 真机验收通过（成功路径 + 关梯子单边挂降级路径双实测）
- **范围边界（首版）**：`web_search` 只取搜索结果的标题 / 摘要 / URL，**不做 `web_fetch` 正文抓取**（代价高：SSRF / 反爬 / 内容清洗 / 阻塞风险，复杂度高一个量级）

**计划（未定案）**：`web-search-design.md` 有多 provider 按角色路由方案（Tavily / Brave / Wolfram）；当前共识是**先用 Brave 攒真实体感**，换 provider 因封装可插拔成本已封死。

#### 3.3 扩展性与零代码接入 ✅

- 加模型 → config 加段（3.1）
- 加工具 → 写类 + 登记（3.2）；第三方挂载契约已留接口
- 加角色 → config `roles` 段 + 重启，`GET /api/roles` 下发，**前端零改动**（2026-09-03 改造验证）

**未做**：以上定制目前只能改 `config.yaml`，无 UI 设置页（见 1.1）。

### 2.6 五、边界与约束

#### 5.1 行为安全硬护栏 ✅

- `file_ops`：工作目录 `file_ops_workspace` 限制读写范围；文件不覆盖
- `shell`：命令黑名单 + IP 白名单 `shell_allowed_ips`
- `web_search`：SSRF 内网拦截 + 硬性超时
- 工具调用轮次上限（防失控循环）

**已知弱点**（`TODO.md` 部署段原文）：ShellTool 黑名单为**字符串包含匹配、可穿透**，加固随「本地能力下沉」一并做（正则 / 词法解析或换沙箱）。

#### 5.2 边界透明与用户决策权 ✅

按 `HUMAN.md` 原则 4（明确安全边界，而非由系统替用户管控）：白名单 / 黑名单 / 工具开关**全部 config 可调**，边界交给用户决策；工具调用过程以 ToolCallCard 展示（见 6.2）。

#### 5.3 凭据与密钥边界 ✅

`config.yaml` 含真实 key 且不入库（`.gitignore` 保护）、`config.example.yaml` 占位符；测试默认占位符、涉 key 路径需显式 `--real-api`；异常统一出口不泄漏内部信息；临时目录用后清理。

#### 5.4 成本约束 🚧

**已做**：`token_counter` 统计 + `max_input_tokens` 截断 + 工具轮次上限。

**未做**：无预算 / 限额 / 告警。`TODO.md` 其他长期增强有「chat_service token 累计上限」，但老大标「优先级很低，不做主动处理」。

#### 5.5 数据主权与出境边界 📐

**计划**（`exchange/deployment-architecture.md` 草案 + `TODO.md` 部署段）
- 数据落云厂商磁盘；Embedding 在自有服务器跑；**LLM API 是唯一出境通道**
- 上云硬前置（不满足别上）：强随机 `server.api_key`（P3.4 校验已就绪）/ HTTPS（Nginx TLS 终止）/ 上云初期显式禁用 `shell` + `file_ops`（`enabled_tools: ["web_search"]`），防云端误操作云机器

#### 5.6 数据可恢复与可迁移 🚧

**已做（技术事实，未作产品承诺）**：SQLite 为真相源、ChromaDB 可重建 → 数据不绑架于向量库；会话与记忆均为软删除 + 回收站可恢复。

**未做**：整体备份 / 导出 / 迁移 — TODO 无条目。上云后这半边会从「无所谓」变成核心承诺。

### 2.9 八、形态与部署

#### 8.1 云端部署、多端使用 📐

**计划**：`exchange/deployment-architecture.md`（草案，待老大确认后派发）；`TODO.md` 部署段：Nginx 脚本示例 / 部署文档 + 安全加固 / 租 VPS 跑 backend + SQLite + 小模型。移动端段：响应式 UI 或独立 `mobile/index.html`、PWA（可选）。

形态：PC 版 C/S（client 在本机不上云，server 上云）；移动版 B/S（浏览器直连云端）。

#### 8.2 端侧能力保留（本地副作用工具在端上） 📐

**计划**（`TODO.md` 部署段，单独立项、不与云部署捆绑）：云端 backend 不注册 `shell` / `file_ops`，由本地执行器承接。下沉时一并完成 shell 鉴权重构（IP 白名单与公网不兼容，改 API Key 鉴权为主）+ 命令注入加固。

**产品理由**：这是本项目选 C/S 而非纯 B/S 的存在理由——本地文件与命令能力只有端侧有。多端时该能力如何降级，是产品差异点。

#### 8.3 单人单实例 ✅

形态事实（非能力）：不考虑多用户、并发、权限。这是决定无数设计的首要形态事实。
