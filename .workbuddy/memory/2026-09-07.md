### 08:35 本地 DSH 副本改用裸仓库（工作区 checkout 卡死 5.5 小时）

- **故障**：`ref/dsh/` 全量 clone（9,080 文件）后，`git checkout` 到锁定 tag **卡死 5.5 小时未完成**——残留数停在 2451、git 进程 24940 僵死、`index.lock` 持续被占用。反复杀进程重跑均复现；sparse-checkout 因 lock 未生效。根因 = Windows 写 9,080 个小文件被实时防护逐文件扫描 + git 维护 index，两个慢相乘。
- **解法（关键洞察）**：本副本定位是**只读参考**，只需 `ls-tree / show / grep / tag` **读 git 对象**，**根本不需要工作区文件**。改用裸仓库 `git clone --bare` → `ref/dsh-bare/`，**零工作区写入，44 秒完成**，直读能力完全等价（实测验证：50 个包 / identity 语义 / AGENTS.md 无 cloud 全部通过）。
- **需要实体文件时**：`git -C ref/dsh-bare --work-tree=ref/dsh-wt checkout <tag> -- packages/<包>` 按需**局部**检出，绝不整体 checkout。
- **环境坑（新增）**：①本机 **safe-delete 拦截** `rm` / `os.remove`，且 **bulk delete guard 拦批量删除**（9,080 文件）→ **必须老大手工删**；②`robocopy` 在此 PowerShell 环境不可用（CommandNotFound）；③`os.replace` 移 lock 也失败（文件被占用）。
- **文档同步**：§2.2 重写为裸仓库查阅指南（命令加 `-C ref/dsh-bare`）+ 新增「按需局部检出」+ 第 4 条坑「Windows 下勿做整体 checkout」；全文 7 处 `ref/dsh/` → `ref/dsh-bare/`；删「本地分支 `pin/0.1.2-rc.1`」说法（裸仓库无工作区）；§4 变更记录补一行。
- **遗留**：旧目录 `ref/dsh/`（231 MB）仍在，需老大手工在资源管理器删除（AI 被批量删除保护拦截）。
- **教训（高复用）**：**Windows + 大仓库 + git checkout = 卡死风险**；参考型副本一律用 `--bare` clone。**判断"要不要工作区"的标准是"是否需要写文件"**——只读场景裸仓库完胜（44 秒 vs 5.5 小时卡死）。

## 老大拍板硬约束 §3.0「第三方引入原则」——只借鉴、不直装

- **老大立论**：现象级爆发的插件生态必然伴随大量跟风项目无人持续维护；关键能力不能押在外部作者不可控的维护意愿上。**即使企业级维护的插件也不直接纳入**，倾向 fork 后自改造或参考代码自己实现。
- **落地为 `exchange/dsh-migration.md` §3.0（置于 §3 开头，声明优先于本节其余结论）**：允许 ①读源码借鉴设计 ②fork 后自改并纳入（代码进本仓库、维护责任归我们、须过本项目 review/测试/命名）③隔离环境临时装跑 prototype（不进产品依赖）；**禁止** `dsh plugin add` 后作为产品依赖。
- **边界（WB 主动补，防误伤）**：本原则针对**插件 / 第三方扩展**；**DSH 底座本体是框架依赖不是插件**，兜底是 MIT + TS 可 fork 自维护——"依赖可接手的底座" vs "依赖不可控的插件"，风险性质不同，A 路径不受影响。
- **连带修正**：§3.3 三项降级口径「选型+适配」→**「借鉴自实现」**（省设计试错，不省实现与维护）；§3.4 三行改写（质量参差→只借鉴不直装 / 版本漂移→**对运行时不成立**，仅影响参考时效 / 第三方安全→大幅下降）；§3.5 A 的"插件生态红利"重述为**设计红利**；§3.7 选型调研改**借鉴调研**（删"作者维护活跃度"维度）+ 新增「fork 代码纳入规范」「§3.0 是否升格项目级原则」待办；§2 插件生态行加用法约束注记；§4/§5.4 补记录。
- **待老大定**：借鉴/fork 代码进库位置与 license 标注格式；§3.0 是否升格到 `docs/ai-governance.md`。

## 假设检验：按 watch / fork 反推等效 star（commit 8aabdb5）
