## 三轮 · 手动 `/compact` 保留语义：三前置事实 ＋ 三选项（老大问「详细说明」时实读产出）

（⚠️ **本节取代**上文〈第 5 件 · 产品决策〉的二选一表述 —— 原登记不完整，会让选项代价判错，已回填三处。）

**问题**：官方 compaction 两条路径的「近文保留」语义不同 —— **自动**保留尾部 **16%**（`retainRatio`），**手动 `/compact`** 只保留**最后 1 个节点**。

**三条前置事实（本轮新增实读 · 🟢 `dsh-v0.1.5-rc.2`）**：
1. **配置面改不动** —— `compactNow` 直接传字面量 `0`（`compaction-basic/src/index.ts:380-384`），**全程不读 `policy` / `spec`** ⇒ `retainRatio` / `retainTokens` **只作用于自动路径**（`:317`）。
2. **`0` ≠ 留 0 条** —— `region.ts:116-154` 语义 = 从尾部**倒序累计 token 到 ≥ 参数即停** ⇒ 保留区 = **最后 1 个节点**，再经 `toolPairingBalancedBefore` **向前吸附到 tool-call / result 配对安全边界**（可能多留几条）。
3. **官方默认组合自带 `/compact`** —— `command-compact` 在 `packages/bundle/base/cordis.patch.yml:325` **启用**（注释："one useful reduction **below the automatic threshold**"）；`bundle/web-app:430` 置 `disabled: true`，但 cordis / ptc / standard **三个 preset 均提供** ⇒ **两条默认链路都会给用户此入口**。

**三选项（替代原二选一）**：**A 不做手动入口**（不装 / 禁用 `command-compact` ⇒ 决策**消解**，判据注明手动路径不适用）／ **B 做且接受官方语义**（手压后近文近乎清零，只剩摘要 ＋ 最后 1 条）／ **C 做且自做 Provider**（子类覆写 `compactNow`，把 `0` 换成配置算出的保留量）⇒ ⭐ **C 即「换 Provider」第一个实际靶子**。

**低成本验证**：**L1 档本就是「手动 `/compact`」** ⇒ 该档顺带断言「保留几个节点 / 多少 token」，即可把本条从**源码推断**升为**实测**（零额外成本）。

**方法论（可复用）**：**「给老大摆选项」前必须先把改变各选项代价的事实查全** —— 原登记只写「硬编码只留 1 条」，漏了「**配置改不动**」与「**默认组合自带**」两条 ⇒ 会让「要不要做这个入口」这个**前置问题根本不出现**，选项被误读成「改不改一行」而非「要不要提供功能」。
