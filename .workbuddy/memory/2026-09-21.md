**验靶手段（本轮最有价值的发现）**：`dsh --profile sdk --dump-config` —— **组合配置树后退出、不激活插件**。
- 输出按 `# == <来源>` 分组；**被 patch 命中的条目，来源注释追记 `, patched by <层文件>`**；**未命中的 patch 打一行** `dsh: [<层>] patch: entry "<id>" not found`。⇒ 「改动命中没有」有**机械可读判据**。
- ⚠️ 该警告路径**仍 exit 0** ⇒ 又一次印证「退出码 0 不能当判据」（既有纪律的又一实例）。
- ⭐ **`--patch <临时层.yml>`（可重复、叠加在 profile 层之后）= 零副作用试验通道** —— **不改场地文件就能试 patch 写法**。本轮五组实验全走此通道。

**五条结论（路 A 机制成立）**：
1. `- id: sdk-jsonrpc-server` ＋ `disabled: true` **确实禁掉了这条由上游 `insert` 进来的行**（来源注释变 `@deepseek-ai/dsh-sdk-app, patched by <层>`）⇒ **补齐 3.7.2 未覆盖的情形**（3.7.2 禁的是 bundle 层直接声明的行，不是 insert 进来的行）。
2. **字段级浅合并**：只写 `disabled` 时，目标条目的 `name` ／ `inject` ／ `config` **全部保留** ⇒ **不必重述 config**。⚠️ README〈已知限制〉"用户 patch 会替换匹配到的整个配置"**仅在提供了 `config` 键时**成立 ⇒ 照字面推广会造出**假风险**（"disable 时必须抄一遍原 config"）。
3. 同层内 `disabled` 与 `insert` **共存成立**，insert 行的 `inject` 原样保留。
4. `insert` 的新条目**一律落在整个条目列表末尾**（所有层之后）⇒ 控制不了插入位置。
5. insert 出来的条目 **id 会被注册**，可被更后的 `--patch` 层用 id 定位（注释形如 `# == <层1>, patched by <层2>`，无警告）⇒ 多段叠加可行。

### 方法论增量（2026-09-21 下午）

1. **「能不能用」可在"不激活"的前提下验出来** —— 产物若是**配置层**（patch 命中／禁用／插入位置／字段合并语义），用**配置预览**即可端到端验，不必真 boot。代价从"起进程＋可能真跑模型"降到"读一遍配置"。
2. **overlay 式临时层是天然的"无副作用试验通道"** —— 凡框架支持"叠加一层临时配置"（DSH 的 `--patch`、其他工具的 `--config-extra` 之类），**优先用它做实验**，把场地文件改动留到确认之后。
3. **文档的限制说明要按"触发条件"读，别按字面推广** —— README 说"patch 会替换匹配到的整个配置"，实测只在**提供该键**时成立。**照字面推广 ⇒ 写出一个不存在的要求（假风险）**，会让执行人白抄一遍配置。
4. **`**` 数偶抓不到嵌套** —— `**A**B**C**` 也是偶数、也平衡，但渲染错乱。**"加粗奇偶"这个格式自检口径存在盲区**（我一直在用）；插入含加粗的内容后须另检「加粗块内部再出现 `**`」。本轮实际踩到一次（自己引入，已修）。
5. **判"未命中"必须有一个"必中的对照组"** —— 本轮特意用不存在的 id 跑出那行 `not found` 警告，才敢说"没警告 ＝ 命中"。否则「没输出」与「输出了我没看」不可分。（与既有「无输出 ≠ 失败」同族，方向是"无输出 ≠ 无事发生"。）
