### 本轮方法论增量（可复用）
1. ⭐ **「装置自判」与「回报引文」是两个独立面** —— 装置 `summary.json` 报"判据成立"只说明**装置的判据**过了；**引文是否等于原件是另一件事**。⇒ 复验凡遇"原文，逐字"字样，**必须做字段级比对**（写脚本解析两个来源再逐 key 比），不靠肉眼、不靠字节数。
2. ⭐ **判据的"用例名"可能把机制钉错主体** —— 规格（`dsh-migration.md:758/804`）写的是中性的「超时」，TODO `:158` 写成「**answerer 超时**」，而实测证明**答者侧不存在超时计时器**（唯一"放下"机制 = 请求侧 `AbortSignal` 撤回）。⇒ 用例名会**指定执行人去验一个不存在的机制**；订正时以"规格措辞 + 实测机制"双依据为准。
3. ⭐ **装置只"采集"、无 `judge()` 断言的判据 = 人工判读** —— 本轮 J3 五条用例的期望值**没有写进装置**（runner 只 `saveJson('J3-cases.json')`）⇒ **复验方必须自力比对期望表**，别以为"装置全绿"就覆盖了 J3。
4. ⭐ **写 CRLF 文件时，Python 字符串里用 `\n` 会引入 bare LF** —— 本轮在 TODO.md（CRLF）追加多行内容即中招（写后 `bareLF=1`）。⇒ 多行改动**按目标文件 EOL 拼**（或写后规范化 + `assert` 只修 N 处）。
5. **装置把 marker 从 JSONL 重排成 pretty 是 runner 自身行为**（`run-33a-answerer-e2e.mjs:60` 的 `JSON.stringify(v,null,2)`）⇒ 磁盘件**不是装置原始字节**；判"引文是否逐字"时基准仍是 runner 落盘件（同源可复跑），但知悉这一层。
6. **smoke 的「零配置路径」满分级写法**（可作范式）：临时 `process.env.DSH_HOME = mkdtemp` ＋ `finally` 还原 ＋ 把"缺省跟随该变量"**钉成断言** ＋ 末尾 `rmSync` —— 我复跑后真实 home 实测无污染。
