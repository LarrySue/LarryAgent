### 重大根因发现（推翻原修复范围，价值高）
- **42 个失败里 33 个与 pytest-asyncio 无关**，是**跨文件事件循环污染**：FastAPI `TestClient`（`test_conversations` / `test_chat_service` 在用）退出时销毁当前线程事件循环，后续 sync 测试调 `asyncio.get_event_loop()` → `RuntimeError: There is no current event loop in thread 'MainThread'`（`asyncio/events.py:681`）。
- **二分实证（方法论可复用）**：`test_file_ops_tool.py` 单跑 **20/20 绿**；`test_archive`+file_ops **31 全绿**；`test_chromadb_degradation`+file_ops 仅 chromadb 自身 1 failed；而 `test_conversations`+file_ops 或 `test_chat_service`+file_ops → **19 failed**。→ 污染源锁定为用 TestClient 的两个文件。
- **含义**：升级依赖大概率一个都修不掉这 33 个（原以为"装 pytest-asyncio 能解决存量债务"是误判）。若低成本修好（autouse fixture 重置事件循环 / 测试内改 `asyncio.run()`），基线可从 **113p/42f → 约 146p/9f**（真失败仅剩 integration 3 + chromadb 6 + test_windows_dir 1 = 10 个）。
- **基线（2026-08-30 01:47 WB 实测，供验收对比）**：`42 failed / 113 passed`。
- **方法论沉淀**：判断"测试失败是依赖缺失还是测试间污染"，**最省事的判据 = 单跑 vs 全套跑对比**。单跑绿、全套红 = 污染，与依赖无关；单跑也红 = 真失败。二分时按字母序逐个前置文件组合即可定位。

## 巨大 BUG：aiosqlite 连接生命周期缺陷（老大授权真实 key 后暴露，WB 复验 + 归档）
- **背景**：Claude 交付集成测试层恢复（commit `0e8d52a`），mock 层自测 2f/150p/3s 判断"没问题"；老大授权真实 key 跑 `--real-api` → 暴露 BUG。排查约 1.5h，表层已修（`f27c091`），**根因的机制级影响面 + Tier0 配套隐患未闭环**。
- **根因（一句话）**：`aiosqlite` 连接绑定到已关闭的 asyncio loop 后，**进程退出时 GC 清理必然挂起**。
- **三层影响**：
  1. **表层（已修）**：`--real-api` 进程退出挂起 **17.5 分钟**、退出码 1，而 pytest 报 "3 passed"（欺骗性极强）。直接触发 = 去假绿改造时删了原脚本式的 `close_db()`，`handle_chat` 建的 `_db` 泄漏。修复 = module 级 autouse fixture teardown 显式 `asyncio.run(close_db())`；wall clock 18min → 26s。
  2. **中层（未防护，机制级）**：独立实验 G1/G2（纯 Python 无 pytest）与 F3/F4（pytest 环境）双环境互证 → **与 pytest 无关的 aiosqlite+asyncio 通用行为**。WB 核查：全项目 `close_db()` 调用点**仅 `main.py:73-74`（lifespan）一处**，uvicorn 常驻安全，但**一次性脚本/CLI 入口无防护、无机制阻止未来踩坑**。
  3. **深层（未闭环，Tier0）**：`conftest.py:64` 用 `atexit.register(shutil.rmtree, ..., ignore_errors=True)` 清理含**真实 key 明文副本**的临时 yaml。两缺陷：①强杀不执行 → 本次排查残留 **40+ 个含 key 目录**（Claude 已清）②`ignore_errors=True` **静默吞失败**。WB 复验：正常退出跑完仍残留 1 个目录（仅 chroma.sqlite3，key 已删）→ **"侥幸正确"而非"机制正确"**。
- **WB 独立复验证据**：全套 **2f/150p/3s、42.72s 正常退出**（对比修复前 18 分钟，修复有效）；剩余 2 failed 为独立存量（chromadb mock 了已不存在的 `archiver.get_db` + windows_dir 中文编码）。基线演进 42f/113p → 2f/150p/3s。
- **产出**：`archive/report-2026-08-30.md`（冷存归档，参照 8-16 report 格式）——含三层影响表、双环境实验、产品暴露面、WB 复验表、3 条待办（清理机制硬化 / key 落盘源头消除 / 产品侧 atexit 兜底，均属最小动作，待老大拍板）。
- **方法论价值**：mock 层永远测不出这类 BUG——连接生命周期（mock 不建真实连接）、GC 退出挂起（属退出期行为，断言够不到）、资源泄漏累积（单用例短跑看不出）。这正是"集成冒烟层"存在的理由。
- **教训**：排查此类问题"二分 + 最小复现 + **wall clock 打点（日志落文件非管道）**"比体感可靠；Windows 下 TaskStop 只杀外层 shell 不杀 python 子进程树，后台 pytest 需 `taskkill /T`。
