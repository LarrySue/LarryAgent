**老大的问题**：早期讨论过"LarryAgent 与多 AI 协作是同构的"，现在又觉得这个判断正确，因为"项目可能需要一个项目知识库"。

**WB 判断（本轮产出，供后续引用）**：

1. **同构可逐格对齐，不是隐喻**：产品层 6 项记忆机制 ↔ 协作层 6 项**已存在**的机制（长期记忆↔exchange/log-*、知识库↔docs/、会话沙盒↔per-AI 区域、保鲜失效↔archive/+阶段清理、用户画像↔各 AI 私有记忆、检索召回↔README 索引+grep）

2. **同构 ≠ 同解**（本论核心）：问题结构相同，**约束条件不同** ⇒ 不能把 2.4.6 的 RAG 方案平移过来
   - 消费者：人类用户 ↔ AI（天然有 grep/Glob/Read）
   - 语料：非结构化外部资料 ↔ 已分区 + 有索引 + git 版本化的 md
   - 检索：语义检索必需 ↔ 索引 + grep 够用
   - 失效：需专门设计（2.4.4 难题）↔ docs→exchange→archive 已实现

3. **真缺口三条**（不是"存取"，是"发现"）：
   - ① 入口不唯一：知识散在 4 个 README + 根 README + TODO + 各 AI 私有记忆
   - ② **发现靠关键词运气**：本轮实例——找"同构讨论"是 grep"同构"才命中的，藏在 289 行文档的第 158 行
   - ③ 决策追溯靠手工块：「决策账本」表、「附·各方看法（决策追溯，原文保留）」都是**人手搭的反查索引** ⇒ 需求真实但机制手工
   - ⇒ ②是唯一必须语义检索才能解的，也恰是 2.4.6 的题

4. **⚠️ 须暴露的矛盾**：同一需求，两层裁定强度相反
   - 产品层 2.4.6 知识库 = **"必要，非常必要"**（老大裁定原话，`product-positioning.md` L172）
   - 协作层 = **"够用就好 + 人类兜底，机制只保留低成本高收益的"**（老大 08-17 收口，且明确批过自己"过度追求机制完善"）
   - ⇒ **不能把产品层强度平移到外部层**；且若外部"够用就好"即够，它也就不能反过来为产品层的"非常必要"提供支持证据（强度不同源）

5. **更值钱的定位**：外部若真做，它是 2.4.6 的**第 0 号用户 / 试验场**
   - 2.4.6 当前"无方案、无排期、待立项"；而外部这层**需求真实、语料现成、消费者可见、失败可观测**
   - ⚠️ 但这条有**两难**，须老大拍：试验场 = 外部要按产品标准做事，**与"外部够用就好"直接冲突**
