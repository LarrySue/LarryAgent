### 一、凭据机制（权威源：`dsh-credentials-local/README.zh.md`，本机已装包）

**DSH 的模型 key 不走 `config.yaml`，走独立的 credentials seam。四层来源，先有值者胜出：**

| 优先级 | 位置 | 可写 | 备注 |
|---|---|---|---|
| 1（最高） | 启动环境 `DEEPSEEK_API_KEY=… dsh` | 否（只读，写入被拒） | 环境层是**启动时拍摄的快照**，启动后 export 看不到 |
| 2 | 受管存储文件 `$DSH_HOME/.credentials.yaml` 的 `refs:` | 是（GUI 或手编） | 手编**自动热重载**；写入保留注释与排版，同刻并发修改会被并入而非覆盖 |
| 3 | 项目 `.env`（`<invocation cwd>/.env`） | 不在此处（只读后备） | 优先于第 4 层 |
| 4 | 主目录 `.env`（`$DSH_HOME/.env`） | 不在此处 | 无 |

- **模型适配器**：`dsh-llm-deepseek` 的 `apiKeyEnv` 默认 `DEEPSEEK_API_KEY`，"先经凭据 seam，再到环境变量"，**按请求解析**（换 key 无需重启）；`baseURL` 默认 `https://api.deepseek.com`，`$DEEPSEEK_BASE_URL` 优先。
- **无 CLI 子命令**：全仓搜 `credentials set|unset|…` 零命中 → 只能用配置界面或直接编辑文件。
- **存储文件格式**：`version:` / `refs:`（按环境变量名存值）/ `records:`（按 `<owner>/<id>` 存插件凭据）。**只放凭据**——非 mapping 根、未知顶层键、空值、类型错、重复键、YAML 错一律**启动时失败**；运行期热重载失败则保留最后可用快照 + 告警。
- ⚠️ **POSIX 强制权限**：产品会**拒绝加载任何"其他用户可读"的文件**（报错提示 `chmod 600`）；Windows 无 mode 可查故跳过。→ **CVM 是 Linux，scp 上去若为 644，DSH 启动会直接失败**（部署必踩）。
- ⚠️ **agent 可读（官方原话）**："agent 不是另一个用户：它的工具进程以你的身份运行，因此它们读这个文件与读你拥有的任何其他文件毫无二致。产品绝不把文件路径交给 agent，也绝不把文件载入环境……**这是审慎，不是边界**：必须让提供方密钥远离自身 agent 的部署**无法靠文件权限做到**。" → 对本项目形态有直接含义：DSH runtime 带 file_ops/shell 工具，**key 对它天然可读**。

### 六、环境坑（当场踩到）

- **Windows 原生 Python 不认 MSYS 风格路径**：`open('/c/Users/...')` → `No such file or directory`（Git Bash 的 `find`/`ls` 认，Python 不认）。⇒ 用 `C:/Users/...` 正斜杠盘符形式，或先 `cd` 再用相对路径。
