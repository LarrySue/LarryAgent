### 一、凭据机制（权威源：`dsh-credentials-local/README.zh.md`，本机已装包）

**DSH 的模型 key 不走 `config.yaml`，走独立的 credentials seam。四层来源，先有值者胜出：**

| 优先级 | 位置 | 可写 | 备注 |
|---|---|---|---|
| 1（最高） | 启动环境 `DEEPSEEK_API_KEY=… dsh` | 否（只读，写入被拒） | 环境层是**启动时拍摄的快照**，启动后 export 看不到 |
| 2 | 受管存储文件 `$DSH_HOME/.credentials.yaml` 的 `refs:` | 是（GUI 或手编） | 手编**自动热重载**；写入保留注释与排版，同刻并发修改会被并入而非覆盖 |
| 3 | 项目 `.env`（`<invocation cwd>/.env`） | 不在此处（只读后备） | 优先于第 4 层 |
| 4 | 主目录 `.env`（`$DSH_HOME/.env`） | 不在此处 | 无 |

- **模型适配器**：`dsh-llm-deepseek` 的 `apiKeyEnv` 默认 `DEEPSEEK_API_KEY`，"先经凭据 seam，再到环境变量"，**按请求解析**（换 key 无需重启）；`baseURL` 默认 `https://api.deepseek.com`，`$DEEPSEEK_BASE_URL` 优先。
- **无 CLI 子命令**：全仓搜 `credentials set|unset|…` 零命中 → 只能用配置界面或直接编辑文件。
- **存储文件格式**：`version:` / `refs:`（按环境变量名存值）/ `records:`（按 `<owner>/<id>` 存插件凭据）。**只放凭据**——非 mapping 根、未知顶层键、空值、类型错、重复键、YAML 错一律**启动时失败**；运行期热重载失败则保留最后可用快照 + 告警。
- ⚠️ **POSIX 强制权限**：产品会**拒绝加载任何"其他用户可读"的文件**（报错提示 `chmod 600`）；Windows 无 mode 可查故跳过。→ **CVM 是 Linux，scp 上去若为 644，DSH 启动会直接失败**（部署必踩）。
- ⚠️ **agent 可读（官方原话）**："agent 不是另一个用户：它的工具进程以你的身份运行，因此它们读这个文件与读你拥有的任何其他文件毫无二致。产品绝不把文件路径交给 agent，也绝不把文件载入环境……**这是审慎，不是边界**：必须让提供方密钥远离自身 agent 的部署**无法靠文件权限做到**。" → 对本项目形态有直接含义：DSH runtime 带 file_ops/shell 工具，**key 对它天然可读**。

3. 🟡 **两处待实测**：① WSL 的 PID 1 独占 seccomp USER_NOTIF（DSH 若走 seccomp 退路会 EBUSY；走 landlock 则无碍）；② systemd 默认关闭。

### B. Docker 判否 + 收口候选（`test-env.md` §8.4.1，⬛ 未拍板）

- **✗ 在 WSL 内加 Docker —— 不解决，因为位置错**：逃逸发生在「宿主进程 spawn `wsl.exe`」这条边界上，写入由 **WSL 侧内核 / 9p 服务**代劳、**不经工具进程树** ⇒ 在 WSL 里再套一层容器，是**在被突破通道的内侧加围栏**：AI 照样能 `docker run -v /mnt/c:…` 把 Windows 盘挂回容器，且容器仍得挂 `/mnt` 才读得到仓库。**Docker 隔离的是"容器内工作负载"，不是"AI 通道"。** 另会给 landlock 判定引入 seccomp / mount ns 干扰层。
- **候选甲**：`/etc/wsl.conf` → `[automount] enabled = false`（最彻底；WSL 内需自带仓库副本，与 §10 已倾向的 `~/work/LarryAgent` 一致；可按需 `mount -t drvfs C: /mnt/c -o ro`）
- **候选乙**：`[automount] options = "ro"`（一行、**杀写留读**；⬛ 该选项是否被当前 WSL 接受未实测）
- **候选丙**：不做（单用户单机 + 需 AI 主动执行 + ACL 仍拦系统路径；与 HUMAN 原则 4「明确边界而非控制」一致）——**我倾向先补归因对照，再定甲乙丙**
- 约束：`/etc/wsl.conf` 全 WSL 共享、改动须 `wsl --shutdown` 生效 ⇒ **须老大拍板后由执行人实测**；`\\wsl.localhost\` 是反方向、**不受 automount 影响**（WB 复验通道不会断）

## 十四、WSL 出网判定 + 只读通道能力边界（17:37 起，老大问「是否交给其他人测试比较好」）

**老大问题**：WSL 出网的补测，是不是交给其他人做比较好？

**答**：不是「比较好」，是**结构决定的唯一路径** —— `wsl.exe` 在 WorkBuddy **程序黑名单**内 ⇒ **执行侧够不着**（`test-env.md` §8.2 已定：Claude 主 / Trae 次 / WB 只读复验）。但必须分清三件事：

1. **执行** —— 只能外包（硬约束，非偏好）
2. **口径** —— 必须留 WB。否则回来的是一份没有判据的报告，无法验收（对照本轮 CVM 出网测试的现成模板：目标清单 + 三类判定 + 采数项）
3. **配置面事实** —— ⭐ **WB 现在就能做**（本轮已实证）

### A. 只读通道能力边界（本轮实测，已落 `test-env.md` §8.2）

- 🟢 **可读系统配置面**：`/etc/*.conf`、`/etc/hosts`、`/etc/environment`、`/mnt/wsl/*`；可 listdir / stat / 读内容
- ❌ **不可读**：`/proc/*`（独立挂载，不经 9p 导出）⇒ **路由表 / 网卡地址等运行时事实取不到**
- ⇒ **取证划线**：**静态配置事实** WB 可独立取证 + 交叉复验；**运行时实测事实**只能由执行通道跑、WB 只读回产出
- ⇒ **推论：「配置面」不必派发** —— 别为一台已知配置的机器开一轮执行

### B. 顺手完成的独立复验（`test-env.md` §7「镜像非 NAT」）

- 证据：`/mnt/wsl/resolv.conf` → DNS = **`192.168.1.1`（宿主 LAN 网关）** + 电信 IPv6 两条
- 判据：NAT 模式下 DNS 会指向 WSL 虚拟网关（`10.255.255.254` 一类）⇒ **「镜像非 NAT」成立**
- ⭐ **价值在证据类型不同**：原结论出自两通道**执行**（`ip` 命令），本次出自**静态配置读取** ⇒ 这是**交叉复验**，不是重复发现
- 附带：`/etc/resolv.conf` 是**符号链接**（真身 `/mnt/wsl/resolv.conf`）—— Windows 侧 `listdir` 可见、`stat` 不到，**别误判为「文件不存在」**

### C. 「WSL 出网口径 = 宿主出网口径」（推论，已落 §7）

- 因镜像形态：DNS / 网关 / 网卡**全跟宿主** ⇒ **宿主开不开梯子，决定 WSL 能不能下境外**
- 实测宿主本地代理端口（`7890/7891/7897/1080/10809/10808/8080/8118/8889`）**全未监听** ⇒ 当时口径 = 宿主裸出网
- ⬛ **两个不许外推的点**：① 镜像模式下 `127.0.0.1` 与宿主共享 ⇒「WSL 可直接复用宿主代理」属**待验推论**（未实测）；② **TUN / 系统代理形态不能由端口探测排除**（端口全闭 ≠ 无代理）

### D. ⚠️ 工具层实证：同一文件的多个 Edit **并行会互相覆盖**（本轮静默丢 2 处编辑）

- 现象：同一条消息发 3 个 Edit 改**同一文件**（`test-env.md` §7 / §8.2 / §8.4）⇒ 三个都返回 "Successfully edited"，但 **只有最后写入的那处活下来**（`git diff --stat` 只显示 4 行，另两处无声消失）
- 成因：Edit 是 read-modify-write，并行时各自基于**同一初始快照**写回 ⇒ 后来者覆盖先到者（**工具层竞争，不是文件被外部改动**）
- ⇒ **纪律：同一文件的多个 Edit 一律串行（发一个、等返回、再发下一个）；不同文件才可并行**
- ⚠️ 与 §D「两次 Edit not found」是**两个不同现象**，勿混：那是「**匹配不到**」，这是「**匹配到了但被覆盖**」
