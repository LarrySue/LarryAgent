### 老大澄清顺位本意 → 隔离方案升级为可验证（commit 19e29b3）

- **老大澄清**：点名顺序**不是优先级、也不是串行本意**，"只是觉得让他们分开执行可能能回避一定程度上的污染或者操作冲突"。→ 顺位重定义为「**资源冲突时的让行次序**」，三方并行不变；在 §3.7 与议题栈里记了顺位由来（防后人误读为串行）。
- **原方案的缺陷（WB 自查发现）**：隔离只写了"各自独立 venv / DSH_HOME / 端口"，是**声明式要求**——我无法从报告反查他们是否真做到了。声明 ≠ 证据。
- **升级四项**：
  1. **统一根目录**（替代"路径自定"）：项目外 `probe-trae/` `probe-claude/` `probe-qoder/`。理由：路径自定**易被建进仓库污染 git**；约定根目录还能一眼分清归属、结束时整目录可删不留残渣。
  2. **四条隔离自检**，输出贴进报告「环境事实」：`DSH_HOME` / venv prefix / `node -v`（**必须报错**）/ MCP 端口。**缺则视为不可复现**。
  3. **baseline 快照（关键）**：开跑前在自己 `DSH_HOME` 内 `git init && commit -m baseline`，跑完贴 `git status`/`diff`。两个作用——证明改动都在自己目录；**检出被别人污染**（出现自己没做过的变更 = 隔离失效，立刻停手报告）。**这是把"隔离"从"我要求你做"变成"我能看见你做了"的关键一步。**
  4. **唯一需错峰的情形**：必须动全局 / 默认 `DSH_HOME` 的步骤，先确认另两方没在跑；其余全并行。
- **方法论（可复用）**：给多个执行方下"隔离"要求时，**必须同时给可验证手段**（自检输出 + baseline diff），否则隔离是无效要求——**我看不见就没法复验**，而不可复验的要求等于没有。
- **⚠️ 又犯一次老错误（自用，已第三次）**：用 `python -c "...."` 且内部含反引号 → bash 在双引号内仍执行命令替换，`probe-trae/` 等被当命令执行、内容静默丢失 2 行。**这次是"只转义了部分反引号"**——看起来对，漏一个就丢内容，比完全不转义更难发现。**硬规则：含反引号的代码一律写成 .py 文件再跑，不做部分转义。**
