# completion-claim-audit

## 触发条件
- 老大指出「只说要记／说做了实际没做」类问题。
- 或需要自查某段时间的完成类断言是否都有工具调用支撑（例如每次事故后、月度自查）。

## 可复跑命令
```bash
cd <skill 目录>
PYTHONIOENCODING=utf-8 python -I audit_claims.py > hits.txt 2>&1
grep -c "n=0" hits.txt          # 命中数
```
脚本默认扫 `C:/Users/SuLarry/.claude/projects/d--Code-LarryAgent/*.jsonl`；
换项目改脚本顶部 `ROOT`。

## 判据（怎么从命中里筛真问题）
1. 先看 **n=0**（本轮没有工具调用）的完成类句——高信号。
2. 逐句判「是不是第一人称完成断言」：转述别人、引用文档、计划句（「我这就去」「稍后」）不算。
3. 抽查 n>0 的：工具调用可能失败或做的是别的事，别只看有没有调用。
4. **正向对照**：必须能从命中里抓到已知实例（例：2026-10-23 黑板「补了一笔」→ `eee595b2` L137，n=0）。抓不到 = 判据失效，先修脚本再下结论。
5. 交叉取证：再用老大抓包的措辞反查用户消息（「没看到／不是说／怎么没／又只／卡了」），两边对上才算实锤。

## 已知坑
- **`tool_result` 在转录里也是 `type: user`**：若按 user 重置「本轮工具调用」，会造成全量假阴性（第一次跑就栽在这里）。脚本已用 `is_real_user_input()` 处理。
- **中文输出在 Windows 控制台会 GBK 乱码/报错**：必须 `PYTHONIOENCODING=utf-8` 且 `sys.stdout.reconfigure(encoding='utf-8')`。
- **`is_error` ≠ 假完成**：很多工具报错后面接的是无关进展；要读上下文再判。
- **n=0 也可能为真**：写入发生在更早的轮次，本句只是复述。必须用 artifact（文件:行／commit／命令输出）复核，别只看 n。
- 断言可能在多个 assistant 消息里拆开（先「撤回」再说「补进日记」），要按整轮读。

## 已知结论（2026-10-24 首次运行）
- 4 处实锤全部是**小而即时的写入**（日记一行、黑板一笔、补记录）；**大交付零误报**。
- 模式：内容已在回复里说完 ⇒ 写入那一步被当成多余而跳过。详见记忆 `false-completion-claims`。
