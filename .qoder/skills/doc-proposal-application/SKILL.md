# 提案套用与草稿退役（工作法）

> 承接自 WB 同名技能（2026-10-13 执行权移交）。适用：把讨论稿／提案套现进权威文档（docs），并把草稿退役或改指。

## 一、先定稿件性质（最大的坑）

- **内容稿**＝成品正文，可整段搬；
- **编辑指令集**＝逐条「现状原文 → 建议改后」。
⛔ 指令集若按“合并”字面理解，会**造出双份“现状原文”**，成为后续漂移源。开工前先读清单开头三行判性质。

## 二、五条核心纪律

1. **锄点用内容前缀匹配，不用行号**（行号因他人编辑必漂）。⚠️ 锄点串**从目标文件里读**、不手抄进脚本（差一字符就 SyntaxError，且前面步骤一行没跑）；表格行有前导缩进，`startswith` 会 0 命中。
2. **脚本化 ＋ 双断言，失败即不落盘**：锄点命中数 `== 1`；批量插入计数 `== 预期`。清单逐条独立，⛔ 不写复合替换。
3. ⭐ **出稿方的清单必查漏项**：自己重扫目标文件 ＋ 相邻文档（实测：清单列 2 处联动，查出第 3 处）。同一矩阵常在多处有副本，**改措辞前先全库 grep 同名表述**，只改一处＝两套口径。
4. **转写残留五查**：外部路径（别原样搬进本仓）｜草案口吻（“抄进本条”→正文口吻）｜枚举结构（分号枚举别插散）｜符号一致性｜列表连续性（插入块的空行会切断列表）。
5. **退役前置查反向引用**，三类分流：**承重引用**→同批改指到已套用的目标文件；**索引条目**→同批删；**工具自生成缓存**→先核 `git ls-files` 是否未跟踪。扫描面**必须含非文档文件**（代码注释里常有“见某稿”）。

## 三、多方评审融合六步（顺序不可换）

1. 先按原样提交一版存档（**含全部意见**，提交信息里逐方列条数）。
2. 核意见里的**外部事实论断**（逐条回源、注明通道；⚠️ **通道不同则结论不可互推** ⇒ 写“未验项＋重测建议”，不直接采信也不直接推翻）。
3. 三档处置**各自留痕**：吸收→标注“vN 新增”／部分吸收→写清采纳哪半／**不吸收→必须给理由且落在正文可找到处**。
4. ⛔ **删意见前先扫「正文对附录的引用」**（同一文件内！实测踩过：正文写“见附录 A·C1”，附录一删即悬空）。
5. 核稿件本体之外是否还有副本（各方 log 里可能也贴了一份）。
6. 定稿落位 ＋ 同步索引 ＋ 提交；正文留一句「含意见的存档版本 = git `<hash>`」。

## 四、定稿后的表述收敛（移入 docs 专用）

- 去掉讨论痕迹（“某某认为”“待表态”“上一轮”），只留结论与依据；过程可追溯交给 git。
- 进 docs 的文件只写**当前态与职责**；沿革进变更记录表（若该区有此约定），不散写正文。
- 复检（删除块后查连续空行；**加粗奇偶必须程序算、且先剔行内 code span**，glob 会把反引号里的星号数成加粗）见〈doc-governance-recheck〉。
