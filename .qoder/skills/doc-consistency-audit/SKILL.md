# 文档一致性巡检（Qoder 工作法）

> 适用：全量职责巡检 ／ 针对性梳理 ／ 重要内容落点核实 ／ 引用与索引完整性检查。
> 定位：这是「审计视角」——发现跨文档的漂移、断链、缺项、过期与“无处可办的建议”。配套工作法（各成一份 skill，本件不展开）：归档瘦身 `doc-archive-slimming`、提案套用 `doc-proposal-application`、事后复检 `doc-governance-recheck`、清退与承接 `doc-sunset-handoff`、判据设计 `verifiable-criteria-design`、断言回源核证 `claim-source-verification`、职责变更同步 `scope-change-sync`。
> ⭐ **一体两面、须同步**：本区（docs）与 `TODO.md` 是同一件事的两面（做什么／怎么做），改一面必同步另一面，两面不一致即为缺陷；同步双向（定调→TODO 承接；执行新事实→回流修正本区结论）。

## 一、先定模式（三选一，可组合）

**A. 全量职责巡检**（触发：“跑一次全量职责”）
- 范围：根级（README ／ HUMAN* ／ TODO）＋ `docs/` ＋ `archive/` ＋ `exchange/`。
- 主轴：**变更点驱动**（对照自上次巡检以来的提交批逐点抽查），已闭环项不复述。
- 产出：〈全量职责巡检报告〉六节（索引一致性 ／ 死链扫描 ／ 过期陈述抽查 ／ 旧发现复核 ／ 结构与精简判定 ／ 本轮边界）＋ 未结项区刷新。

**B. 针对性梳理**（单主题 ／ 单区域 ／ 单条目复核）
- 范围收窄、**证据标准不降**：凡“说没有 ／ 不存在”必须附检索式与遍历范围。

**C. 重要内容落点核实**（“X 落在哪” ／ “是否一致” —— 高频轻量）
- 次序（省时间的关键）：
  1. 全库 `git grep`（多关键词变体，注意**前缀陷阱**：`landlock*` 会漏 `cvm-landlock-verify`）；
  2. **先查两处 skill 库**：`~/.workbuddy/skills/*/SKILL.md` 与 Qoder skills —— 原则 ／ 方法论常沉淀于此且**不在 git 内**；
  3. **git pickaxe 全历史**：`git log --all -S "短语" --oneline`（`-S` 是精确子串；含已删文档），命中后看 diff；
  4. 历史版本：`git show <rev>:<path>`（已删文件的原文）；
  5. 落点找不到时，报告**检索覆盖范围**＋“未见成文”结论（不得只写“没有”）。
- ⚠️ 铁律：**提出“建议改 XX”前先核 XX 存在** —— 无载体的建议会空转且伪装成“待办”。
- ⚠️ 同一条**反着也成立**：写“**明细／文案见 `git log -p`**”之前，先用 pickaxe 验它**真落过盘**（实测 10-14：我在未结项写“四份文案见 git 史”，`git log --all -S "沉淀纪律" -- <log>` 只命中“待贴”那句、清扫前版本里也没正文 ⇒ 那句当场成断链）。**只在对话里给过的东西不进 git** ⇒ 要别人照做的内容必须先写进我有写权的区，再引用它。

## 二、四件套（可复算方法，A/B 通用）
1. **地图 × 索引**：目录实际 ↔ 各级 README ／ 索引清单逐条比对（缺项 ／ 多项）。
2. **死链 ／ 引用**：node 内联脚本扫 `](path)`（双基准解析：文件相对 ＋ 仓根相对）；反引号路径只做抽查（全量扫描噪声大）。
   - ⭐ **`§N` 类章节错引可脚本化核**（拿不准就用脚本，别目测）：① 取**被查文件自身章节号集合**（`^#{2,5}\s+\d+(\.\d+)*`）；② 正则扫全文 `§(\d+(\.\d+)*)`；③ 未命中本文件者先看**同行有无 `xxx.md`** ⇒ 有则去**目标文件**核该章节号（⚠️ 注意目录层级：`docs/dsh/` 里写的 `production-env.md` 实在 `docs/`）；④ 两边都查不到才是**真错引**。两类常见**假阳性**：表内 §N 由**表头声明的依据文件**兜住（可解但不显式 ⇒ 属表述层，报而不改）、目标章节实为上一级 `###` 内的 `####`（例：〈基线收口复核〉在 §3.4 内）。**修法只改错的那一条**，别顺手重写整表；改完把"其余引用已核过、皆存在"写进回报，免得他人再查一遍。
3. **过期陈述**：变更点驱动 grep —— 近期提交批涉及的文档 → 逐个 grep 旧关键词，核“现在时”陈述 vs 现状。
4. **体量与落位**：各区体量对比；落位判据＝「**是否仍被引用**」（→ `docs/`）；archive 锁定区**不改叙述**，只可加批注 ＋ 退役指向。

## 三、证据与表述纪律
- 外部事实三级标注 🟢🟡🔴（`docs/ai-governance.md` §3.1）；**不因来源身份加权**。
- 报告必须**可复算**：方法、命令、计数写全。
- **观察与评论分开**（先摆事实，再给判断）。
- **只读巡检**：不改被查文件；报告写 `exchange/log-qoder.md`。
- 结论标注“截至本次查询”。

## 四、落点与清理规则速查
- `docs/` 只引用**稳定落点**（`docs/` ／ `archive/` ／ `TODO.md`；“行动指南”例外）；`exchange/log-*` 是活日志、**不承诺保留**、不得被当承接目标。
- 活日志清理三件套：**清理前核无孤儿**（内容都已被承接）→ **登记**（删了什么 ／ 承接落点 ／ `git log -p` 回溯）→ 与相关改动合并 commit。
- 未结项管理：条目 =「问题 ＋ 建议 ＋ 状态」；“已消”移入头注清单（**编号不重排**，防历史引用错位）；详细证据挂巡检报告。
- 权限（**执行层短尺**，细则不复述）：可写区＝`docs/`、`archive/`、`exchange/` 讨论稿 ＋ 各级 `README.md`（直接改并 commit，改完在本区回报，无需请示）＋ 阶段归档时对 `TODO.md` **搬块**；只读区＝`.claude/`／`.trae/`／`.qoder/rules`／`.workbuddy`／`HUMAN.md`·`HUMAN_NOTE.md`（发现问题 ⇒ 备好可粘贴文案提交人类）。⛔ 边界细则（他人权限、各区归属、闭环步骤）一律查 **`docs/ai-governance.md` §3**；老大直接命令最高优先级（覆盖一切准则）。

## 五、踩坑登记（缓慢沉淀：遇新坑追加）
1. 前缀搜索漏网 ⇒ 搜索带多关键词变体（含中缀、后缀形态）。
2. “建议改 XX”前先核 XX 存在（无载体建议＝空转）。
3. 「目录 vs 包」层级对撞（读 `kind` 字段再判层级；已两度发作）。
4. 区分**历史叙述**与**现状陈述**：历史动机（如“趁到期前”）不改；现状 ／ 未来时限须换新值（如 CVM → 2027-10-09）。
5. 行尾已由 `.gitattributes` 统一 LF（2026-10-08）⇒ 不再维护“行尾保持”类检查。
6. 巡检顺手 `wc -c` 两份 `MEMORY.md`（警戒参照：~30KB 级截断；当前裕量大）。
7. 修改共享工作区文件前：先看 `git status` 有无他人在途改动；提交用**明确路径**（pathspec），不 `add -A`。
8. **早期（P0~P2）的讨论素材已在 `archive/`**：`qoder-work-historical-record.md`（完整交流记录）＋ `-digest.md`（结论与事实精简版，与完整版互指）——仓内检索为零时**先查这两个文件**（⛔ 不援引／访问任何项目外存档位置；如需新素材，**向老大提出、由老大提供**）。实例：召回阈值 0.3 的两场讨论（设计期 0.7→0.5 ／ 实测 0.3573 后 0.5→0.3）即在此件中。
9. **引用 `HUMAN.md`／`HUMAN_NOTE.md` 只用「文件 ＋ 锚串」，⛔ 不带 `:NN` 行号**——这两份老大常改，行号一次插入即漂（实测：10-14 他重排〈目前参与AI〉⇒ 全库 5 处 `:NN` 当场失效、含我自己两处；10-17 他当场一笔编辑，就把我 docs 里的 `HUMAN.md:48` 顶成了空行）。**锚串＝标题或句子里可 grep 的字面片段**（如「过时计划的条目」「有以下项值得测」「毒化已清理」「中性事实态」）；〈段名〉须与标题逐字一致才算可复算锚，条目号（如"第 2 条"）只作辅助、不作锚（清单会被重排）。**复算式**：`grep -rnE "HUMAN(_NOTE)?\.md.{0,3}[0-9]" --include=*.md docs archive exchange TODO.md README.md` ⇒ 命中即待处理：**改自己的、给他人出文案并附新旧对照**，历史日报不追改（注：描述这条规矩本身的文本也会被该式命中＝自指噪声，逐条判性即可）。**开工触发**：`git log` 近期若动过这两份 ⇒ 先跑该式再动别的（10-17 我就是没先跑，照抄了转办稿里的 `:103`）。
10. **进上下文的治理文件只写当前职责**：不写交接、时间点、历史状态、‘老大裁定’；沿革交给 `git log` 与变更记录表（详见 `scope-change-sync`）。
11. **同一原则只留一处权威落点**（本仓为 `docs/ai-governance.md`），其余只留指针；在两份治理文件里各写一遍⇒ 必漂。 ｜**适用边界（老大 10-14 尾定）**：这条纪律**只用于 `docs/` 与各级 README 之间**；**各 AI 的约束文件里留一份是刻意的**（唯一每轮自动注入的载体，老大原话「写到约束文件里面是效果最好的」）⇒ ⛔ **不提「把约束升格进 docs」、也不提「删约束文件里的复述」**，落点分配由老大把控。我能报可改的只有可写区那一侧。
    - 11.1 **载体分层尺**（老大 2026-10-14 定，尾刻更正）：**`HUMAN.md`＝给 AI 的约束／提示**｜**`HUMAN_NOTE.md`＝老大自阅 ＋ 他的安排与 AI 职责的落点**｜**`docs/ai-governance.md`＝机制层唯一权威落点（保持现状，勿加复述）**｜**各 AI 约束文件＝执行层**（唯一每轮自动注入，留短尺＋指针，⛔ 不复制原则原文）｜**各级 README＝落实层**（只写**本区**谁负责＋怎么负责）｜**其余＝指针**。⚠️ **「给谁看」不是判据**——AI 读职责读的是自己的约束文件，`HUMAN*` 都不自动注入；⇒ 判「这条该写在哪」只问两件事：**① 谁执行它**（→ 落那个 AI 的执行层约束文件，不然它每轮看不见）**② 是否跨 AI 共享的项目事实**（→ `docs/` 或讨论稿）。两问都否就留 `HUMAN_NOTE`，⛔ 别为「成文」硬塞进 `docs/`（我曾这样误推一条，见本仓 `exchange/log-qoder.md` 未结项 23 留痕）。⇒ 巡检见同一职责出现在第二处时，先判它属**必要落实**还是**纯复述**：后者即缺陷，改指针或删。
    - 11.2 **分层漂移是双向的**：除查「机制层改了、执行层没跟」，必同样查「**执行层新写了、机制层没有**」⇒ 后者同轮回流 `docs/`（实测 10-14：老大给 `CLAUDE.md` 写的〈技能沉淀〉比 §3.3 多出**用前先查 ＋ 可随推进迭代升级**两面，我当轮补进 §3.3 才消差）。⚠️ 这不是"建议升格"（升格由老大把控，见坑 11）——此处说的是**我自己写的机制层条目落后于现行口径**，补齐属可写区正常动作。附带收获：执行层这一轮的**载体形态**（Claude 技能库走仓内 `.claude/skills/`、入 git）属跨 AI 共享事实 ⇒ 一并登记进 §3〈文件与载体〉，勿只留在约束文件里。
    - 11.3 **单份文件内部也会自相矛盾**（比跨文件漂移更隐蔽，跨文件比对查不到）：实测 10-15——老大把 `CLAUDE.md`〈技能沉淀〉整段复制进 `.trae/TRAE.md`（⚠️ **当时路径**：正本 10-18 起在 `.trae/rules/TRAE.md`，本条记的是 10-15 现场，⛔ 别据此改史），路径没换（仍指 **`.claude/skills/`**＝别人的私有目录），而 TRAE.md 自己的〈行为准则〉第一行就把 `.claude/` 列为"不得做任何改动"⇒ **同一文件内两条互斥**，照字面执行就越界。⇒ 巡检**整段复制**的条款时，除了跨文件比，还要在同一份文件内问一遍：「这条让我做的动作，这份文件自己禁不禁？」（抄来的段落最易残留上一家的活动类型与路径，顺手核"活动名词"是否也照抄错了）。
12. **阶段编号漂移**：已取消的旧阶段号会被旧讨论稿**捣用成新含义**——实例：`P5` 原为「移动端＋部署」、`TODO.md` 已声明 2026-08-20 取消 P 编号，但 time-context 稿拿它当「记忆保鲜阶段」用了十余处。⇒ **见 P 编号先核 `TODO.md` 的取消声明**；现行口径只有三个：`DSH-N`（迁移线）／`P0–P4`（已完成主线，只属历史）／**「长期迭代（`TODO.md` 待立条目）」**；能力层引用一律改指**能力树编号（如 2.9.1／2.4.4／2.9.2）**。
13. **命名与 glob 对不上＝规则静默失效**：全区口径按 `log-*.md` 立，而 `log_design.md`（下划线，历史命名）形式上不在覆盖内⇒ 归属／清理／不得引用三条对它全部落空，历史上全靠逐次人工授权兜底。⇒ 巡检查“某类规则是否真盖到全部实例”时，拿**声明的 glob 去 glob 实际文件名**（不只是 grep 关键词）；修法优先**在治理文本里补覆盖**，不轻易改名（改名会断引用）。
15. **变更记录表「断档」不靠肉眼查**：外部断言常以「表末条停在 X、正文已到 Y」为形——**先验字面**（`git log --since=<末条日期> -- <文件>` 列出自那之后的全部提交，比对表内是否各有对应行）**再定性质**：末条是否已被他人补上（旧快照的断言会字面失效但**实质仍可能对**，如本仓 10-14 一例：说「停在 09-17」时表里已有 10-13／10-14，可 09-30 与 10-09 三笔改动确实没登记）。⇒ 补登时**标「补登」＋附提交号＋按日期序插入**（不追加到表尾），⛔ 只补账不动正文与档位；并顺手核每行列数与总行数（脚本）。
16. **自沉淀门槛（同 §3.3 于本仓 ai-governance）**：本技能族里**任一 skill 被第二次调用**、或本轮跑出一条别处没有的可复算步骤 ⇒ 当轮就把它写回对应 skill（触发词／步骤／坑三段齐），⛔ 不要攒到"以后再说"；新建 skill 前先跑一遍现有 8 份，能并则并（同一原则两处写＝必漂，坑 11 同理）。**只装方法**：约束条款 ⇒ 约束文件，项目事实 ⇒ `docs/`。
    - 16.1 **skill 生效判据（10-15 定）**：① **就地改同一份文件**＝本会话当场生效（改完试调用看正文即可）；② **同名并存时用户级优先**（老大 10-15 专测结论，与我影子件那轮观察一致）⇒ **迁进项目级后必须删净用户级同名件**，否则仓内那份被遮蔽、静默失效；③ 一旦动了"位置"（搬家／删建同名件），本会话返回体的**基目录字符串不可单独作判据**（我实测出现过"基目录报仓内、正文却不含仓内独有标记"）⇒ 判生效看**内容差异**，并在新会话复核。⛔ 任何时候都别拿"可用技能列表"当判据（会话级快照）。
