# 文档治理事后复检（工作法）

> 承接自 WB 同名技能（2026-10-13 执行权移交）。既用于**自己做完动作后的自检**，也用于复验他人的同类动作（同一套判据）。
> 一句话定位：**不是校对改动本身，是校改动留下的空洞与失联。**

## 一、承接 6 条（有没有人接住）

1. 删项逐个 grep 承接——`[x]` 已完成项是**搬家**不是删除，要找到它的新落点。
2. 清交流区前先做「承接转登」（结论→docs，待办→TODO，溯源→git）。
3. ⭐ **提「建议改 XX 文档」前先核那个载体存在**——没有载体的建议会空转，却在清单里看着像待办。
4. 核承接**拿被移条目的独有细节去 grep 目标段**——**只命中名字不算**（实测：段名声称含“进入前”，实则只含“开门之后”）。
5. ⚠️ **安全类条目单列一核**（实测 10-15：他人约束文件瘦身，删掉六条“运维约定”里的 `--real-api` 残留含**真实 key** 必须手动清 —— 这类"丢了不出错、只在特定模式下炸"的句子最容易被当明细删掉）。⇒ 复检搬家时先问：**有没有一条是"防泄漏／防误删／防越界"的？** 它必须逐字找到落点，找不到即判**未承接**，⛔ 不接受“方法里应该有”。
6. **反向情形**：对方把**事实**也一并搬进自己的 skill 时，我这侧 `docs/` 的引用**不要跟着改成指 skill**（那等于让事实寄居在方法载体里，与 §3.3「skill 只装方法」相反）。⇒ 正确改法＝**事实留在自称真相源的本档 ＋ 只把方法指针指过去**（实测：`docs/test-env.md`〈临时目录口径〉原引 `CLAUDE.md〈运维约定〉`，该节搬家后改成“Windows 侧值留 test-env ＋ 命令指 `.claude/skills/backend-testing`”，并注明“⛔ 别再引 CLAUDE.md 该节”）。

## 二、引用完整性 3 条

1. 搬家后**反向 grep 旧落点**（实测一次措出 5 处静默悬空）。
2. 一处明细变动先想一句：「还有谁在别处描述这件事的形态」（README／索引／面板／代码注释）。
3. **代码注释里的「事实名」不随文档归档失效**——判别：指向**文档坐标**才改；指向**物自体**（源码行／提交号／装置件）不修。

## 三、面板不变量 4 条（程序算，不肉眼）

1. ✅／[ ] 标记不变量；
2. 「延后项收回」是**三处同步**（段首说明＋上游汇总口径＋条目本体）；
3. 「某段已收口」是**带时间戳的断言**——其后任何段外新增都会让它过期；
4. 段内挂 `[ ]` 有**两种相反成因**：状态标记过期→摘框 ／ 真实在飞项→**保留 `[ ]` 只更新内容**；判别法＝「这条现在还有没有人在干活」。

## 四、编辑卫生 9 条

1. 提交前扫凭据（`Bearer|password|secret|sk-`）。
2. **提交前必重新 diff**——多 AI 共写同一工作区，旧快照会过期。
3. **「改状态」与「删内容」是两种动作**，混在同一次编辑里越界不报错（拆逐次提交才可追溯）。
4. **大块替换前核覆盖区间内有无常驻内容**（实测**已两次**同形翻车：一次吃掉「通用纪律 6 条」，一次 `old_string` 尾巴带到下一节的 `## 🗂 已清理段落` 标题、`new_string` 没把它写回去 ⇒ 标题当场消失）。⇒ **旧串必须含足够上下文、新串必须逐字带回区间内所有常驻标题**；⚠️ 而且**"Edit 成功"不等于内容没被吃**（它只保证匹配唯一）。**复算动作**：跨节编辑后立刻 `grep -n "^## \|^---$" <文件>` 与编辑前的节序对一遍（我编辑前先跑一次留底），数量少了就是吃掉了，当场补回。
5. **shell 里跑 `node -e "…"` 时，串内的反引号会被 bash 当命令替换吃掉**（实测：正文里的 `` `92af3ea` `` 变成空，落盘成「见 ）、」这种残句，且不报错）。⇒ 内联脚本**一律单引号包脚本**（`node -e '…'`），或先 Write 成临时 `.js` 再 `node /tmp/x.js`；⛔ 别让 ASCII 双引号／反引号／`$` 进双引号脚本（本条与前一条同源：**shell 改写过的字符串会静默损坏正文**）。**改完必回读被改行**（`indexOf` 定位＋`JSON.stringify` 打印，比"看起来成功"可靠）。
6. **「登记条目」里的形制规矩对自己也生效**：登记段规定不写 commit hash（本区 48fe582 定），我给旧登记做澄清时顺手加了个 hash ⇒ 又违反自己刚立的形制，回读时发现才删。⇒ 补注要照该条目**所在段的现行形制**写，不因为"我是解释者"豁免。
7. **段落之间必须显式插空行**（实测：用 `[...].join('')` 拼新段落，`join('')` 是**空分隔符** ⇒ 我以为写了两个 `''` 就有换行，结果新段落被**直接粘在表格最后一行尾部**，markdown 表格被静默撑坏）。⇒ 新段落的前导分隔符**写字符串字面量 `'\n\n'`，不靠数组 join**；插入后复算两条：① **表格每行 `|` 计数是否仍一致**（一行数字突变＝粘连）② `sed -n` 打插入点上下三行肉眼看结构。⚠️ 这类损坏在 `cut -c1-70` 的截断输出里**看不出来**，判据得用计数不能靠眼看。
8. **提交信息（commit message）里别用 heredoc 拼长中文串**（实测：修 README 那笔的标题混进了一个字面 `\r`，正文与文件内容都对，但标题不 amend ⇒ 只能登记备查）。⇒ 标题走**单行直传**（`git commit -m "…"`），正文需要多行才用 heredoc；提交后 `git log --oneline -1` **回读标题**核对。（实况变体：在双引号的 commit -m 里写 JS 式转义 \u0022 不会被还原，**原样进标题**——本轮一笔提交标题就留下了两处；文件内容无误，按不回改历史的规矩登记备查。⇒ commit 文案只用中文引号「」，⛔ 不放任何转义序列）
9. **脚本里"先重写 t、再复用旧偏移量做 splice"＝截断大文件的定形**（实测事故：`t = t.slice(0,i) + NEW + t.slice(i + a.length)` 写成两行、第二行用的是**已改过的 t** 与**旧串长度** ⇒ `docs/ai-governance.md` 从 41653 B 掉到 **9412 B**，§3 后半连 §4/§5 全没了）。⇒ 三条硬规矩：**① 一次编辑只从一个源字符串算偏移**（要连改两处就写成一串 `slice`、或分成两次跑）；**② 写盘前先断言输出长度**（`if (out.length < src.length * 0.9 && !有意删除) fail`）；**③ 写盘后立刻核字节数＋节标题数＋尾部 60 字符**，与编辑前留底比对（光看"脚本 exit 0"毫无信息量）。事故当场先 `cp` 幸存件再动刀：幸存前缀＋`git show HEAD:<file>` 后半 ＝ 可重建，**别在没备份时重试**。

## 五、挂起回头查

「等待某条件」的条目，**条件一旦满足必须回头改它**（实测：一条挂着“待复核放行后可改”，而该件早已通过复验 ⇒ 僵死）。复检时先问：这条的阻塞条件今天还成立吗？

⭐ **新原则反照已落地动作**（自踩型盲区）：治理原则当日新增／改写后，**把当天自己落过的动作重照一遍**——逐条问「按新尺，它算『共享事实进公共区』（合规）还是『自用事实进公共区』（该收）？」。冲突**摆成独立待裁条**（甲＝保留但瘦身／乙＝收回，＋自身倾向），⛔ 不许用「当时是老大令我做的」自证仍对——命令在前、原则在后时，**后者覆盖前者的部分正是复检要抓的**。⚠️ 他人（含老大）正在编辑中的治理文本**只引用不追改**：落地前以最终版为准，报告里注明"该行仍在演化、尚未提交"。

## 六、输出形式

结论分三档：**成立**／**成立但表述有缺**（逐条列、不改结论）／**不成立**（摆矛盾＋选项＋自身倾向）。每条必附可复算证据（命令／计数／行内容），**不采信执行方声明**。报告写自己区的 log，并与相关改动合并 commit。
