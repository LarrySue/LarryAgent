# 过程性文档清退与承接（工作法）

> 承接自 WB 同名技能（2026-10-13 执行权移交）。职责划分：`log-*` 那半通常归协调方（WB），**讨论稿那半归文档维护方**；跨界清理两边同步后动手。

## 一、五条核心纪律

1. 删前核 **git 留底**——⚠️ **文件在仓库 ≠ 那段在里面**（他人正在写的常只在工作区）。
2. ⛔ **不另存物理备份**（git 即留底；备份件反而成为第二份漂移源）。
3. 逐条核承接：结论→`docs/`；待办→`TODO.md`；**建议型→不自行处置**（替用户拍定性＝越权）。
4. **先落盘承接件，再删原件**（顺序颠倒＝瞬时孤儿，中间崩溃就永久丢）。
5. **被清理物自述「已迁出」也是印象、不是证据**（实测：自述“已迁 TODO”，逐条 grep 才发现 4 个子项散在 4 个行号）。

## 二、什么算必清（三档）

| 形态 | 判定 |
|---|---|
| **段落引用**（把某 log 章节当长期证据） | 🔴 必清——活日志会被轮换，引用会**静默失活** |
| **行动指南**（“什么情况去读哪个文件”） | ⚪ 不算引用、可留；但**只许指向稳定落点** |
| **讨论稿指针**（非 log，未定案） | 🟡 缓——随稿演化，定稿进 docs 后同批改指 |

## 三、三条判据

- ⭐ **「文件还在、内容被轮换」＝静默失活**（比断链阴）。核引用不能只核“文件在不在”，要核**指向的那段内容当下还在不在**；判「内容不存在」前先自证判据（拿编号字面 grep 会因形式差异**伪装成缺失**）。
- ⭐ **反向用法**：已被登记为资产／复现件的段落 ⇒ **不可删、只可归档**；「清理」授权 ≠ 「删资产」授权。
- ⭐ **反向过检**：仓内**零承接 ≠ 可删**（它可能是某件事的唯一证据，删了不报错、没人察觉）；判「零承接」要**两通道核**（内容 grep ＋ 历史 pickaxe）。

## 四、产物台账回流

「我做了 A」之后「别人对 A 做了 B」时，**A 相关的所有陈述进入待更新集**（实测：三处“备份在 X”因用户真删 X 而变失活路径）。删完回头查：谁引用过这个被删物。

⭐ **承接会在校完之后消失**（实测 10-16：删条目前逐条核过承接、还记下了「→ 某 log 的 `:38`／`:39`」，结果**核完到落盘之间，老大清理了那个 log、整节 −93 行** ⇒ 两条承接同时失效，而我这边原文已经删了）。⇒ 三条：**① 承接指针必须带「兜底」**——除了指对方现值，同时记下自己这侧的 git 回溯点（`git show <commit>:<自己的 log>` 第 N 行），这样对方被清也不至于事实蒸发；**② 落盘前最后一刻再扫一次** `git status` 与承接方现值，⛔ 不用几分钟前的核查结果（共享工作区里"我刚核过"的保质期只有几分钟）；**③ 承接方是 `log-*` 的尤其危险**——活日志随时会被属主或老大清，把唯一承接放在别人的活日志里＝把事实存在会被轮转的介质上。这是 §三「零承接 ≠ 可删」的反面：**有承接 ≠ 承接会一直在**。

## 五、多 log 联合清理约定

授权读两处（各 log 头部自述 ＋ 区 README）｜保留活层（状态区／未结项／待裁／通用纪律）｜未裁建议**提炼成「⏳ 未结项」留下**，不替老大拍｜清理记录形制＝删了什么／权威落点／回溯方法（**不写 commit hash**）｜⭐ **〈已清理段落〉只留最新一条登记**（老大 2026-10-14 定：更早的随手清掉，留一条只当写法参照——它不是档案，攒着就变成堆）｜头部自述为「设计过程记录／产品方向源」的 log 不该清（清了＝毁其职能）。

## 六、收尾

清理与相关改动合并 commit（pathspec 明确路径，不 `add -A`）；在自己区 log 留一句「已清理段落（按规矩）：……」；向协作方同步一句“此段已撤”。
