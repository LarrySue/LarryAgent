# 断言回源核证与分流转办（工作法）

> 定位：这是**核证者**的动作，不是修复者。默认**零代码改动**（除非老大明说“去改”）。

## 一、六步

1. **定位坐标**：断言里的文件／行号先当“入口”不当“证据”——行号可能已漂，先读**整个函数／整个文件**再判。
2. **回源不采信声明**：他人说“已修／已迁／已登记”一律当印象；逐条 grep ＋ 必要时 `git log -S` ／ `git show <rev>:<path>` 取当时快照。
3. **影响面扇描**：谁消费它（grep 调用方）·测试有没覆盖该分支·文档在何处叙述过它·配置是否真供得上（区分“可调”与“硬编码”）。
4. **零副作用实测**（能实测就别只推理）：
   - 纯函数直调：`Cls.__new__(Cls)` 绕过 `__init__` ⇒ 不读配置、不建连接、不起进程；
   - 只跑无害命令验环境（如 `echo %COMSPEC%` 辨壳）；
   - ⛔ 不在真实库上跑测试（先看 `LARRY_CONFIG` / DB 路径是否临时库）；不打印任何凭据。
5. **三组对照**：正向命中（证明探针有效）／预期失效（证明断言）／旁路对照（防工具层故障伪装成被测对象失败）。
6. **结论分档**：**成立**／**成立但定性需订正**（事实对、措辞或归因不准）／**不成立**。订正他人表述时写清“**不改结论**”那几条只是表述。

## 二、分流（决定谁能动）

| 档 | 例子 | 处理 |
|---|---|---|
| **表述层** | 注释与实现不符、文档断言错、死引用出处 | 文档面可直接改；代码注释改法需协作方认可 |
| **行为层** | 改默认值、改防护强度、改提示文本 | ⛔ 不动，列「待裁」并给选项（含“不动”这一选项） |
| **已有裁定** | 先查历史裁定（HUMAN_NOTE／TODO／docs）再提建议 | ⛔ 不要重复劳功——先证明“这笔债未被裁过” |

## 三、留痕形制

- 标题带序号 ＋ 一句「核证方式」（读了哪几份、实测怎么跑、零改动声明）；
- 逐条证据：文件:行 ＋ 引文**逐字**（⚠️ 跨文档引用优先用**章节锚／条目名**不用 `:NNN`；引文用词必校，错一个词就要自纠）；
- 影响面分档（危害不同时列成表，别给一个笼统“严重”）；
- 建议修法编号 (a)(b)(c)，每条写明代价与适用面；
- 摆矛盾不折中：与交办人原话不一致时，直说“与您原话相反，摆出来请您裁”，附实测；
- 合并 commit（pathspec 明列路径，⛔ 不 `add -A` 扫入他人未提交改动）。

## 四、坑登记

- “有痕迹”≠“有出路”：日志里有 warning 但无异常／无标记／无重试，得写成两层，不能笼统说“完全静默”。
- 同一机制的不同字段危害不同（有的字段失败会响、有的完全无声），**逐字段分档**再下结论。
- 断言的“实例例”本身可能不准（如默认防护会拦住那个写法）——要给出**真正能落地的那个变体**，否则转办会被驳倒。
- 测试常只锁正向：补一句“绕过方向零测试 ⇒ 回归无人知”，归入建议。
