## 1 贯穿性底层原则（非独立域）

> **「信任」不单列为一个域**——它是贯穿所有层面的底层逻辑与方向，渗透于能力树每一处，而非与能力并列的分类项。以下为它在树中的落点（每个落点仍在本域编号下）：

| 落点 | 体现 |
|---|---|
| 2.7.2 边界透明与用户决策权 | 边界交用户决策，而非系统替用户管控 |
| 2.7.5 数据主权与出境边界 | 数据在哪、什么出境 |
| 2.7.6 数据可恢复与可迁移 | 数据不被绑架、可带走 |
| 2.7.3 凭据与密钥边界 | AI 不碰用户的 key（key 只走配置、不入库、不出日志） |
| 2.8.2 AI 行为可见 | 让用户知情 AI 在干什么；来源可核对、核不了会明说 |
| 2.3.1 回收站（会话级） | 会话删除可恢复 |
| 2.4.3 记忆可管理 | 记忆删除**当前不可逆**（设计决策，非信任缺口）；撤销覆盖由「入库前确认可编辑（已做）+ 删除前如实提示（**承诺，待 2.8.1 UI 兑现**）」保障 |

## 2 功能边界树

### 2.1 读法

**状态图例**

| 标记 | 含义 | 落地方式怎么写 |
|---|---|---|
| ✅ | 已实现 | 写**怎么做的**（代码 / 配置事实） |
| 🚧 | 部分实现 | 分别写已做的部分与缺的部分 |
| 📐 | 有计划（TODO 有条目 / 讨论稿有方案，但无排期） | 写**怎么计划的**（引用来源） |
| 🗣️ | **老大裁定占位**：有意向、有优先级，但零方案零排期 | 写**裁定内容**（不写落地方式） |
| 🌱 | 愿景，**无承接**（TODO 无条目、exchange 无稿、无设计、**无老大裁定**） | **不写**（如实标注无承接） |

> 🗣️ 与 🌱 的区别在**承接强度**：老大口头裁定是比 TODO 条目更强的承接信号，但弱于「有方案」。**2.3.3 / 2.3.4 / 2.3.5 / 2.4.6 属此档**，优先级差异写在各条目内。
>
> **🗣️ 优先级汇总**（老大裁定序列，强→弱）：**2.4.6 知识库（必要、非常必要）> 2.3.4 多模态（中）> 2.3.3 会话沙盒（意向）> 2.3.5 主动触达（很低）**。四者均无方案、无排期。

**写实口径（全树通用）**
- 凡 🚧 项须写明**已做到哪一档**（承诺档位澄清），不以愿景充数。
- **已做 = 用户可达**：代码层存在但无 API / UI 入口的，不算已做，须注明「层内具备、未暴露」。

**编号规则**：全局十进制多级编号，一级 `1` / 二级 `1.1` / 三级 `1.1.1`，同级内连续、不重置。顶层 8 个域为第 2 章下的 `2.3`–`2.10`，每域下为子项（能力 / 功能 / 模块）。

### 2.3 域一：交互与会话

#### 2.3.1 会话生命周期管理 🚧

- 回收站软删除：`GET /conversations/trash` + `restore` / `purge`，删除可恢复

**计划**（`../TODO.md`「UI 页面三件套」）
- 三个 Vue 页面：设置入口（复活）/ 已归档列表 / 回收站列表。后端 API 与前端 `api.ts` 函数均已就绪，**仅缺页面**，UI 复用活跃列表骨架
- 老大 2026-08-27 定调三者同期做

**无承接**：批量归档 / 批量删除为老大意向，未进 TODO，无排期

#### 2.3.2 对话体验 🚧

**已做**
- SSE 流式输出 + 停止生成（P3 核心交付）

**计划**（`../TODO.md` UI/UX 段 + `ui-reference.md` §5.4 / §6）
- 会话项时间戳展示（API 已返 `updated_at`，只差渲染）

#### 2.3.3 会话级作用域（沙盒） 🗣️

**老大意向**（无方案、无排期）：**会话可指定工作空间，类似每个会话有一个沙盒；未指定工作空间的会话单独创建一个沙盒**（具体实现逻辑待细化）。TODO 无条目、无设计稿。

> 注：此条不是 UI 列表功能，落地质变为**数据模型 + 工具作用域 + 隔离策略**。会话为单元管理，本子项为其能力侧留位。
>
> **与 2.10.2 联审**：沙盒决定工具的**作用域**，2.10.2 端侧能力决定工具的**执行位置**——沙盒落在端上还是云上直接决定本条数据模型，定案时须一并审。此处只留钩子，不预埋设计。
> 轻量判据：行业沙盒两模式（E2B 即抛 microVM / Daytona 持久容器）均为商业云、自托管不友好；**单人 + 自托管场景下，目录级隔离 + 工具作用域绑定（每会话绑定 `file_ops_workspace` 下子目录）即可拿到大部分产品价值**，复杂度低一个量级且与现有 pathlib 沙盒同构。结合 2.7.5 硬前置第 ③ 条（云端禁用 shell/file_ops），该轻量方案在可预见形态下始终够用。

#### 2.3.4 多模态输入 🗣️

**老大裁定**：**占一个位置，优先级中**。当前无实现、无设计、无排期；具体方案未定（会话内上传文件 / 图片的处理链路、与 2.4.6 知识库的关系、上下文注入方式均未定案）。

> 与 2.4.6 知识库的区别：多模态输入是**单次会话内的临时处理**；知识库是**持久化的外部资料注入**。
> **升级通道（留钩子，不预埋设计）**：2.3.4 方案定案时，考虑「单次会话内的文件 / 图片被用户显式保存 → 升级为 2.4.6 知识库条目」这条临时→持久通道是否留口。
> **隐藏依赖（本条「中」优先级里最重的成本）**：若主力模型无视觉能力，2.3.4 就不只是上传 UI 问题，而是**模型阵容问题**——要么新增 VLM（2.5.1 的新用例：按输入类型路由模型，与 2.6.2 同族），要么走本地解析管线（不加模型但加基建）。定案时与 2.5.1 / 2.6.2 联审。行业共识为「分类路由 + 混合管线」（文本型 PDF 走解析、截图图表走 VLM、长文档走检索 + 选择性注入），与原则 2（成本不能上天）对齐：不整文件灌入。

#### 2.3.5 主动触达 🗣️

**老大裁定**：**偏向做，优先级低**

**产品语义**：由 **AI 发起**而非用户先开口，基于时间与记忆主动推送（提醒 / 跟进 / 定期任务）。与被动问答相对，是交互范式的扩展，也是「越来越懂你」的另一种表达方式。

**无方案、无排期**：无实现、无设计，`../TODO.md` 无条目。

> **触发依赖**：需以 2.9.1 时间感知 + 2.4.2 长期记忆为前提，定案时一并考虑触发源与频率。
> **触达通道（空白，待定）**：云端如何把消息推给用户——PC 端系统通知 / 移动端 Web Push（**2.10.1 的 PWA 现标「可选」，若 2.3.5 要做则升为通道候选**）；不自造推送基建。
> **审批与打扰模型**：默认低打扰、高风险外部动作须用户点头（复用 2.7.2 config 化哲学，不新造机制）。
> **执行权边界（留痕）**：2026 Agentic 产品标配已是「圈定范围 + 审计轨迹 + 一键撤销」。本条定案时须显式写清 agent 能替用户做到哪一步、如何一键收回，与 2.7.2 同族。
> **触发引擎位置与 2.10.2 联审**（决定 missed-run 是否必答）：引擎放云端常驻则「设备休眠 / 后端下线期间错过的触发要不要补跑」问题很薄；放端侧则**必须有显式策略**（补跑全部 / 只补最近一次 / 跳过）。

### 2.4 域二：记忆与知识

> 本域由单行升格而来（项目主线是「越来越懂你」的记忆闭环，一行装不下）。

#### 2.4.1 短期记忆 ✅

会话内消息历史，超长按 `llm.max_input_tokens` 截断旧消息（见 2.9.2 — 该机制本身是一致性问题的根源）。

#### 2.4.2 长期记忆闭环 ✅

- **提取**：`memory/archiver.py::generate_summary` — 归档时 LLM 生成摘要（`POST /api/memory/archive`）
- **人审**：`POST /api/memory/archive/confirm` → `confirm_and_store`，**确认（可编辑）后才入库**
- **写入时矛盾检测（留钩子，立项时读）**：行业 2026 实践在写入时做矛盾检测（新记忆与既有事实冲突即标记），防「几周后才发现冲突」。本项目最省事的挂点就是上面的入库前确认环节——摘要与既有记忆冲突时顺带提示用户，无需新建机制。
- **双写**：SQLite 为真相源 + ChromaDB 向量库（**结构事实**：可由 SQLite 重建；**重建工具未实现**，属 2.4.4 计划）；Embedding 用本地 bge-small-zh
- **召回**：新对话按语义相似度检索（`memory/engine.py::get_long_term_memory`），拼进上下文
- **降级**：ChromaDB 不可用时静默降级，不阻塞对话

#### 2.4.3 记忆可管理 🚧

**已做（用户可达）**：`GET /api/memory` 列表可查；`DELETE /api/memory/{id}` 删除（**硬删，不可恢复**）；编辑发生在 `archive/confirm` 入库前（入库前可编辑）。

**层内具备、未暴露**：db 层有 `deactivate_memory`（`is_active` 软删），但 **API 层无调用方**，用户实际不可达 —— 故「可停用」**不计入已做档位**。

**承诺档位澄清**：当前档位 = **可看 / 可删（硬删、不可恢复）/ 入库前可编辑**，**不含**停用、入库后编辑与重归档。

> **删除不可逆是设计决策，不是信任缺口**：用户主动删记忆的动机通常是想删干净。撤销覆盖由「入库前确认可编辑 + 删除前如实提示不可恢复」保障；**不为记忆另建回收站**（单用户场景下属过度工程）。
>
> 远期想法「记忆浏览器 / 可视化」落点在 2.8.1，未进 TODO。

#### 2.4.4 记忆保鲜与代谢 📐

**计划**（`../TODO.md` 记忆系统调优段，长期、按使用体感调）
- 检索参数调优（`score_threshold` / `top_k` / 分级阈值）
- 相邻 chunk 合并（避免 LLM 看到被截断片段）
- **保鲜机制**：`last_hit_at` / `priority`，被频繁检索的记忆提升保留权重
- **失效机制（新增钩子，2026-09-06 行业对齐）**：上述字段管「不该忘的别忘」，**管不了「该更新的没更新」**。行业证据：记忆系统加入「遗忘惩罚」后，时间线越长表现越差（周级 −18.2 分 → 季度级 −29.5 分，老大注：实际使用体验也可证明此现象存在）；删除 / 失效能力实测极低（ForgetEval：Graphiti 4.4–7.0%、Letta 52.7%）。低成本修正 = **版本化 supersede + `valid_from` / `valid_to` + 检索证据打 `current / historical / transition` 状态标签**；**不需要知识图谱**（单人单实例下不划算）
- 向量同步补偿（ChromaDB 恢复后校验 SQLite ↔ Chroma 一致性并补写）
- Embedding 模型迁移脚本（重建 collection + 全量重索引，待触发）

#### 2.4.5 用户画像 📐

**计划**（`../TODO.md` 多场景 AI 架构段，标「长期」）：从记忆中提炼结构化用户画像，注入 system prompt；落地手段含长期记忆按 `source_role` 加权（软隔离）。

> 层级：它是**记忆的衍生物**（TODO 原文即从记忆提炼），故为记忆域子项，不与长期记忆并列。
>
> **隔离强度待定**：`source_role` 加权目前是**软隔离**。若未来转硬隔离（角色间记忆不可见），涉及已入库摘要在角色间的重分属，成本随数据量递增——须与记忆隔离设计一并拍板。
>
> **四作用域 schema（2026 行业已收敛）**：生产记忆系统普遍按 **user / agent / session / app** 四类作用域标识符组织，检索时组合且 user 级权重最高。本项目对应：2.4.5 用户画像 = **user 级**、2.3.3 会话沙盒 = **session 级**、`source_role` 角色归属 = **agent 级**——三者是**同一张记忆元数据 schema 的三列**，须一次设计（与 2.4.4 保鲜 / 失效字段、时间专题的 `occurred_at_*` 同批定：ChromaDB payload 写入后不可改，只能重灌一次）。

#### 2.4.6 知识库 🗣️

**老大裁定：知识库是必要的，非常必要**；同日补充「**知识库可以考虑带有知识引擎**」。当前无方案、无排期，待立项（TODO 无条目、`exchange/` 无讨论稿、无设计）。

与 2.4.2 的区别：长期记忆 = 对话自动沉淀（已实现）；知识库 = 用户主动导入的外部资料（RAG 同源、产品语义不同）。

> 与 2.3.4 的升级通道：见 2.3.4（临时→持久）。
>
> **「知识引擎」按三层递进落地（老大裁定：知识库可以带有知识引擎）**：
> 1. **基座层（首版即做，成本已封死）**：混合检索（BM25 / FTS + 向量 + RRF 融合）+ 元数据组织（来源 / 时间 / 标签 / `source_role` 归属）。行业实测混合检索比纯向量召回提升 15–30%；chunker / 向量库 / 本地 embedding 全部现成。**这一层本身即「知识引擎」的最小可用形态**——裁定③ 的合理内核首版即可兑现，不必等图。
> 2. **轻图层（留钩子，触发式）**：轻量实体 / 关系抽取。**触发条件**：真实使用中出现基座层答不好的多跳 / 关联类查询，且评估证明基座不够——先跑混合 RAG 基线，**图试点赢不了基线就砍掉**。
> 3. **完整 KG（明确不做）**：GraphRAG 式全量建图 + 社区摘要，索引成本可达数万美元级 LLM 调用；其「全局综合」能力对单人、以定点召回 + 上下文注入为主的 LarryAgent 是过剩的。
>
> **与 2.4.4 的作用域区分（消张力）**：2.4.4 的「不需要知识图谱」作用域是**记忆的保鲜与失效**；本条的「知识引擎」作用域是**知识库的组织与检索**。语料不同（对话摘要 vs 文档）、查询形态不同、失效语义不同——两条并存，互不推翻。
>
> **立项时六个产品决策点（预列，降低将来讨论成本）**：① 首批资料格式范围；② 与长期记忆同 collection 还是分 collection（直接影响召回加权与来源标注）；③ **引用从第一天就有**（无引用则退化为黑盒回答机，与 2.8.2 来源标注哲学同构）；④ 2.3.4 升级通道接入位；⑤ **是否经 MCP 暴露**（与 2.5.3 联动裁定——若暴露，知识库就不只服务 LarryAgent 自己）；⑥ **知识引擎分档**（默认第 1 层，第 2 层评估触发，第 3 层排除）。
> **分型**：个人知识库已收敛为「RAG 应用带聊天」与「聊天应用带 RAG」两型——LarryAgent 属**后者**，且可与 2.4.2 长期记忆共用同一条召回管线（chunker / 向量库 / 本地 embedding 均现成），故 2.4.6 与 2.9.2 同构，同为「既有能力延伸」。

### 2.5 域三：能力扩展

#### 2.5.1 多模型按需切换 ✅

`config.yaml` 的 `models.<name>` 任意新增，`config.py` 自动解析，**加模型零代码**。当前为手动指定，无自动路由。

#### 2.5.2 工具挂载 ✅

**已做**
- 框架：`tools/base.py`（BaseTool 护栏基类：超时强制 / 错误归一 ToolError / 执行日志）+ `registry.py` 注册 + `config.yaml` `enabled_tools` 开关
- 已挂：`shell` / `file_ops` / `web_search`
- `web_search`：Brave provider（可插拔），2026-09-04 真机验收通过（成功路径 + 关梯子单边挂降级路径双实测）
- **范围边界（首版）**：`web_search` 只取搜索结果的标题 / 摘要 / URL，**不做 `web_fetch` 正文抓取**（代价高：SSRF / 反爬 / 内容清洗 / 阻塞风险，复杂度高一个量级）

**计划（未定案）**：`../exchange/web-search-design.md` 有多 provider 按角色路由方案（Tavily / Brave / Wolfram）；当前共识是**先用 Brave 攒真实体感**，换 provider 因封装可插拔成本已封死。

#### 2.5.3 扩展性与零代码接入 ✅

- 加模型 → config 加段（2.5.1）
- 加工具 → 写类 + 登记（2.5.2）；第三方挂载契约已留接口
- 加角色 → config `roles` 段 + 重启，`GET /api/roles` 下发，**前端零改动**（2026-09-03 改造验证）

**未做**：以上定制目前只能改 `config.yaml`，无 UI 设置页（见 2.3.1）。

**方向提示 🗣️（老大裁定：MCP 是一个可以预留的扩展方向；零排期）**：2026 年工具连接的事实标准已收敛为 **MCP**（1 万+ 公开 server、SDK 月下载约 9700 万、OpenAI / Google / 微软 / AWS 全部原生支持、已捐赠 Linux 基金会）。
> ① **不需要推翻现有框架**：BaseTool + registry + `enabled_tools` 结构上就是干净的适配闸门，接 MCP client 的成本在协议握手与传输层，不在工具模型重构。
> ② **MCP 不外包安全**：行业实测仅 **12.9%** server 评为高信任；2026 年 1–2 月 30+ CVE；有跨租户泄漏与路径穿越事故；社区 server 安装失败率 30–50%。若接入，沿用 2.7.1 / 2.7.2 哲学——新 server **默认禁用、按需开启**。
> ③ **方向为「接入」**：本条当前指**接入**第三方 MCP server。反向（把本地能力经 MCP 暴露给其他 client）**未定**，与 2.10.2 端侧能力联动——若走暴露，端云边界会更清晰，但那是另一条决策，本稿不预设。

### 2.7 域五：边界与约束

#### 2.7.1 行为安全硬护栏 ✅

- `file_ops`：工作目录 `file_ops_workspace` 限制读写范围；文件不覆盖
- `shell`：命令黑名单 + IP 白名单 `shell_allowed_ips`
- `web_search`：SSRF 内网拦截 + 硬性超时
- 工具调用轮次上限（防失控循环）

**已知弱点**（`../TODO.md` 部署段原文）：ShellTool 黑名单为**字符串包含匹配、可穿透**，加固随「本地能力下沉」一并做（正则 / 词法解析或换沙箱）。

#### 2.7.2 边界透明与用户决策权 ✅

按 `../HUMAN.md` 原则 4（明确安全边界，而非由系统替用户管控）：白名单 / 黑名单 / 工具开关**全部 config 可调**，边界交给用户决策；工具调用过程以 ToolCallCard 展示（见 2.8.2）。

#### 2.7.3 凭据与密钥边界 ✅

`config.yaml` 含真实 key 且不入库（`.gitignore` 保护）、`config.example.yaml` 占位符；测试默认占位符、涉 key 路径需显式 `--real-api`；异常统一出口不泄漏内部信息；临时目录用后清理。

#### 2.7.4 成本约束 🚧

**已做**：`token_counter` 统计（**落日志，未入库**）+ `max_input_tokens` 截断 + 工具轮次上限，目前实质上的成本约束由老大在web search API和LLM API的服务商控制台操作和管控。

**未做**：无预算 / 限额 / 告警。`../TODO.md` 其他长期增强有「chat_service token 累计上限」，但老大标「优先级很低，不做主动处理」。

> **与 2.8.3 共享同一事实基座**：本条统计与 2.8.3 是同一件事的两种表述，当前均只落日志。这已保留将来做成本可见所需的**数据底座**——不提前建预算 / 告警系统（单用户下的主动成本管理是过度工程）。
> **最便宜的一档（留痕，未排期）**：行业量化记忆操作使 API 成本 +20–40%，通行做法是用 flash / haiku 级廉价模型做摘要与提取。本项目 `generate_summary(model=...)` 与 `ArchiveRequest.model` **均已透传**，走廉价模型分流只需加一条 config 默认策略，属零代码改动。

#### 2.7.5 数据主权与出境边界 📐

**计划**（`../exchange/deployment-architecture.md` 草案 + `../TODO.md` 部署段）
- 数据落云厂商磁盘；Embedding 在自有服务器跑
- **出境通道不止一条**：LLM API 是其一，**`web_search` 的查询词同样出境**（发往境外搜索服务商）。行业实证（MosaicLeaks，ServiceNow Research 2026-06）：搜索查询序列可被外部观察者反推用户正在研究什么——基础 agent 34% 查询泄漏信息，**能力越强的 agent 泄漏越多（51.7%）**。对健康 / 理财类个人助理尤其敏感：用户问「我这个指标要不要紧」时，**查询词本身就是健康信息**
- **处置口径（老大裁定）**：上述出境事实**如实陈述，但不作为待处理项**。理由：实际使用为多家 LLM + 多家 search 服务商混合，单一观察者难以拼出完整画像，且单一用户被盯上概率极低，按逃熊原则风险可接受；且处置决定权在用户（见 2.7.2 边界透明），问什么、用不用搜索、用哪个搜索API由用户自己定。
- **上云硬前置（不满足别上，共 4 条）**：① 强随机 `server.api_key`（P3.4 校验已就绪）② HTTPS（Nginx TLS 终止）③ 上云初期显式禁用 `shell` + `file_ops`（`enabled_tools: ["web_search"]`），防云端误操作云机器 ④ **最小备份 / 导出能力**（见 2.7.6，老大认可升格）

#### 2.7.6 数据可恢复与可迁移 🚧

**已做（技术事实，未作产品承诺）**：SQLite 为真相源、ChromaDB 可重建 → 数据不绑架于向量库；**会话**为软删除 + 回收站可恢复（2.3.1）。

**已知边界**：**记忆删除当前为硬删、不可恢复**（见 2.4.3，属设计决策而非缺口）；故「可恢复」目前只覆盖会话，不覆盖记忆。

**未做**：整体备份 / 导出 / 迁移 — TODO 无条目。

> **已升格为上云硬前置第 4 条（老大认可）**：本条不再等「上云后变重要」，而是**上云前必须闭环**——最小备份 / 导出能力与 2.7.5 的另三条并列。理由：数据可恢复可迁移是「数据不被绑架」里最硬的一条，且最容易「上了云才发现需要」，无过渡期。

#### 2.9.2 超长会话一致性 🚧

**现状**：`max_input_tokens` 截断旧消息 —— **机制方向是反的**（是丢弃，不是压缩）。这不是「做得不够好」，是方向做反。

> **不是从零开始，但两条管线不能互套（第 4 轮口径修正）**：会话内压缩与 2.4.2 归档摘要**共用同一条 LLM 摘要基础设施**（模型路由 / prompt 管理 / 调用管线），但**目标不同**：归档摘要是「对话 → 语义摘要 → 入库」（供检索后使用），会话内压缩须**保留可行动的精确信息**（路径 / 标识符 / 决策 / 错误串）。行业量化：生成式摘要的多会话信息保留仅 **37%**（丢路径 / 行号 / 错误串），逐字式 compaction 约 **98%** 保真。故本条仍属「既有能力延伸」，但**不能把 `SUMMARY_SYSTEM_PROMPT` 拿来就用**。
>
> **行业分级路径（成本由低到高，2026 已收敛）**：① **工具结果遮蔽**——旧工具输出换为结构化占位符，JetBrains 实测比纯 LLM 摘要性价比更高（成本 −52%、任务完成率不变），是**最划算的第一步**；② 历史摘要（技术同源，但**须单独设计 compaction 式 prompt 与保留策略**）；③ 滑动窗口兜底。
> 实现约束：工具调用与结果须**同存同弃**（原子组）；**错误轨迹不要压掉**（留着可避免重犯）。可选策略：保留头尾逐字 + 只压中间；被压缩历史 soft-hide 可搜索恢复（**后者本项目无设计**，与 2.4.3 同族，立项时再读）。

#### 2.9.3 降级与韧性 ✅

- ChromaDB 不可用 → 静默降级，不阻塞
- `web_search` 失败 / 限流 → 指数退避 → 降级为正常回答 + 「未能联网核实」，不报错不中断（2026-09-04 关梯子单边挂真机实测通过）
- LLM 网络请求 tenacity 重试
- 异常统一出口：`LarryException` → 统一 JSON，不泄漏内部

> **断网时的端侧可用性边界**：本条的「降级」指依赖不可用时的**软件行为**；「断网时什么仍可用」属**能力按端分布**问题，见 2.10.2——PC 端有本地文件 / 命令能力，云端 + 移动端 B/S 断网即不可用。
