## 三、P1 记忆系统（六子任务）

- 设计问答：Embedding 本地 vs OpenAI —— **"不是非用 OpenAI 不可"**；组件耦合性**低**、模型可换（`:8647`）；Qdrant 定位 = 存储 + 检索长期记忆（`:8734`）；讨论了记忆持续积累的规模控制。
- 客户端形态确认为 **PC C 型（本地文件能力）＋ 手机简问**（`:8850`）。
- 检索初参：**score_threshold = 0.5 起步**（QoderWork 曾建议 0.7；复核确认"都行、只是调参起点不同"）（`:9301`）。
- 实施链：P1.1 Embedding（bge-small-zh-v1.5 / 512 维 + 测试件）→ P1.2 向量库 CRUD（其后由 Qdrant **迁移 ChromaDB**："对个人 Agent 来说更合适"，`:13160`）→ P1.3 DB 补全 → P1.4 长期记忆检索 → P1.5 归档（**两步流程：摘要生成 → 用户确认后双写**，`:9026`）→ P1.6 端到端。
- ⭐ **召回阈值 0.5 → 0.3（2026-08-10）**：实测查询"我叫什么名字"与归档摘要相似度仅 **0.3573**、被 0.5 过滤 —— 建议降 0.3 并当场验证"成功召回"（`:16478` 等）；老大指示"改 0.3、并把调整优化与文件位置写进 TODO"（`:17862`）⇒ 落码 `engine.py::get_long_term_memory`（**现值至今 = 0.3**）。

## 六、框架调研（DSH 引入的起点）

- 起因：AI 协作治理成本讨论（"亲手写约束文件、划交流区……是微缩版的多智能体系统设计"，`:25705`）。
- 调研对象：Qoder Agent SDK／**DeepSeek Harness**／OpenAI Agents SDK／Claude Agent SDK／Google ADK／LangGraph／CrewAI／AutoGen／Smolagents／PydanticAI／Agno／Dify／Semantic Kernel／Haystack／MCP／Mastra（`:25733`、`:26577`）。
- **DSH 核心事实**："一切皆插件"（基于 Cordis）＋ 四种运行模式（标准／PTC／极简／创造）＋ 全链路 Trajectory 追踪 ＋ 会话/沙箱/压缩等开箱能力。
- **评估结论：不直接替换现有架构**（已有 P0-P4 成果，迁移是大工程）；借鉴点 = 上下文工程（压缩/快照/分叉）、全链路日志、图状态管理；当时并注 **"LarryAgent 的体量还小到可以直接手写这些特性"**（后随 DSH 迁移决策修订）。

## 七、Web Search 专项选型

- 结论：**"Brave 能用，但 Tavily 更适合你的场景"**（`:27016`）——Tavily 为 Agent 端到端优化（抓取＋提取＋引用），免费 1,000 次/月、付费 $27/月起；Brave 免费 2,000 次/月更宽裕但需自建正文提取（超量 $5-9/千次）；另评估 Serper／Exa／Google CSE。建议"Tavily 默认 ＋ Brave 备用，config 切换"。国内备选 = 火山引擎联网搜索。
- Brave 标注要求：须公开标明使用，但无位置硬性规定（`:27656`）。
- 数学/物理类：通用搜索引擎效果差（公式易被格式破坏），宜专门服务（Wolfram 类）（`:27927`）。
- 产出：`docs/web-search-design.md`（`:28203`）＋ 通义千问/DeepSeek 补充调研文档。
