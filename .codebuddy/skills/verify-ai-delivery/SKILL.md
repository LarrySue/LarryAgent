# 复核 AI 交付链

派发出去的任务收回来时，**验收以代码 / 日志 / 物证为证，不以任何 AI 的完成声明为证**。  
本技能把「回源取证」变成固定动作序列，避免被叙述层说服。

## 何时用

- 某个 AI 回报「做完了」「跑通了」「判过了」
- 用户说「他跑完了」「你看看结果」
- 需要对回传证据（日志 / JSON / 截图 / 归档）做可信度判定
- **升级依赖后要判「上游是否已自修」我方补丁**（补丁该不该退役 / 重跑复验）—— 见铁律 10 与判据「上游自修判定」

## 铁律

1. **读证据文件，不停在叙述层** —— 回报正文只是索引，结论要从原始输出里自己读出来。
2. **可复现 > 可解释** —— 能算 hash 的不肉眼比，能读物理文件的不信转述。
3. **「缺失」≠「致败」** —— 清单式缺失要分开统计（缺 5 个包、可能只有 3 个真致败）。
4. **归因要落到层** —— 判「与规格矛盾」时先问：这口锅归规格、归派发稿、还是归执行环境。
5. **不确定就写不确定** —— 「成因未知」是可接受的结论，别为叙事完整编一个。
6. **「回报里没写」≠「没做」** —— 回报正文是**索引**，不是全集。判「某观测**从未**做过」前，**必须先把回传件翻一遍**：原始日志 / JSON 里常留着收报人没写进表格的观测。⚠️ 实测教训：曾据回报正文判「该装置从未在坏环境跑过」，而回传件里**改前 / 半修状态的同一装置输出就在**（`initializeOk:false`）⇒ 结论错了一整条，据此给出的建议方向也偏了。
7. **能上机就上机，别把「证据在远端」当作可接受的边界** —— 回报说「在服务器 / 某机器上跑了」时，**优先用现成通道自己上机核原始件**（读 JSON、`readlink`、看目录实物、必要时重跑关键命令），比读回报强一个量级。⚠️ 通道**一律前台跑**（后台任务常拿不到沙箱放行）。  
   ⚠️ 上机之后**仍要留痕**：把原始件 `scp` 回本机存档（见 S2.5）—— **远端机器会到期，只读不回传 = 证据最终还是会丢**。
8. **「现象可复现」≠「结论成立」—— 还要核结论的基准** —— 判「应为 X 却是 Y」（装错版本 / 被污染 / 配置漂移）时，先做**对照实验**确认 **X 是不是真的应为 X**。⚠️ 实测教训：见依赖树里某包是旧版本，便据「顶层声明已升新版」判「代际污染」；而**正确基准是图解析结果（lockfile）**，不是「顶层声明」—— 换一棵确定干净的同配置环境一跑，发现那个旧版本**根本不该出现**，结论整条反掉。⇒ 凡「异常」判定，先问一句「**正常值我凭什么认定**」；「看到旧版本」**不等于**「装错了旧版本」。
9. **下「回归」结论前，先验证「修前基线」真的被恢复了** —— 比对新旧状态时，"修前"若只是**声称**恢复，那份对照就是**假的**，此时观察到的差异**不能**算作"新版本引入的问题"。⚠️ 实测教训：判「我的修复引入回归」时，先跑了一步"恢复修前状态"作对照 —— 而那条命令 **install 直接失败**（旧 lockfile 与 workspace 的 peer 声明不兼容，`0.0.1-rc.1 doesn't satisfy range "*"`），**"修前状态"根本没恢复**；把无效对照当有效，就会把**成因未知**误当**归因证据**。⇒ 环境类修复的对照，**恢复步骤失败一律记「无效对照」**，不得当作「修前也红」的证据；换手段重做（例：反向 —— 把新状态里可疑的那一项**钉回旧值**再跑，成败两侧都看）。
10. **「符号存在」≠「问题已修」—— 判它挂在哪个主体名下** —— 复核「**上游是否已自修**」（升级依赖后，我方补丁该不该退役）时，**不能只因在包里搜到了那个字符串就判「已修」**：同一字符串/现象常挂在**另一个主体**名下，语义完全相反。⚠️ 实测教训：判「015 是否已自修 Windows 沙箱方言缺口」时，`operation not permitted` 在新版包里**确实出现 1 处**——但它属 **`seatbelt`（macOS）** 的方言表，而 Windows 用的 `windows-acl` 名下**仍然没有它**；**不判归属就会得出「已修 ⇒ 补丁该退役」的反向结论**。   ⇒ 判「已修」须把符号**钉到主体**（哪个 runner / 哪条平台链 / 哪个分支）上，并**查全树确认无别的扩展点**（本例：扫 12105 个 js/ts 才敢说「签名表唯一一处」）。同族见铁律级判据「对照组出自哪个主体」。
11. **判他方「坏了」之前，先证明「你的判据在健康对象上会绿」** —— 判据自身有 bug 时会产出一整片 `FAIL`，看起来像对方的错，**且不会报错、只会静默假失败**。⚠️ 实测教训（2026-09-17，同一轮连撞两次）：
    - 在 **`.mjs`（ESM）里用裸 `require.resolve`** ⇒ `ReferenceError`（`e.code === undefined`，打印成 `FAIL undefined`）⇒ **5 条依赖全 "FAIL" 是假象**，差点误报「交付的依赖树是坏的」。修法 = `createRequire(import.meta.url)`。
    - **把 pnpm 的 scope 目录当「空壳」**（判据 = 目录存在 && 非链接 && 无 `package.json`）⇒ `@deepseek-ai` / `@types` **本来就没有 `package.json`**（它在 scope 下的包目录里）⇒ 对该层**必然假阳性**。⇒ 凡判据涉及目录/包布局，**先写清该工具的正常形态**（pnpm：**scope 目录是普通目录，其下的包条目才是链接**），空壳统计必须排除 scope 层。
    - **判「某章节/内容不存在」时，判据锚在编号字面上**（`.md` 里 grep `§3` / `§7` / `§8` 无命中 ⇒ 判「引用已失活」），而原文用的是**另一种编号形态**（`### 3.`、`#### Logo 设计定案`）⇒ 得到的是**假「缺失」**（与上两条同源，但表现为「明明在却判没有」）。⚠️ 实测（2026-09-17）：据此误报「`docs/ui-reference.md` 的『来源』标注已失活」，实际被引的「Logo 设计定案与迭代历程」「过渡动画方案」与 `### 0.`～`### 5.` 章节**都在原文里**。  
      ⇒ 判「内容不存在」**用语义 / 同义变体取证，不用编号字面**；且**先证明判据能命中同义的健康对象**（本例：拿一组确定存在的同义章节试跑，或改读全文标题列表人工比对）。**「编号对不上」只说明措辞不精确，不等于内容没了。**  
      ⇒ **同源**：铁律 9（先验修前基线）、判据「**「无输出」≠「失败」**」（下失败判定前先验证执行通道本身）——**「异常／失败」的第一嫌疑人是测量装置。**
12. **判「成败」不得取异常码 / 返回码，只取实际状态** —— 本机 Windows 上异常码与真实副作用**系统性不一致**（同族四例：回收站删除 API 报错而**实际删成功**｜`mklink` 报错而**目录实际存在**｜`os.symlink` 报 `WinError 2` 而**链接实际建成** `tag=0xa000000c`｜`git commit` 被沙箱判 **BLOCKED ＋ Exit 1 ＋ 无 stdout** 而**提交已写入**）。  
    ⇒ 判链接一律看 `os.lstat(p).st_reparse_tag` ＋ `os.readlink(p)`，**不看有没有抛异常**；⚠️ node 的 `lstat().reparseTag` 对 symlink 回 `0x0`（不填充）⇒ **判 reparse 类型走 Python 通道**。  
    ⚠️ 实测教训：曾据 `except` 分支判「本机建不出真符号链接 ⇒ isolated 布局不可用 ⇒ 须 `hoisted` 兜底」，**整条错、并据此向执行人下发了错误的自检指导**；实际是**抛假异常但链接建成**、默认装法完全可用 ⇒ 连带「两面环境结构不同」的推论也一起作废。
    - **`git commit` 那条是常态、不是故障**（2026-09-17 实测）：项目 `.git/hooks/post-commit` 装了 Qoder AI tracker（提交后启动 `Qoder.exe`），沙箱按 `reg.exe` 黑名单拦下该启动 ⇒ **每次提交都会报 BLOCKED**，而提交其实已完成 ⇒ **处置 = 不重试、不换 shell 绕过，直接 `git log --oneline -3` 核结果**；`git status`／`git log` 等只读命令不受影响。
    - ⚠️ **验 shell 脚本改动的两条可用通道**（本机 shim 常致解释器/工具缺失）：① **语法** —— `bash -n` 会被 PATH shim 解析到 WSL（黑名单拦截）⇒ 改用**当前 Bash 会话内 `( . <片段> )`，片段首行 `set -n`**，可「只解析不执行」（零副作用）；② **展开** —— 抽被测命令行、把 `node` 换 `echo` 并**去掉 `| tail`** 再跑（本机 shim 常缺 `tail`，会让输出整段丢失而**伪装成「没输出」**）。

- 🔴 **复核动作自身也会改现场 —— 收尾必须核 `git status`，不能只报结论**。两条实测（2026-09-17 同轮）：  
  ① **`python -c "…"` 里塞含反引号 / `$()` 的多行文本 ⇒ 不只是"命令失败"，而是在仓库根目录凭空建出垃圾文件**：`-c` 载荷里的反引号被宿主编排器当**命令替换**先执行 ⇒ 报出一串 `command not found` / `syntax error`；更隐蔽的是**未加引号的行被当成重定向目标**，在仓库根下建出 **2 个 0 字节文件**（文件名就是那段规则原文），于是 `git status` 多出 2 条 `??`，**不核就会被误当成"别人放的未跟踪文件"带进后续判断**。  
  ⇒ 纪律：含反引号 / `$()` / 多行的文本**一律先 Write 成 `.py` 载体再跑**（⛔ 不塞 `-c "…"`、⛔ 只转义一部分）；**任何带引号嵌套的写操作之后立刻 `git status` 复核**；清理误建文件&#x6309;**「确名 ＋ 0 字节」双条件定向删**，⛔ 不用通配。  
  ② **"我核过的东西没被动过"是断言，不是默认** —— 复核期间的写操作（脚本输出落盘、`scp` 回传、临时目录）都可能落在被测目录里。⇒ 交付结论前把 `git status --porcelain` 跑一遍：**clean 才算复核收尾完成**；有脏项要能逐条说明"这是我加的 / 这是本来就有的"。

13. **出稿方义务：自己下发的判据/前提也要复验，被推翻就回填稿件本体** —— 派发稿里的前提错了，会变成执行方的额外负担（他得先顶住"照稿执行"的惯性、再自己花时间暴露矛盾）。两条硬规矩：
   - **写验收判据必须写明期望方向与出处**（绿／红、以及"红因须是 X"），⛔ 禁止用「同上」「三条同上」这类省略 —— 负向哨兵（故意污染环境、期望被守卫拦下）**期望值就是红**，省略式写法会让复验者按字面把红哨兵当失败。
   - **执行方报出"你的记载与我的实测矛盾"时**，出稿方须**回源复核**（自己重跑或找独立通道），**并把订正回填到稿件本体**，⛔ 不能只在回报/对话里说明 —— 稿件是后来者唯一会读的东西。实测（2026-09-17）：一次派发稿里同时含 ① 错误的环境前提（symlink）② 写反的哨兵期望值，两处都在回报后被订正回填。
14. **证据资格只看「可验证性」，不看来源身份**（自 MEMORY 证据纪律收敛，2026-10-08）—— 一条陈述算不算数，由它**能不能被验证**决定，与说话人是谁／资历／语气无关。
   - **身份不为证据加权**：同一句话出自"专家／官方／资深同事"与出自"随口一说"，证据等级**相同**，区别只在**验证成本**。
   - **闲聊层 ≠ 决策层**：对话里的推测、直觉、随口判断默认归**闲聊层**，⛔ 不进结论区、不作决策依据；要进结论区必须**补证据或补逻辑**。
   - **写"采纳／定调"前先问一句「证据是什么」**：写不出证据支点就**拒收**，而不是给它套上"洞察／方法论／升格候选"的外壳。⚠️ 危险性在于**给闲聊套上权威外壳后它会自我繁殖**（派生出更多看似有据的结论）。
   - **反向检查**：发现某结论的支撑是"某某说过"而非"数据／代码显示"时，**立即显式暴露**。
   - **论据真实 ≠ 论据适用**：核实外部论据须先核**来源是否真实**，再核**场景是否匹配**；只看第一步 ⇒ "有引用即采信"（第二类证据污染）。
   - **代码复核属「文献证据」，不是「执行证据」** —— 读源码／文档／笔记只能证明「**代码里写了什么**」，证不了「**运行时真的发生什么**」；两者证据等级不同。⇒ 凡结论出自代码复核，须**显式标注为文献级**，且**转写／升格进权威文档时必须逐条保留该标注**，⛔ 不得在同一次改写里被拔高成执行级。（实例 2026-09-15：我方四稿全部是文献证据、**没跑过**。）

## 动作序列

### S0 · 取实况（不看快照）

```bash
git status --porcelain && git log --oneline -3
```

同时取回报文件的规模 / 章节结构 —— 规模突变本身就是线索（例如回报区从 199 行被清成 25 行 ⇒ 有人在改）。

### S1 · 读回报全文（**不截断**）

长行必须完整读。**截断预览会导致误判**：曾因 grep 预览截断，把"某条已有承接"误判成"无家"。

### S2 · 点物证

回传件是否存在、数量、大小对不对得上回报里的声明。  
**能读到物理文件是最高等级证据** —— 优先核这些，而非回报里的表格。

```bash
python scripts/scan_evidence.py list <证据目录>
```

### S2.5 · 原始件回传（远端产物必须落到本机）

远端产物（`~/<proj>/results/` 之类）**不能只留在远机上**：机器会到期，而且**只有回到本机才能用你自己的扫描器**做 Tier0。

```bash
scp -i <key> -o BatchMode=yes -r user@host:~/<proj>/ "<本地证据目录>/"
# 回传后逐件比对字节，确认传输无损（远程 find -printf "%P %s" ↔ 本地 os.path.getsize）
```

⚠️ 常见坑：本机 Python 不认 MSYS 风格路径（`open('/tmp/x')` 会解析成 `C:/tmp/x`）⇒ 临时文件写**盘符路径**。

### S3 · Tier0 安全自查（**由复核方自己做，不采信对方的自检声明**）

扫凭据形态串（`sk-…` / `Bearer` / `password` / `secret`）。

**判法（关键）**：**算命中串的 sha256 与已知占位符比对 + 看长度与字符类分布**，  
**绝不打印命中值** —— 打印即泄密。

- 真 key 形态 = 固定长度 + 固定字符集（如 `sk-` + 32 位 hex）
- 占位/脱敏正则 = 长度与字符类不符（如 `sk-` + 36 位含 `g-z`）
- 复现已知占位符的 sha256 前缀 ⇒ 直接判定为无害

```bash
python scripts/scan_evidence.py scan <证据目录>          # 只报 sha/长度/字符类，不回显
python scripts/scan_evidence.py sha <候选串>...          # 与已知占位符比对
```

⚠️ **纪律的边界是「凭据载体」这一类别，不是某个文件名**（实测事故 2026-09-17）：既有纪律只写了「查 `backend/config.yaml` 按键名定位、禁止整段 cat」，于是查**另一个**凭据载体（`$DSH_HOME/.credentials.yaml`）时就回到了"临场判断要不要脱敏"——过滤写成"打印任何 `键:` 行"，把 `records[].payload.secret` 的值打进了工具输出。

⇒ 凡触碰凭据载体（`*credential*` ／ `*.env` ／ `*secret*` ／ `config.yaml` ／ 任何 `key:`·`secret:` 字段）：**脱敏写成脚本的默认行为**（打印前一律正则替换为 `<REDACTED:n>`），不靠"我这次只列键名"的自觉；**要判"是不是同一个值"用 sha256 前缀比对，不用肉眼看值。**

### S4 · 同形性判定（**归一化后逐字节比** ／ 同路径时用 sha256）

「多态表现相同 / 不同」这类判定，**别靠肉眼，也别只看字节数**：

- **路径不同的同形** —— 先把各样本的路径替换成占位符（`<HOME>` / `<H>` 等）**再逐字节比对**。  
  ⚠️ 实测教训：两个 home 的 stderr 是 15247 vs 15499 B（差 252），看似不同；**归一化后完全相同** —— 252 = 路径名长度差 6 字符 × 出现 42 次。⇒ **只看字节数会把"同形"误判成"有差异"**，结论直接反掉。
- **同路径的多态** —— 逐文件 sha256：全同 = 铁证；不同 ⇒ 差异点就是变量所在。

```bash
python scripts/scan_evidence.py same <文件1> <文件2> ...
```

⚠️ 判「同形」的**比较面要选对**：本轮的比较面是 **stderr 全文归一化后比对**，而非 `exit code` / `stdout` 字节数 —— 后者在多个态下**本来就无判别力**（同一装置 `stdout` 3.4~3.7 万 B 跨态只差几百）。先问「这个面能不能区分我要区分的两态」，再比。

### S5 · 栈帧归属（最高价值的一步）

崩溃 / 报错的 **stack 里的包路径**能直接回答「**崩在哪一层的哪一版代码**」，  
比任何结论表述都硬。典型收获：结论只说「A 与 B 跨代」，  
栈帧却显示 **C 层也在执行路径上** ⇒ 直接影响修复方案的可行性评估。

```bash
# 从原始 stderr / json 里提包路径
grep -oE '[^/ ]+/\.pnpm/@[^/]+@[0-9][^/]*' <stderr文件> | sort -u
```

### S6 · 对照规格原文

回报里写「与规格矛盾」时，**去读规格原文**，判锅归谁：

- 规格**已预言**该结果 ⇒ 不是规格错，是**执行者没读全**或**派发稿没承接**
- 规格**确实没写** ⇒ 才是规格缺陷
- 注意**门禁条件在动作前是否可满足**（例：「装前核代际」而对象为空壳 ⇒ 该门禁装前必然不可满足）

### S7 · 输出与收口

**四块，结论先行：**

1. **判定**（成立 / 部分成立 / 不成立）+ 一句话根因
2. **独立复核过的**（我实际核了什么、用什么方法核的）
3. **增量**（对方未报 / 表述不全的，按重要性排）+ **待拍事项**
4. **收口** —— **判定＝成立时才做**（含"带订正 / 带增量"的成立；**不成立 ⇒ 退回重派、不标完成**）。复验不是终点，判定完还要把结果送进它该去的地方。三步，**只有第 ① 步是 WB 亲手做**：
   - ① **标 `TODO.md`** —— 把对应条目**改为已完成**（附必要说明）。WB 自己的活。
   - ② **通知 Qoder 同步 `docs/`** —— 依执行实际同步（「一体两面」的文档面）。`docs/**` 归他，WB 只交接。
   - ③ **阶段收尾时通知 Qoder 归档** —— 大如 DSH-2、小如 DSH-3.3 收尾时，把该段 TODO 归档进 `archive/roadmap-history.md`。归档同样归他。
   - ⚠️ **WB 只亲自改 `TODO.md`**（归属表见 `docs/ai-governance.md` §3）⇒ ②③ 是**交接动作**、不是自己动手。⛔ **别"复验完就散"** —— 判定成立却没通知，TODO 会**烂在面板里**、`docs` 侧口径不更新（这正是「一处两面跨职责」必须有同步协议的原因）。
   - ⚠️ **复验结论的落点在 `docs/`（归 Qoder）** ⇒ 通知里要把结论**写全**（判定 ＋ 判据 ＋ 证据出处），⛔ 不能只丢一句"复验通过"。
   - **边界 —— 一次性小修不走这条链**：派发时若已定「闭环即消、⛔ 不进 `TODO.md` ／ `docs/`」（单点小修），收口只做**在被派发方 log 的状态行升级为「已复验成立」**，⛔ 不为它新建 TODO 条目再走一遍交接。

| **⛔「行数 ＋ 体积」两个数字要验互斥** ★ | 报告给形如「**N 行 ／ M 字符**」的量化时，**两个数字可能互斥** ⇒ 用**滑块反推**：枚举该文件**所有 N 行窗口**，看字符数的取值域。实测（2026-09-22）：报告称「`### 待派发` = **92 行 ／ 24,030 字符**」；同区间实测 **21,450 字符**，且该文件**任意 92 行窗口的字符数上限 ≈ 21,500**（全文均 168 字符/行）⇒ **24,030 与"92 行"不可能同时成立**（也不是字节口径 —— 该区间字节 = 36,241）。⇒ 凡"行数 ＋ 体积"成对出现，**先验互斥性**；单个数字错了会连带把「占比 ／ 可压缩量」算歪。 |  
| **⛔ 数字对不上时先反查「读数时点」** ★ | 报告数字与实测不符时**别急着判"算错"** —— 先 `git show <commit>:<file> \| wc -l`／`wc -c` **逐提交比对**，把它的样本**定位到某个 commit**。实测（2026-09-22）：一份巡检报告同稿给出「文件 610 行 ／ 173,502 字节」（= 提交 `05ba554`）与「`:568` 已写『3.7.5 · 已回报 · 待 WB 复验』」；而该行内容在 `05ba554` 是「已派发 · 待回报」、在下一个提交 `ed9ae77` 是「已回报并复验」⇒ **两版都不成立**，只在**对方提交前的工作区中间态**成立 ⇒ **同一报告内混用两个时点**（一处引未提交的工作区、一处引已提交快照）。⇒ 复验结论要**钉住读数时点**；反之，**任何报告都该自报「读数时点 = `<commit>` ／ 工作区是否有未提交改动」** —— 在"用户实时改文件"的协作节奏下，这是可复现性的最低要求。 |

| **⛔ 扫引用面前先分「同名不同物」** ★ | 做"谁引用了 X"的扫描时，**先列出 X 的所有同形异义写法**再定匹配式 —— 否则清单**必然两个方向都错**。实测（2026-09-22）：报告要清点"归档 `TODO.md` 的 `DSH-3.0` 块在区外被引用多少处"，它用**前缀式**匹配（连 `DSH-3.0.2` 一起命中）⇒ ① 把 `§3.0`（指 `dsh-migration.md` 的**章节号**，与本块无关）误纳；② 漏掉裸写法 `3.0`（实测另有 **8 处**未列）。⚠️ 讽刺之处：**该报告自己的另一节正在提出"上游路径与本仓库路径同名无区分"是系统性缺陷** ⇒ **"报告的缺陷恰好是它自己指出的那类问题"是这类错误的典型信号**，见到就往下查。⇒ 核法：**同形词分列 → 各自定匹配式 → 命中后逐处判性质（借地址 ／ 仅提及）**。 |  
| **判「表述未承接」前先通读同文件邻近段** | 指控"某处表述未承接新变更"时，**先看同一文件后面是否已有承接** —— 否则会**过报**。实测（2026-09-22）：报告指 `production-env.md:531`【凭据落在 A、可运行 profile 落在 B —— 两者被劈开】因该 profile 被删而"事实基础消失"；而**同文件 `:537` 已显式写**「✅ 现状（2026-09-16）：…『劈开』这一形态**在 CVM 侧已消除**」⇒ `:531` 是**历史论述**、上下文自洽 ⇒ 该指控**过报**（应降为"加一句指向 `:537` 的指针"）。⇒ 判据 = **该文件内是否已有承接**，不能只看被指控的那一行。 |  
| **⛔ 阴性证据先查「产生它的分支条件」（防构造性恒真）** ★ | 拿到 `X === false` 这类**阴性证据**时，**先读产生它的代码分支** —— 若该分支被装置自己关掉了，这条证据就**恒真、无判别力**。实测（2026-09-22，复验 driver「能自己退出」）：装置把 `forceAfterMs: 0`（⛔ 永不 force），而源码是 `if (!exited && forceAfterMs > 0) { … forced = true }` ⇒ 分支不可达 ⇒ `forced`／`killCalled` **必然 false**，与"被测对象是否真自退"**无关**；报告把它列为自退证据之一（不是错，是恒真）。⇒ 判据链要有**判别力**：本例真正管用的是 `beforeExit` 触发（`process.exit()` 不触发它 —— 实测两次 `node -e` 对照成立）＋ 监督侧看门狗未触发 ＋ 子进程真退出。⇒ 同族：`killedByHarness=false`／`watchdogFired=false` 这类"装置没动手"的字段，**要先问装置是否本就没能力动手**。 |
