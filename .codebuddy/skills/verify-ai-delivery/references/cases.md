## 铁律案例（T）

### C-T6 · 「回报里没写」≠「没做」
曾据回报正文判「该装置从未在坏环境跑过」，而回传件里**改前 / 半修状态的同一装置输出就在**（`initializeOk:false`）⇒ 结论错了一整条，据此给出的建议方向也偏了。

### C-T8 · 「现象可复现」≠「结论成立」
见依赖树里某包是旧版本，便据「顶层声明已升新版」判「代际污染」；而**正确基准是图解析结果（lockfile）**，不是「顶层声明」—— 换一棵确定干净的同配置环境一跑，发现那个旧版本**根本不该出现**，结论整条反掉。

### C-T9 · 先验证「修前基线」
判「我的修复引入回归」时，先跑了一步"恢复修前状态"作对照 —— 而那条命令 **install 直接失败**（旧 lockfile 与 workspace 的 peer 声明不兼容，`0.0.1-rc.1 doesn't satisfy range "*"`），**"修前状态"根本没恢复**；把无效对照当有效，就会把**成因未知**误当**归因证据**。

### C-T10 · 「符号存在」≠「已修」
判「015 是否已自修 Windows 沙箱方言缺口」时，`operation not permitted` 在新版包里**确实出现 1 处**——但它属 **`seatbelt`（macOS）** 的方言表，而 Windows 用的 `windows-acl` 名下**仍然没有它**；**不判归属就会得出「已修 ⇒ 补丁该退役」的反向结论**。
本例：**扫 12105 个 js/ts** 才敢说「签名表唯一一处」。

### C-T11 · 判他方「坏了」前先验判据（2026-09-17，同一轮连撞两次）
- 在 **`.mjs`（ESM）里用裸 `require.resolve`** ⇒ `ReferenceError`（`e.code === undefined`，打印成 `FAIL undefined`）⇒ **5 条依赖全 "FAIL" 是假象**，差点误报「交付的依赖树是坏的」。修法 = `createRequire(import.meta.url)`。
- **把 pnpm 的 scope 目录当「空壳」**（判据 = 目录存在 && 非链接 && 无 `package.json`）⇒ `@deepseek-ai` / `@types` **本来就没有 `package.json`**（它在 scope 下的包目录里）⇒ 对该层**必然假阳性**。pnpm 正常形态：**scope 目录是普通目录，其下的包条目才是链接**。
- **判「某章节/内容不存在」时锚在编号字面上**（`.md` 里 grep `§3` / `§7` / `§8` 无命中 ⇒ 判「引用已失活」），而原文用的是**另一种编号形态**（`### 3.`、`#### Logo 设计定案`）⇒ **假「缺失」**。实测：据此误报「`docs/ui-reference.md` 的『来源』标注已失活」，实际被引的「Logo 设计定案与迭代历程」「过渡动画方案」与 `### 0.`～`### 5.` 章节**都在原文里**。
- **再反向：grep 命中 ≠ 内容在** —— 命中的可能是「禁止再出现该串」类**注释**（2026-09-22 实测：核「旧硬编码串已消失」时，唯一命中恰是该行自己的禁令注释）。

### C-T12 · 判「成败」不得取异常码 / 返回码（本机 Windows 系统性不一致，四例）
回收站删除 API 报错而**实际删成功**｜`mklink` 报错而**目录实际存在**｜`os.symlink` 报 `WinError 2` 而**链接实际建成**（`tag=0xa000000c`）｜`git commit` 被沙箱判 **BLOCKED ＋ Exit 1 ＋ 无 stdout** 而**提交已写入**。
⚠️ 曾据 `except` 分支判「本机建不出真符号链接 ⇒ isolated 布局不可用 ⇒ 须 `hoisted` 兜底」，**整条错、并据此向执行人下发了错误的自检指导**；实际是**抛假异常但链接建成**、默认装法完全可用 ⇒ 连带「两面环境结构不同」的推论也一起作废。
- **`git commit` 那条是常态、不是故障**（2026-09-17 实测）：项目 `.git/hooks/post-commit` 装了 Qoder AI tracker（提交后启动 `Qoder.exe`），沙箱按 `reg.exe` 黑名单拦下该启动 ⇒ **每次提交都会报 BLOCKED**，而提交其实已完成 ⇒ **处置 = 不重试、不换 shell 绕过，直接 `git log --oneline -3` 核结果**；`git status`／`git log` 等只读命令不受影响。
- ⚠️ **验 shell 脚本改动的两条可用通道**（本机 shim 常致解释器/工具缺失）：① **语法** —— `bash -n` 会被 PATH shim 解析到 WSL（黑名单拦截）⇒ 改用**当前 Bash 会话内 `( . <片段> )`，片段首行 `set -n`**，可「只解析不执行」（零副作用）；② **展开** —— 抽被测命令行、把 `node` 换 `echo` 并**去掉 `| tail`** 再跑（本机 shim 常缺 `tail`，会让输出整段丢失而**伪装成「没输出」**）。

### C-T13 · 出稿方义务
一次派发稿里**同时含 ① 错误的环境前提（symlink）② 写反的哨兵期望值**，两处都在回报后被订正回填。

### C-S4 · 同形性判定（比较面）

## A · 证据与通道（观测取自哪个对象 / 哪条通道）

### C-A1 · 通道隔离
WSL 内裸跑 `node`：一条通道命中 Windows 版、另一条 `command not found`。

### C-A2 · 观测要核到对象层（2026-09-17）
执行方把「profile 的依赖解析到全局 npm dsh」（**全局 home** 的 junction 机制）当成「**工程 `.dsh-home`** 落点」的机制，而后者 **241 条 junction 全指本仓库 `.pnpm`**。

### C-A3 · 「某文件没有 X」前先问读的是哪一面的副本（2026-09-17）
执行方判「`run-s0-e2e.mjs` 没有构建前置检查」，而**本机 `:40-61` 有**（远端是滞后副本）⇒ 差点据此去「回填」一个**本来就没缺**的东西。

### C-A4 · 配置里的名字 ≠ 生产走的那条（2026-09-17）
落点被定在 `larry`，而 `client/src-tauri/src/main.rs` 实际 spawn 的脚本里**硬钉 `profile: 'sdk'`**（脚本头注释明写"client 跑的就是它"）⇒ `larry` 全仓零使用。

### C-A5 · 「哪一次运行产生的」只认运行自报的标识
同一目录下 8 个会话 = 4 次运行。按 mtime 两两分组会得出**符号相反**的结论（"负向对照态也出现了 marker"）。**唯一锚点 = 该次运行自己落盘的 id**（实测：`dsh-prompt.mjs` 的 stderr `[dsh-prompt] session=…`）。

### C-A6 · 「证据原文」也可能被后处理
交付证据里凡含**本地化工具输出**（`taskkill` ／ `tasklist` ／ `qwinsta` 等）的件，须**同机跑同命令取原始字节**比对：中文 Windows 上这类输出**恒为 GBK**（`GetACP=936`），而 `spawnSync(…,{encoding:'utf8'})` 读它必得乱码 ⇒ **证据里出现英文 = 不是该进程的原始产物**（另有 BOM 等手工痕迹可佐证）。⛔ 结论可以照样成立（自己复跑即可），但**这批件的"原文"不可采信**。

### C-A7 · 换一条通道／环境复跑，专抓「硬编码字面量」（2026-09-22）
同一份验收脚本里 ① `preflight.channel` 写死 "`Po` + `werShell/system（本机直跑 node）`" ⇒ 复验方走 **Bash 通道**跑，输出**仍是该串** ⇒ 该字段**不能承担「注明取自哪条通道」的职能**；② 判据 detail 写死「本轮跑在**有 key** 的环境下」⇒ 复验方**无 key** 跑 ⇒ 打印 `envKeyPresent=false（…本轮跑在有 key 的环境下…）` **同句自相矛盾**。⇒ 两者都**不影响判据成立**（PASS 依据是别的字段），但**报告文本会在别的环境撒谎**。

### C-A8 · 落点层级 > 包声明（2026-09-17）
`createRequire.resolve` 三个起点，**同一份插件、仅换层**：落 `profiles/node_modules/…` 共享层 ⇒ 命中 **`0.0.1-rc.1`**（旧代，`import` 即崩）；落 `profiles/<p>/node_modules/…` ⇒ 命中 **`0.1.5-rc.2`**。

### C-A9 · 「能解析」≠「解析到对的那份」（2026-09-17）
`plugin-sandbox-dialect` 的 peer `@deepseek-ai/dsh-sandbox-local: "*"` ⇒ pnpm 解析到 **`0.0.1-rc.1`**（同树 `dsh-llm` 是 `0.1.5-rc.2`）⇒ **跨代混装、`import` 即崩**。
**宽范围 specifier 的隐藏语义**：node-semver 下 `satisfies('0.0.1-rc.1','*') === false` ⇒ `peerDependencies: "*"` 既让解析**落到 prerelease 的旧代**，也让 `--frozen-lockfile` 校验报 `doesn't satisfy range "*"`（**拒绝主体是未派包 mount-probe**，却被归因成「刚同步的那个包」）。⚠️ `--no-frozen-lockfile` 只**跳过校验**、不修根因。

### C-A10 · 分帧/压缩日志「读到半截」不报错
DSH 的 `session.v3.jsonl.zstd` = **9 个 zstd frame**；「一次解压」读时 **`zstdDecompressSync` 与 `createZstdDecompress` 都只解第一帧** ⇒ 得 **179 B / 1 行**的「合法小文件」，看起来像「日志里就是没有那条」。**正解 = 按 magic（`28 B5 2F FD`）切分逐帧解**。

### C-A11 · 「取到空值」先怀疑路径
字段取不到有多种可能，**不一定是真的没有** —— 先核取值路径（层级／大小写／同名异义／是否包在别的容器里）。

## B · 判据自身：先怀疑测量装置

### C-B2 · 判据取自「真实运行时」
运行时可能不是你认为的那个运行时（替身 / 本地版 / 仿真跑出的观察**不可外推**）。

### C-B3 · 「机制存在」≠「实现真的走这条路」
源码里读到一个机制（超时／重试／回退／守卫），**不等于**该次执行真的走了它。须**实测正反两组 ＋ 反向对照**，并**读源码确认负结果的精确含义**（"没触发"不等于"不存在"）。

### C-B4 · 「无输出」≠「失败」
工具层故障（超时被杀／管道丢失／编码乱码）会**伪装成被测对象的超时或崩溃** ⇒ 下失败判定前**先跑一条必成功的对照命令**，确认能看到它的输出。

### C-B5 · 阴性证据先查「产生它的分支条件」（防构造性恒真）（2026-09-22，复验 driver「能自己退出」）
装置把 `forceAfterMs: 0`（⛔ 永不 force），而源码是 `if (!exited && forceAfterMs > 0) { … forced = true }` ⇒ 分支不可达 ⇒ `forced`／`killCalled` **必然 false**，与"被测对象是否真自退"**无关**；报告把它列为自退证据之一（不是错，是恒真）。⇒ 本例真正管用的是 `beforeExit` 触发（`process.exit()` 不触发它 —— 实测两次 `node -e` 对照成立）＋ 监督侧看门狗未触发 ＋ 子进程真退出。
同族：`killedByHarness=false`／`watchdogFired=false` 这类"装置没动手"的字段，**要先问装置是否本就没能力动手**。

### C-B6 · 判据字段会因「问题已修」而失去判别力（2026-09-21）
`selfVisibleAtApply` 在改为「provide 挂 root」后**所有样本恒 `true`**（root fiber 恒 ACTIVE），**已无判别力**；真正的对照只剩修前/修后的 `injectedAnswerer`（`false`→`true`）。

### C-B7 · 装置「全绿」≠ 判据全被覆盖（2026-09-21）
runner 对五条用例只 `saveJson('J3-cases.json')`、**无一句 `judge()` 断言期望值** ⇒ 复验方**必须自力比对期望表**，⛔ 别看 `verdict=判据成立` 就以为覆盖了。核法 = **读装置源码，列出它到底 `judge()` 了哪几条**，与「判据清单」做差集。

### C-B8 · 判据的「用例名」可能把机制钉错主体（2026-09-21）
清单写「**answerer 超时**」，而 `decide()`（`lib/index.js:175-192`）里**没有任何超时计时器**，唯一"放下"机制是**请求侧 `AbortSignal` 撤回**（`signal` 与应答赛跑 ⇒ `cancelled`）。⇒ 订正以「规格措辞 ＋ 实测机制」**双依据**为准（规格写的是中性的「超时」，是被订正对象把它加严成了「answerer 超时」）。

### C-B9 · 探针 API 的语义会自造假读数
用"**创建或打开**"语义的 API（`CreateSemaphoreW`）判"内核对象是否存在/是否被占"**会自造对象** ⇒ 恒得"空闲"（`wait=0`），且看起来完全自洽。⇒ 须改用"**只打开**"语义（`OpenSemaphoreW`），并配**正对照**（对**已知存在**的对象打开应成功）＋**反向对照**（同进程同名字连调两次，第二次应"被占"）。

### C-B10 · 负向对照须双锚（＋ 破坏面须实测）（2026-09-17）
两条变体只断言 `④=false`，若会话日志根本没被创建，同样 PASS；补 `②_activated===true` ＋ `logPresent===false`（负向 3）／`logPresent===true && bytes>0` ＋ `killedBy!=='child-exited-first'`（负向 4）。
⚠️ **破坏面大于其名**：`no-session-dir` 名为"打掉 ④"，实测 **③ 也红**（`turnEndKind=error` / 模型根本没被调到，因只读落盘目录令 **session 创建即失败**）。
⚠️ **别把实现副作用写成断言**（该变体注释须写明"别断言 ③ 必须绿"，否则 DSH 一改实现就假红）。

### C-B11 · 判据改动 = 改测量装置 ⇒ 必须实跑（2026-09-17）
补锚后在真实场地把两个变体**各跑一遍**（均 exit=0）才敢说加固成立 —— 查证据只证明「该字段当前为真」，**证不了「新断言不误伤」**。

### C-B12 · 自写取证脚本的「口径缺陷」会产出恒假结论（2026-09-17，**同一类缺陷连踩两次**）
判「树里有没有某个包」时 ① 用目录名解析包名（`+` 未还原成 `/`）② 用「子串包含」判定 —— 而 pnpm 的 `.pnpm` 目录名是**截断名**且**截断名恰为全长名的前缀** ⇒ 判定**恒为真**，输出「孤儿 = 0」这种**看起来很干净的结果**。**正解 = 读被检对象的权威字段**（读 `package.json` 的 `name`），不用路径名反推。

### C-B13 · 装置的「自曝 note」要与 before/after 实物对照（2026-09-21）
`bundles.json` 的 note 写「重排是为让远端答者先于 3.3-a 答者 apply」，而 `before` 里二者次序**已满足**该条件，重排的**实际差异是另外两项互换**。⇒ 结论不受影响，但**照 note 复现会困惑**。核法：**`after − before` 的差集才是「这个动作真正改了什么」**。

### C-B14 · 稳定量 vs 运行变量（含「尺寸差不可当判据」）
- **尺寸差**（2026-09-17）：同一装置两态的差异量先测为 **240 B**、后测为 **246 B**；更典型的是**「模型复述」面的长度随 run 变、甚至方向相反**（unpatched 1156 ／ patched 1152）⇒ 把一次 run 的尺寸差当规律，会写出**永远不可复现的判据**。
- **采样条数**（2026-09-21）：同一臂两次运行，`remote-pending-sample` 一次 5 条、一次 4 条（后段采样被收工截断）⇒ 拿"采样条数"当判据就会**假红**。

## C · 结论的适用范围

### C-C1 · 缺陷定性是「全称」还是「部分」（2026-09-29，复验 DSH-3.4 探针）
报告称 `ev?.data?.message?.source` 是**"死字段、恒 null"**，我当时采信并写进了 `TODO.md` 与记忆；实读 `session/types.ts`「SessionEventMap」后其实是**覆盖不全** —— `user/message` 的 payload **直是** `UserMessage`（`source` 在 **`data` 顶层**），只有 `system/message` ／ `assistant/message` ／ `tool/result` 三类才包 `{ turn, step, message: XMessage }`（`source` 在 **`data.message`**）⇒ 该表达式**对三类有效**。
核法（双向）：① **分类型样本逐类跑**；② **回原始数据数分布**（35 份 snapshot 的 `nodeEvents`：system 35/35 ＋ assistant 57/57 有值、user 0/92 ⇒ 不是"数据里没有"，是**取法丢了**；旁证 `messages[]` 侧同口径字段 user 亦 92/92 非 null）。

### C-C2 · 「影响面」断言须先 grep 定义点（2026-09-17）
记为「凡依赖 `installPlugin` 的**本机**装置都跑不起来」，实际该函数**全仓只 1 处定义、1 处调用**（`s0-e2e.test.ts:92` ／ `:246`）⇒ 真结论是「**那一个装置**跑不起来」。⚠️ **过宽的影响面双向有害**：向上**夸大严重性**、向下**给出错误的作业边界**。

### C-C3 · 「发生过」≠「只在那种条件下发生」
复盘成因时**分两栏写**：**首次触发条件** 与 **根因成立条件**。

### C-C4 · 「偶发」的定性须先数次数（2026-09-17→18）
旧登记写「同机**另有**一次运行走了 X 路径」，全量盘点后实为 **6 次且严格成对** —— **不是偶发、是可重复的双发模式**。同族风险：**样本漏数**（旧登记只数到 8 个会话，实为 20 个，漏一半以上）⇒ **「已知样本数」本身须现场重新盘点**，不采信台账数字。

### C-C5 · 修正性实验的结论必须限定路径

## G · 复核动作的副作用与现场

### C-G1 · 复核动作自身会改现场（2026-09-17 同轮两条）
① **`python -c "…"` 里塞含反引号 / `$()` 的多行文本 ⇒ 在仓库根目录凭空建出垃圾文件**：`-c` 载荷里的反引号被宿主编排器当**命令替换**先执行 ⇒ 报出一串 `command not found` / `syntax error`；更隐蔽的是**未加引号的行被当成重定向目标**，在仓库根下建出 **2 个 0 字节文件**（文件名就是那段规则原文），于是 `git status` 多出 2 条 `??`。
