# 已闭环待办的归档瘦身

> ⛔ **执行权已移交（2026-10-13 老大裁定）**：**归档动作归 Qoder** —— `archive/**` 归他（含本技能的落点 `archive/roadmap-history.md`）。**WB 侧不再执行本技能**：WB 复验后只改 `TODO.md` 的标记并留通知指针，由 Qoder 归档。
> 本文件保留全文，用途有二：① **移交 Qoder 吸收**（他已收到抽离版，见 `exchange/log-qoder.md`）；② WB **复验他的归档动作**时对照。⛔ 除非老大点名，WB 不按本技能触发执行。

把**已完成且已复验**的待办块从活跃面板搬到冷存储归档，**不丢内容、不断引用、不动在飞内容**。

## 何时用

- 「TODO 太长 / 瘦一下 / 精简」
- 「该归档的归档，该删除的删除」
- 一个阶段（如 DSH-N）的多个切片全部闭环，用户问「能不能提前归档」
- ⚠️ **不适用**：清理交流区日志 / 讨论稿 → 用 `doc-sunset-handoff`；把提案稿套进权威文档 → 用 `apply-proposal-to-doc`

## 铁律

1. **只搬「块内 `[ ]` = 0」的块**，程序化核（别肉眼）。含未勾选项的块是活内容，**即使整段标着 ✅ 也不搬**。
2. **正文逐字迁出、零改动**。归档区是**锁定快照**，不进讨论、不勾状态、不就地更新。要修叙述另起一稿，不改快照。
3. **归档一次成形**：进了就冻住 ⇒ 别分几次进（分次会在锁定区留下半截）。
4. **删前核承接 —— 且"承接没就位就得先补"，这是两件事**：待办块的「结论 / 判据」应已在 `docs/`、「未闭合项」应已在别处（`TODO` 的「待核 / 待派发」）登记；归档 = **搬家不是删除**（`archive/README.md` 通常明写这条 ⇒ 先读该区 README 确认授权与落位标准）。
   - ⭐ **判据「仍被引用」就不得进冷存**：归档区的收件判据是 **「是否仍被引用」，不是「是否闭环」**（`archive/README.md` ＋ `docs/*/README.md` 常双重申明）。实测：某阶段的**判据**虽躺在已 ✅ 的块里，却因「换基线须重验」仍属**活跃权威** ⇒ **必须先把落点补进 `docs/`，再搬块**。⛔ 直接搬 = 把活跃判据埋进冷存，且原块那句「权威落点 = `docs/…`」会**变成空指**。
   - ⭐ **正确顺序 = 先归位（判据→`docs`）、再落位（未决→`TODO`）、后搬家（`TODO`→`archive`）**。顺序颠倒会把未决项**冻在快照里**（归档区不追现态 ⇒ 变成永久挂账）。
   - ⚠️ **别信原句的「各有归宿 / 已登记」断言** —— **逐条 grep 验证**。实测：「另有 3 项未决，其中 2 项各有归宿」核下来**只有 1 项真落到了别处**（另一项的"归宿"只写在同一段**即将迁出**的文字里 ⇒ 迁出即失）。
5. **在飞内容一根不动**（未起跑切片、待裁项、前置约束）。

## 流程（全程序化，别手改）

0. **读目标区 README** 确认：谁能改、落位标准、是否"搬家非删除"。
1. `git status` ＋ 还原立场：确认工作区是否干净（他人可能在飞）。
2. **切块**：按标题层级切，块 = 标题行 → 下一个同级/更高级标题前，**含末尾空行**。
   逐块算：`行数 / 字符 / 字节 / 块内 - [ ] 数`。`[ ]` ≠ 0 的块**直接排除**。
3. **抽正文**：块内容行 = `lines[a-1 : b-1]`（**去掉末尾那一行空行**，它就是块间分隔）。
4. **写归档**：`原文件.rstrip('\n') + '\n\n---\n\n' + 段头 + 各块正文 + '\n'`
   - ⚠️ **先核该区的组织方式**：若归档区**按编号排序**（实测：`roadmap-history.md` 实为 `3.0 / 3.1 / 3.2 / 3.2.1 / 3.3 / 3.7 …`）⇒ **插在编号位**（如 `3.4` 插在 `3.3` 与 `3.7` 之间），⛔ 不是一律追加到文末（追文末会让编号区乱序）。
   - 段头级别**照该区既有惯例**（先核已有段用的是几级标题）—— 通则"高一级"（`#### DSH-3.0` → 归档里 `### DSH-3` 父段 ＋ 原级子段）**只在归档区确以父段聚合时成立**；实测该区是**同级 `####`**。
   - 段头写四样：阶段身份 / 「本段 = 冷历史快照，在飞切片不在本段」/ **`:N` 坐标系说明**（见下）/ 迁出来源 —— 另加**「未决项不载于本段」＋指回 `TODO` 段名**（防读者在冷存里找现态）。
   - **补该区的目录/索引行**（该区若自述"检索靠 Grep 目录"，不补就等于砍掉检索入口）。
5. **TODO 侧留指针**：在被搬走的每个**位置**留 1 个小节（标题带 `✅ 已归档（日期）` ＋ 2 行说明：搬到哪 + 本区在飞内容从哪起）。指针里**不放 `[ ]`**（否则破坏「✅ 段内不得含 `[ ]`」不变量）。
6. **修引用**（见下节）—— 这一步最不能省。
7. **校验**（见下节）。
8. 提交。

## ⭐ 引用修复（两个方向，别只做一个）

### A. 区外 → 被搬走的块（会悬空）
逐条判「**借地址**（要改）vs **仅提及**（可留）」：
- `见本文件「DSH-3.7.2」段` / `见 3.0 \`:73\`` / `来源见 \`:234\`` ⇒ **借地址** ⇒ 改指 `archive/…` 的同名段
- `ref/community/xxx（3.1）` / `3.1–3.6 实现侧 → Trae` ⇒ 仅按编号**提及** ⇒ 可留
- ⚠️ **同名陷阱**：扫 `3.0` 会命中 `§3.0`（指**另一份文档**的章节号）⇒ **先核目标当下在哪，再改**。实测：以为是"块被归档了"该改的某条，真目标其实在**留存区**，改了反而错。

### B. 块内 → 区外（迁走后坐标系失效）
块里指向留存区的 `见 \`:40\`` / `TODO:40` 会失去意义。
- **不要逐条重算行号**。在**归档段头写一次坐标系说明**：
  「本段正文里 `` `:N` `` 引用 = **归档前 `TODO.md` 的行号**；要定位用 `git show <归档提交>^:TODO.md`。指向代码/装置文件的引用形如 `main.rs:274-291`，不受影响。」
  （⚠️ 先分清两种 `:N`：`` `:74` `` 这种裸冒号的是**本文件行号**，`main.rs:274` 那种是**文件名行号**，别一起改）

### C. ⭐ 顺手清算「早已腐烂」的行号引用
**长寿命面板文件里的 `:N` 引用必然腐烂且不报错**。实测（TODO.md 整理时）：`:271` / `:275` 当前**指向空行**；`见 3.0 \`:73\`` 的真目标早漂到 `:71`；`\`:278\`` 的真目标在 `:546/548`。
- 判据 = **用脚本打印该行号当下的内容，跟引用句的语义对一遍**（别假设它还对）
- 修法 = **改指段名 / 条目名**（行号是脆弱引用，名字才稳）
- 已腐烂的、且目标是**留存区条目**的 ⇒ 改指**条目名**（如 `见本段「3.1 前置 · 仓库资产缺陷」`）
- ⇒ 一般化：**别的文件引用你这份面板的 `:N` 时同样会烂** ⇒ 全仓扫一遍（见下）

## 校验（三项硬指标 + 三项常规）

| # | 指标 | 做法 | 期望 |
|---|---|---|---|
| ① | **零越界删除** | 多重集差：`HEAD 版行 - 新版行`，逐行判「属于某块 ∪ 属于被改写引用」 | **无第三类** |
| ② | 未勾选不变量 | `- [ ]` 计数前后 | 搬走的块本应**无 `[ ]`**；⚠️ 若本次**同时做了「落位」**（把未决项登记进 `TODO`）⇒ 净增 ≠ 0 **属预期** ⇒ 逐条对上即可，别当异常 |
| ③ | ✅/`[ ]` 不变量 | 扫「标题含 ✅ 的小节内是否出现 `- [ ]`」 | **0 冲突** |
| ④ | 内容不丢 | 逐块断言「该块正文 in 归档新文本」 | **True** |
| ⑤ | 全仓引用 | 扫 `` `:\d{1,4}` `` ＋ 块名 ＋ `TODO:\d+`，**跨文件**（`docs/` `exchange/` `.md` `.ts` `.py` `.sh`） | 逐条核过 |
| ⑥ | 凭据 | 待提交 diff 扫 `Bearer/password/secret/sk-` | 无命中 |

另：`git diff --numstat` 的增删量应能对上（对不上就查"是不是他人同时在改"，或自己漏算）。

## 常见坑

- **行尾**：**已由仓库 `.gitattributes` 统一为 LF**（`* text=auto eol=lf`，2026-10-08）⇒ 行尾由基建层保证，**无需再人工核对 / 维护**。
- **别用 `cut -c` 处理中文** —— 按字节切后再按本地编码解，**整段乱码**。截断/切片走 Python。
- **heredoc 会吃掉转义**：`'\\'` 变成 `'\'` ⇒ 脚本里有反斜杠/正则时**写成 `.py` 文件再跑**，别塞 heredoc。
- **块边界要断言**：切之前 `assert` 首行/末行/末行是否空行，防文件被别人改过后静默切错。
- **归档区"不追加" vs 本次追加**：那条规则防的是"在锁定区追加**讨论/状态**"，不是禁止**移入新归档** —— 该区通常自己写着「后续完成的工作也会持续移入」。目录/索引行照补。
- **状态面板的元信息也要同步**：段头状态（如「DSH-3 待启动」）、编号约定条（「完成一个即归档一个」）会因本次归档而**过期** ⇒ 一并改。
- **既有的死引用顺手挖**：本次实测挖出两处指向「文件末尾『缓删』区」的死引用（该区**早已移出本文件**）⇒ 扫"指向本文件某区"的措辞时，**核该区此刻是否还在**。
- **`numstat` 与多重集差对不上，多半不是异常**：`git diff --numstat` 是**位置化**计数（重复行 / hunk 边界会多出 -/+ 对），多重集差是**位置无关**的 ⇒ 差几行正常，**判"有没有越界删除"以多重集为准**；真要对齐，看被删行能否**逐条归类**（属某块 ∪ 属被改写引用）。
- **`git show <rev>:<file>` 给的是库内形态**（现与工作区**同为 LF**）⇒ 可直接逐行比对，不必再归一化。
- **判据类内容迁进 `docs` 时，先核目标节的编号体系**（`#####` 下已有的 `①②③④`、`⑤` 等）⇒ 新条目若能**另起兄弟节**就别去插队重排（重排会打断别处对「第 N 条」的既有引用）。零编号扰动优先。
