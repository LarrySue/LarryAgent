# 远程场地 dry-run 探针

要在一台**机会宝贵 / 改动不可逆 / 多 AI 共用**的机器上做判定之前，**先把场地钉住**，判定轮才有效。

## 六条铁律

1. **判据先读源码**，别只读文档。文档会漏掉协商逻辑，也会把"人工构造的高位输入会失败"写成"实现会失败"。
2. **只读、零装包、零改配置。** 你探的是「**现状**能否满足」，不是「我能不能把它弄成满足」。装一个包、改一条 sysctl = 改变场地 ⇒ 后面所有判定作废。（`apt-cache policy X` **只查不装**；系统级开关**只读不写**。）
3. **正证 > 存在性。** "接口存在 / 调用没报错" ≠ "真的生效"。必须造出**可观测的差异**。
   ⚠️ **且差异必须由「被测实现自己的参数」造出，不能是探针自设的参数** —— 自设参数造出的差异只证「**平台／内核有这个能力**」，**不证「实现会这么做」**。
   （2026-09-23 实测踩过：用自设的「拒读」掩码测 landlock 得到 `EACCES`，而被测实现的 profile 是 `readOnly: ['/']` ⇒ **读权限全开**；那条正证被上游误读成「沙箱会挡住读敏感文件」。）
   ⇒ 造差异前先问一句：**这个参数是哪一方给的？**
4. **换一条独立通道复做同一个正证。** 用与产品无关的第二语言／第二工具重跑，避免"装置本身写错"被当成"环境事实"。
5. **顺手采场地台账并打包**（版本 / 绝对路径 / 资源 / 目录 / 已有资产 / 场地是否独占）。后续切片会反复用到，一次采齐。
6. **把判据原文回贴到结论旁**——否则探的范围会漂成"我觉得重要"。

## 标准清单

**A. 目标核查（对着判据逐条）**
- 每条前置／依赖项的**存在性**（`dpkg -l` / `command -v` / `-d` 判目录）
- ⭐ 若缺失：**能否补**（`apt-cache policy`）＋ **补了能不能用**（它依赖的 ns／权限／内核能力在不在）——这一步最容易被跳过，也最容易给出错误乐观结论
- 运行环境**能力项**：内核版本 / ABI / cgroup 代 / 用户命名空间开关

**B. 正证（每条"可用"都要一个可观测差异）**
- 造一次**期望中的拒绝或成功**，把具体错误码读出来
- 换第二条通道复做

**C. 场地台账（供后续复用）**
- 路径映射：各 home／数据目录／凭据载体**存在性**（**只列键名，绝不回显值**）
- 运行时**绝对路径** —— ⚠️ 非登录 shell 的 PATH 常不含 ⇒ 裸 `node` / `dsh` 输出为空是**场地事实，不是故障**
- 资源与 cgroup v2 可读性、监听端口
- **场地是否独占**：列他方（其他 AI / 其他人）的产物目录 —— 多 AI 共用机器时必需
- **已有器材清点**：机器上很可能已有前人探针 —— ⚠️ 先看它是**给哪台机写的**（实测踩过：一件自述"本机 Windows"、用 `USERPROFILE` 的探针被搬到了 Linux 机上）

## 落地纪律

- **只读途径**：`ssh 'bash -s' < 本地脚本` ／ `ssh 'python3 -' < 本地脚本`，**不往远程留文件**；`ssh` 走**前台**（后台任务常拿不到沙箱放行）。
- **写入本地文档**：**断言必须放在写盘之前** —— 批量写多文件时，若某个文件已先落盘才发现后一个断言失败，就只能回滚重做。
- **结论分三类写**，不得混：① **已证**（有正证）② **已由源码／文档钉死**（引文件:行号）③ **仍需上机确认**。
- **探针不出判定**——判定是下一轮的事；dry-run 只负责"场地与预期是否一致"。

## 常见坑

- **文档里的"实测"要核主语**：「X ⇒ 失败」要问清是**"有人手工构造 X"**还是**"实现自身会产生 X"**。实测踩过：某文档写"高位掩码喂老内核 ⇒ 系统调用直接 `EINVAL`"，成立；但产品实现**按协商能力裁剪掩码**，根本不会触发。把这条读成"产品在老内核上会失败"就是过度声明。
- **正证的"参数来源"也要核**（同铁律 3）：差异由**探针自设参数**造出时，它证的是**平台能力**，不是**实现行为**。两者会被后来的读者混为一谈，且在「实现比探针宽松」时制造**错误的安全感**。
- **"缺失" ≠ "不可用"**：缺 A 往往**自动降级**到 B（链式仲裁）。要读源码确认降级路径，**并确认降级后是否降档** —— 降档（如失去进程/网络隔离）是**安全层面的实质变化**，必须单列暴露、交人裁。
- **别把估算当实测**（实测过"约 314 MB"与真实 681 MB 差一倍）。
- **场地非独占时**：任何"取状态 → 跑命令 → 再取状态"的归因，**先确认窗口内无第三方活动**，否则证据自动降级。
- **正证要包住上限**：一条正证常常还没证到"边界行为"，把"没验到"的部分写清楚（如"未验：多路径精确授权"）。
