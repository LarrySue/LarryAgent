# 文档治理复检清单（删减类任务）

> ⚠️ **分工变更后的用法（2026-10-13 老大裁定）**：删减 ／ 搬家 ／ 归档类**动作**现由 **Qoder** 执行（`docs/`、`archive/` 归他）。本技能 **WB 保留**，用于：① **复验 Qoder 的这类动作**；② 自己清理 `exchange/log-*` 后的自检。⛔ WB 不亲自执行文档删减 ／ 搬家 ／ 归档。

**删减 / 搬家 / 归档类**文档动作的**事后核验**。重心＝查「**删掉 / 搬走的东西有没有承接**」，不是核对改动文字本身。

> 本 skill 只做**复检**（判据层）。**执行**动作本身去对应流程 skill：清退过程稿 → `doc-sunset-handoff`；待办块归档 → `archive-closed-todos`；提案稿套进权威文档 → `apply-proposal-to-doc`。

## 一、承接核验（删之前 / 搬之后）

1. **删项承接** —— 每个被删条目逐个 grep 确认目标文件有承接。重点盯 `[x]` 已完成项：那是**搬家**（`TODO.md` → `archive/roadmap-history.md`）不是删除。
2. **清交流区（`exchange/log-*`）前必先做「承接转登」** —— 删除前逐条核「这条结论有没有稳定落点」，没有的先补进去再删。核承接 = 对**关键锚点逐个 grep 权威文件**（不是"读一遍觉得有"）。**最容易漏的三类：装置缺陷、判据增补、外部通道的完整观测**（它们常只活在派发／回报正文里）。
3. **写「建议改 XX 文档 / 加进模板」之前，先核那个载体是否存在** —— 「建议」写得再合理，**没有载体就是空转**（每次重踩同一个坑），却在清单里**看起来像一条待办**。核载体成本 = 一次 grep。实测：项目里**不存在「派发稿模板」文件**（派发稿逐次手写在交流区），而某处写着「派发稿模板的凭据条款建议同批修订」⇒ 落不到任何文件。
4. **「已归档」段的段名 ↔ 实际承接范围可能不重合 ⇒ 核承接不能按段名推断** —— 要核「目标文件的**既有同段**是否已吞掉它」，不是核「目标文件里有没有这条」：**同段 ≠ 同物**。**判别法**：拿被移条目的**独有细节**去 grep 目标段，命中才算承接；只命中**名字**不算。实测：`archive/roadmap-history.md`「DSH-3.0·开工前置」段名该含"进入前"，实则只含"开门之后干了啥"。

## 二、引用完整性（正反两向）

5. **搬家 / 删除后，反向 grep 旧落点**（方向与"删之前扫引用"相反）—— 内容从 A 移到 B 后，**旧的「权威落点 = A」表述全部变成断链**，且平时看不出来（活日志会被清、断链只在被引用时才暴露）。**动作**：对**旧定位串**做一次全库 grep，逐处改指新落点。实测：移一块后揪出 **5 处静默悬空指针**。
6. **一次「收回 / 移动」会带出下游表述漂移 —— 须与动作同批核** —— 凡**一处明细变动**，就想「**还有谁在别处描述了这件事的形态**」。实测：某文档写「J6 两条承接位置 = `TODO.md` 延后段」，而其中一条已被收回至「待派发」段 ⇒ 合并表述过期。（与第九条「汇总句 ↔ 明细项」同源，但**漂移可发生在别的文件**。）
7. **代码注释里的「事实名」不随文档归档失效** —— 反 grep 会把代码自述一并命中（实测 4 处：`real-api.ts` / `global-setup.ts` 等自述"DSH-3 前置件 1"），但它们指向的是**代码本体**、不是文档坐标 ⇒ **不修**。**判别法**：指针指向**文档坐标**（某文件某段）才须随搬家更新；指向**物自体**（源码 / 提交 / 装置）的与文档搬家无关。

## 三、面板不变量与状态

8. **标记不变量（程序化检查，别肉眼）** —— `✅` 阶段内不得含 `[ ]`；含 `[ ]` 的小节不得挂 `✅`：
   ```
   awk '/^\*\*/{sec=$0} /^- \[ \]/{if(sec ~ /✅/) print "冲突 行"NR" | "sec}' TODO.md
   ```
   - `✅` 出现在**括号内作状态修饰**（如"✅ 串行已解除"）也会被判冲突 ⇒ 那种一律改成文字表述。
   - **反例**：段头**不带** `✅` 的段里出现 `[ ]` 是**完全正常**的（说明该段还没完）—— 别一看 `[ ]` 就想消掉它。
9. **「延后项收回」是「三处同步」动作，不是移动一行** —— 把一条从「延后（低优先·待触发）」段移出变正式待办时，**必须同步改两处"汇总句"**：①「延后」段的**段首说明**（原文"有两条…"，移动后只剩一条即矛盾）；② **上游段的汇总口径**（如某段写"唯一未闭合的下游尾巴 = X"）。⇒ 「**一体两面，须同步**」不只在两个文件间，**同一文件内的「汇总句 ↔ 明细项」同样适用** —— 任何**锚在条数 / 集合上的汇总句**都会因明细增删而失准。
10. **「某段已收口」是带时间戳的断言 —— 其后任何"段外新增"都会让它过期** —— 触发源 = **承接登记 / 收回 / 搬家把旧账搬进来**（不是段内增删）。**做法**：凡做过"承接登记 / 把某条目搬入某段"的动作，**须回查该段的"收口声明"是否还成立**；判先后用 `git log -S '<那句话>'` 比提交时间，别凭印象。实测：某段声明"自本条起不再有未完成项"，**后来**清理把一条缺陷**承接登记**进来 ⇒ 声明过期，制造"声明无未完成 + 段内有 `[ ]`"的假矛盾 —— 当时的账**算错了对象**（该改的是那句声明，不是 `[ ]`）。
11. **「段内挂 `[ ]`」有两种相反成因，处置相反 —— 别一律当"容器失真"删掉**：
    - **(a) 状态标记过期**：子项全完 / 全移出、父节点没摘 ⇒ **摘掉复选框**（降为结构说明行）。
    - **(b) 真实在飞项**：事**还在做**，只是**性质或归属变了**（如 待裁 → 已派某 AI 修）⇒ **保留 `[ ]`，只更新其内容与状态**，**绝不摘框、更不移出该段**。
    - **判别法**：先问「**这条现在还有没有人在干活**」—— 有 ⇒ (b)；没有且子项全完 ⇒ (a)。
    - 段的完整性**不取决于它有几条 `[x]`，而取决于它名下还有没有人在干活**。实测：把一条"已派 Claude 修"的装置缺陷当 (a) 处理（摘框 ＋ 移去「待派发」）⇒ 被指出"那段不完整了"。
    - 顺带钉死「待派发」段语义 = **"该派但还没派"**（待裁 / 等触发 / 等上游里程碑）；**已派出的条目不在其列** ⇒ 归其**所属阶段段**。

## 四、编辑卫生

12. **提交前对「待提交 diff」扫 `Bearer` / `password` / `secret` / `sk-`**，再复扫文件本体；命中逐条判性质（**删除行内**的普通用词无害）。
13. **提交前必重新 diff** —— `git add` 前**重新确认磁盘当前状态**。⚠️ 老大**实时跟 WB 的流式输出、会在 WB 检查 / 思考期间顺手改文件** ⇒ AI 正在看的快照可能已过期。
14. **「改状态」与「删内容」是两种动作，做前者时手不能滑到后者** —— 改之前先问「这行除了状态标记，还有没有实质信息」；有则**只动标记、其余逐字保留**。危险处：同一次编辑混入两种意图，**越界部分不会报错**（Edit 回执一样 Successfully）⇒ 只能靠**改后读回 diff** 发现。实测：改容器行时把其下 **6 条实体子项连根删了**，靠 `git checkout --` 回滚重做。
15. **大块替换（Edit 覆盖到段尾）前，先核被覆盖区间里有没有「常设内容」** —— `old_string` **只取到被改内容的边界**，不贪图"一次覆盖到段落结束"。实测：一次 Edit 把该区**常设的「通用纪律 6 条」一并吃掉**，靠紧接着的串行 Edit 补回。（与上条同源、触发相反：上条是手滑多删子项，本条是替换范围划大、把邻居也圈进去。）

## 五、挂起与等待

16. **「等待某条件」的挂起条目，条件一旦满足就必须回头改它 —— 否则会被永远挂起** —— 挂起理由本身是「**锚在外部状态上的一句断言**」。**体检提示**：巡查挂起条目时，逐个问「**它等的那个条件，现在满足了没**」。实测：一条挂「待复核放行后可改」，而该件**早已通过复验** ⇒ 卡点已解除却没人推，僵死（无人工回查会一直挂着）。

## 六、产出与处置（复检完往哪送）

> 复检**不是终点**：查出什么，要按**归属**送到它该去的地方（归属表见 `docs/ai-governance.md` §3）。本 skill 的**两个用法场景，处置方向相反**，别混。

17. **场景① · 复验 Qoder 的删减 ／ 搬家 ／ 归档动作**（即 10-13 新用法之一）—— 缺陷**归他修**：⛔ WB **不亲自改** `docs/` ／ `archive/`，只**暴露 ＋ 备精确改法**（改哪个文件、哪一行、原文 → 改成什么），交 Qoder 执行；**涉定性 ／ 方向 ／ 归属判断的 ⇒ 报老大等拍板**，别自行折中。⚠️ **结论要写全**（判定 ＋ 判据 ＋ 证据出处）—— 复检结论的**落点在 `docs/`（归 Qoder）**，只丢一句"复检通过"等于**没交接**。
18. **场景② · 自清 `exchange/log-*` 后的自检**（10-13 新用法之二）—— 缺陷**归自己**：`log-*` 是 WB 自己的区，**直接改 ＋ 事后说明**；⚠️ 但若缺陷**落在别区**（典型：清 log 时发现 `docs/` 侧承接缺失、或某段权威落点是它处），**回到场景① 的处置**（暴露 ＋ 备改法，不越界自改）。
19. **复检中新踩到的坑 ⇒ 沉淀为本清单的新条目** —— 本文件 `一~五` 每一条都带**实测来源**，就是靠这个机制长出来的。⇒ 收尾时问一句「**这次有没有遇到清单还没覆盖的失效形态**」，有则补一条（**连同实测事实**）；⚠️ 纯表述层面的犹豫不沉，只沉「会再次踩到」的形态。
